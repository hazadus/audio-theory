## Классы и структуры {#classes}

<MarginNote items={[
  { label: 'Learn C++ → 14.2 Introduction to classes', description: 'Класс как тип с данными и функциями.', target: { url: 'https://www.learncpp.com/cpp-tutorial/introduction-to-classes/' } },
  { label: 'Learn C++ → 14.5 Public and private members and access specifiers', description: 'Модификаторы доступа и данные класса.', target: { url: 'https://www.learncpp.com/cpp-tutorial/public-and-private-members-and-access-specifiers/' } },
]}>

Класс (class) и структура (struct) в C++ различаются одним: у `class` члены по умолчанию закрыты (`private`), у `struct` открыты (`public`). По соглашению `struct` берут для простых наборов данных, а `class` — для объектов с поведением и инвариантами. Точка с запятой после закрывающей скобки обязательна. Методы объявляются внутри класса, а все поля описываются заранее вместе с типами.

</MarginNote>

`Parameters` — структура из трёх ссылок на параметры, а `BypassTransitionSmoother` — класс с закрытым состоянием. Доступ задают метки `public`, `protected` и `private`; метка действует до следующей. `private` разрешает доступ только методам этого класса, `protected` — ещё и наследникам, `public` — всем.

```cpp
class BypassTransitionSmoother {
public:
  void prepare(const juce::dsp::ProcessSpec& spec) { /* ... */ }
  [[nodiscard]] bool isTransitioning() const noexcept { /* ... */ }

private:
  double crossfadeLengthSeconds = 0.0;
  double sampleRateHz = 0.0;
  juce::LinearSmoothedValue<float> dryGain{0.f};
  juce::LinearSmoothedValue<float> wetGain{1.f};
  juce::AudioBuffer<float> dryBuffer;
};
```

### Значения полей по умолчанию {#default-members}

<MarginNote items={[
  { label: 'Learn C++ → 13.9 Default member initialization', description: 'Инициализаторы членов и порядок инициализации.', target: { url: 'https://www.learncpp.com/cpp-tutorial/default-member-initialization/' } },
]}>

Запись `= 0.0` или `{0.f}` рядом с полем (C++11) задаёт значение, если конструктор не указал другое. Поле, у которого нет ни такой записи, ни инициализации в конструкторе, получает значение по умолчанию своего типа: `dryBuffer` создаст конструктор по умолчанию класса `AudioBuffer`. Поле встроенного типа (`int`, `double`, указатель) без инициализатора содержит произвольное значение, а не ноль, как в Go.

</MarginNote>

### Константные методы {#const-methods}

<MarginNote items={[
  { label: 'Learn C++ → 14.4 Const class objects and const member functions', description: 'Какие методы можно вызывать у const-объекта.', target: { url: 'https://www.learncpp.com/cpp-tutorial/const-class-objects-and-const-member-functions/' } },
]}>

`const` после списка параметров обещает, что метод не меняет поля объекта: `bool isBypassed() const noexcept`. Только такие методы можно вызвать у константного объекта и через `const T&`. Компилятор проверяет обещание, и попытка изменить поле в `const`-методе становится ошибкой. Из-за этого `prepare(const juce::dsp::ProcessSpec& spec)` может читать `spec.sampleRate`, но не может его менять.

</MarginNote>

В объявлении `const juce::String getName() const override` два `const`. Второй, после списка параметров, делает метод константным. Первый стоит перед типом результата и относится к возвращаемому значению: метод возвращает копию строки, и эту копию нельзя изменить. Для значения, возвращаемого по копии, такой запрет бесполезен: вызывающий код всё равно получает собственный объект. С C++11 он ещё и мешает перемещению, о котором речь [ниже](#copying). В `PluginProcessor` этот `const` написан потому, что так объявлен чисто виртуальный метод в `juce::AudioProcessor`: `virtual const String getName() const = 0;`. Переопределение должно возвращать тот же тип, что и метод базы, и убрать `const` только в наследнике нельзя.

### Статические члены и this {#static-this}

<MarginNote items={[
  { label: 'Learn C++ → 15.7 Static member functions', description: 'Статические функции-члены и отсутствие this.', target: { url: 'https://www.learncpp.com/cpp-tutorial/static-member-functions/' } },
  { label: 'Learn C++ → 15.6 Static member variables', description: 'Статические поля: одно на весь класс.', target: { url: 'https://www.learncpp.com/cpp-tutorial/static-member-variables/' } },
]}>

Статический метод принадлежит классу, а не объекту, и не имеет `this`. `JsonSerializer` — класс без полей, который служит группой функций: `JsonSerializer::serialize(parameters, outputStream)` вызывается без объекта. Статическое поле одно на весь класс; `static constexpr auto modulationDepth = 0.4f;` в `Tremolo` — константа класса, известная при компиляции. Слово `static` в C++ означает разное в зависимости от места: у члена класса — «принадлежит классу», у локальной переменной — «живёт до конца программы», у функции вне класса — «видна только в этом файле».

</MarginNote>

Внутри метода поля и методы доступны без префикса: в `PluginEditor::resized()` вызов `getLocalBounds()` означает `this->getLocalBounds()`. Слово `this` — указатель на текущий объект, его пишут явно только для устранения неоднозначности или чтобы передать объект дальше, как в лямбде `[this]`. Вложенные типы вроде `Tremolo::LfoWaveform` объявлены внутри класса и снаружи называются через `::`; в наследнике они видны без квалификации: `BusesLayout` из `juce::AudioProcessor` используется в `PluginProcessor` как есть.

## Конструкторы и инициализация {#constructors}

<MarginNote items={[
  { label: 'Learn C++ → 14.9 Introduction to constructors', description: 'Конструктор и инициализация объекта при создании.', target: { url: 'https://www.learncpp.com/cpp-tutorial/introduction-to-constructors/' } },
  { label: 'Learn C++ → 14.10 Constructor member initializer lists', description: 'Список инициализации и порядок инициализации полей.', target: { url: 'https://www.learncpp.com/cpp-tutorial/constructor-member-initializer-lists/' } },
]}>

Конструктор (constructor) — метод с именем класса и без типа результата; он вызывается при создании объекта. Если конструкторов нет, компилятор создаёт конструктор по умолчанию. Часть после двоеточия и до тела — список инициализации членов (member initializer list). Поля создаются сразу с нужными значениями до выполнения тела. Присваивание в теле сначала создало бы поле со значением по умолчанию, а потом перезаписало.

</MarginNote>

```cpp
explicit BypassTransitionSmoother(double crossfadeLengthSecondsValue = 0.01)
    : crossfadeLengthSeconds{crossfadeLengthSecondsValue} {
  jassert(0.0 < crossfadeLengthSeconds);
  reset();
}
```

Для ссылок, `const`-полей и классов без конструктора по умолчанию список инициализации — единственный способ. Так написан конструктор `Parameters`: поля-ссылки `rate`, `bypassed` и `waveform` невозможно создать пустыми. Поля инициализируются в порядке объявления в классе, а не в порядке записи в списке; если порядки расходятся, срабатывает `-Wreorder`.

Конструктор базового класса тоже вызывается в списке инициализации, как `super().__init__(...)` в Python. База создаётся раньше полей наследника:

```cpp
PluginProcessor::PluginProcessor()
    : AudioProcessor(
          BusesProperties()
              .withInput("Input", juce::AudioChannelSet::stereo(), true)
              .withOutput("Output", juce::AudioChannelSet::stereo(), true)) {}

PluginEditor::PluginEditor(PluginProcessor& p) : AudioProcessorEditor(&p), /* ... */ {
```

Из этого порядка следует, что поле `Parameters parameters{*this};` в `PluginProcessor` создаётся, когда часть `AudioProcessor` уже построена, и конструктор `Parameters` может добавлять в неё параметры. Подробнее — в [«Кто владеет объектом»](/cpp-ownership/#juce-handover).

### explicit {#explicit}

<MarginNote items={[
  { label: 'Learn C++ → 14.16 Converting constructors and the explicit keyword', description: 'Converting constructors и ключевое слово explicit.', target: { url: 'https://www.learncpp.com/cpp-tutorial/converting-constructors-and-the-explicit-keyword/' } },
]}>

Неявное преобразование превращает одно значение в объект другого типа, когда тип аргумента не совпадает с ожидаемым. Для этого компилятор ищет у нужного класса конструктор, который можно вызвать с одним аргументом: исходное значение одно, и других данных для создания объекта у него нет. Подходит и конструктор, у которого остальные параметры имеют значения по умолчанию, как у `BypassTransitionSmoother(double crossfadeLengthSecondsValue = 0.01)`.

</MarginNote>

Если бы этот конструктор не был помечен `explicit`, следующий код компилировался бы без ошибок. Функция `inspect` придумана для примера:

```cpp
void inspect (const BypassTransitionSmoother& smoother);

inspect (0.5);                            // из 0.5 создаётся временный BypassTransitionSmoother
BypassTransitionSmoother smoother = 0.5;  // то же при инициализации через =
```

Число `0.5` молча превратилось бы в объект с переходом длиной полсекунды, хотя по вызову `inspect (0.5)` этого не видно. С `explicit` обе строки — ошибка компиляции, и объект создаётся только явно: `inspect(BypassTransitionSmoother{0.5})`. Так же объявлены `explicit Parameters(juce::AudioProcessor&)` и `explicit PluginEditor(PluginProcessor&)`: без `explicit` процессор можно было бы передать в функцию, которая ждёт `const PluginEditor&`, и компилятор создал бы для этого вызова временный редактор.

Конструктор с несколькими параметрами тоже может участвовать в неявном преобразовании, но только из списка в фигурных скобках: вызов `f({a, b})` создаст объект параметра из `a` и `b`. `explicit` запрещает и этот случай. Обычно его ставят у всех конструкторов, которые можно вызвать с одним аргументом, если неявное преобразование не нужно.

### Фигурные скобки {#brace-init}

<MarginNote items={[
  { label: 'Learn C++ → 10.4 Narrowing conversions, list initialization, and constexpr initializers', description: 'Список инициализации и сужающие преобразования.', target: { url: 'https://www.learncpp.com/cpp-tutorial/narrowing-conversions-list-initialization-and-constexpr-initializers/' } },
  { label: 'Learn C++ → 13.8 Struct aggregate initialization', description: 'Агрегатная инициализация структур.', target: { url: 'https://www.learncpp.com/cpp-tutorial/struct-aggregate-initialization/' } },
]}>

В C++ несколько синтаксисов создания объекта; в коде плагина в основном используются фигурные скобки (C++11): `BypassTransitionSmoother testee{1.0};`, `juce::LinearSmoothedValue<float> dryGain{0.f};`, `PluginProcessor processor{};`. Отличия от круглых скобок: `{}` запрещает сужающие преобразования (`int x{3.7};` не компилируется, а `int x(3.7);` молча даст 3), а `int x{};` гарантирует ноль, тогда как `int x;` оставляет произвольное значение.

</MarginNote>

Строка `T x();` объявляет функцию `x`, возвращающую `T`, а не объект. Это следствие правила грамматики «если запись можно разобрать как объявление функции, выбирается оно», и её называют «most vexing parse» («самый досадный разбор»). Фигурные скобки `T x{};` однозначно создают объект.

Простые структуры без конструкторов, например `juce::dsp::ProcessSpec`, инициализируют по полям. В `Tremolo::prepare` это записано с именами полей (C++20, designated initializers), а в тесте — списком в порядке полей, который создаёт временный объект параметра:

```cpp
const juce::dsp::ProcessSpec processSpec{
    .sampleRate = sampleRate,
    .maximumBlockSize = static_cast<juce::uint32>(expectedMaxFramesPerBlock),
    .numChannels = 1u,
};

testee.prepare({sampleRate, blockSize, channelCount});  // в тесте
```

Во втором вызове тип временного объекта компилятор берёт из сигнатуры метода, поэтому писать `ProcessSpec{...}` не нужно. Здесь значения `sampleRate`, `blockSize` и `channelCount` — `constexpr int`, а поля `ProcessSpec` беззнаковые. Сужение для констант, значение которых известно при компиляции и помещается в тип, разрешено.

## Наследование и виртуальные методы {#inheritance}

<MarginNote items={[
  { label: 'Learn C++ → 24.2 Basic inheritance in C++', description: 'Базовый и производный классы.', target: { url: 'https://www.learncpp.com/cpp-tutorial/basic-inheritance-in-c/' } },
  { label: 'Learn C++ → 24.4 Constructors and initialization of derived classes', description: 'Конструкторы производных классов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/constructors-and-initialization-of-derived-classes/' } },
]}>

Запись `class PluginProcessor : public juce::AudioProcessor` — открытое наследование (inheritance): публичные члены базы остаются публичными, а объект наследника можно использовать везде, где ждут базу. Почти всегда пишут именно `public`; множественного наследования в плагине нет. `CustomLookAndFeel` наследует `juce::LookAndFeel_V4` и переопределяет методы отрисовки; остальное поведение унаследовано.

</MarginNote>

### virtual и override {#virtual-override}

<MarginNote items={[
  { label: 'Learn C++ → 25.2 Virtual functions and polymorphism', description: 'Виртуальные функции и полиморфизм.', target: { url: 'https://www.learncpp.com/cpp-tutorial/virtual-functions/' } },
  { label: 'Learn C++ → 25.3 The override and final specifiers, and covariant return types', description: 'Спецификаторы override и final.', target: { url: 'https://www.learncpp.com/cpp-tutorial/the-override-and-final-specifiers-and-covariant-return-types/' } },
]}>

Хост знает о плагине только как об указателе на `juce::AudioProcessor` и вызывает `processBlock` через него. Вызов попадает в версию наследника потому, что в базе этот метод объявлен со словом `virtual`. В Python, TypeScript и Java все методы виртуальные, в C++ нет: метод без `virtual` вызывается по статическому типу указателя, и «переопределение» в наследнике через указатель на базу не сработает.

</MarginNote>

```cpp
void prepareToPlay(double sampleRate, int expectedMaxFramesPerBlock) override;
void resized() override;
```

`override` (C++11) просит компилятор проверить, что метод действительно переопределяет виртуальный метод базы. Опечатка в имени или типе параметра без `override` создаст новый метод, который никто не вызовет; с `override` это ошибка компиляции. Тот же `override` стоит у деструктора: `~PluginEditor() override;`.

<MarginNote items={[
  { label: 'Learn C++ → 25.7 Pure virtual functions, abstract base classes, and interface classes', description: 'Чисто виртуальные функции и абстрактные классы.', target: { url: 'https://www.learncpp.com/cpp-tutorial/pure-virtual-functions-abstract-base-classes-and-interface-classes/' } },
]}>

Многие методы `juce::AudioProcessor` объявлены как `virtual ... = 0;` — чисто виртуальные, без реализации. Класс с хотя бы одним таким методом называется абстрактным: создать его объект нельзя, только объект наследника, реализовавшего все такие методы. Поэтому `PluginProcessor` определяет `getName`, `acceptsMidi`, `getNumPrograms` и другие, даже когда они просто возвращают `false` или `0`.

</MarginNote>

### Сокрытие имён и using {#name-hiding}

<MarginNote items={[
  { label: 'Learn C++ → 24.8 Hiding inherited functionality', description: 'Скрытие унаследованных методов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/hiding-inherited-functionality/' } },
]}>

У базы две перегрузки `processBlock`: для `float` и для `double`. Если наследник объявляет метод с этим именем, он скрывает все перегрузки базы, даже с другими параметрами. Строка `using AudioProcessor::processBlock;` возвращает скрытые перегрузки в область видимости наследника. Без неё компилятор выдаст предупреждение `-Woverloaded-virtual`.

</MarginNote>

```cpp
void processBlock(juce::AudioBuffer<float>&, juce::MidiBuffer&) override;
using AudioProcessor::processBlock;
```

## Шаблоны {#templates}

<MarginNote items={[
  { label: 'Learn C++ → 13.13 Class templates', description: 'Шаблоны классов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/class-templates/' } },
  { label: 'Learn C++ → 11.6 Function templates', description: 'Шаблоны функций.', target: { url: 'https://www.learncpp.com/cpp-tutorial/function-templates/' } },
]}>

Шаблон (template) позволяет один раз описать алгоритм или контейнер для разных типов. По назначению он близок к дженерикам других языков. `juce::AudioBuffer<float>` — буфер <Term id="sample" firstMention>отсчётов</Term> `float`, `AudioBuffer<double>` — буфер `double`; логика класса общая, а тип элементов выбирается при использовании. Компилятор инстанцирует (instantiate) шаблон для каждого набора аргументов, поэтому определение шаблона должно быть видно в месте использования, и шаблонный код обычно лежит в заголовках.

</MarginNote>

Шаблон принимает и значения: в `std::array<juce::dsp::Oscillator<float>, 2u> lfos` второй аргумент задаёт число элементов. Плагин объявляет и собственные шаблоны. `SampleFifo<SampleType>` передаёт отсчёты <Term id="lfo" firstMention>LFO</Term> из аудиопотока в интерфейс, а `StridedQueue<T, Size>` хранит точки графика:

```cpp
template <typename SampleType>
class SampleFifo { /* ... */ };

template <typename T, size_t Size>
class StridedQueue { /* ... */ };
```

Для функций параметры шаблона обычно выводятся из аргументов:

```cpp
template <typename Number>
Number twice (Number value)
{
    return value + value;
}

auto integer = twice (3);          // Number выводится как int
auto sample = twice (0.5f);        // Number выводится как float
auto precise = twice<double> (3);  // Number задан явно, аргумент преобразуется в double
```

<MarginNote items={[
  { label: 'Learn C++ → 11.7 Function template instantiation', description: 'Как компилятор создаёт функцию из шаблона и когда аргументы указывают явно.', target: { url: 'https://www.learncpp.com/cpp-tutorial/function-template-instantiation/' } },
  { label: 'Основы C++ для JUCE → static_cast', description: 'Встроенное преобразование типа с угловыми скобками.', target: { article: 'cpp-basics', anchor: 'static-cast' } },
]}>

Явный аргумент нужен, когда вывести тип не из чего. `std::make_unique<juce::AudioParameterFloat>(...)` передаёт свои аргументы конструктору, и по ним не видно, какой объект создать. `juce::FromVar::convert<SerializableParameters>(parsedResult)` получает `juce::var`, а тип нужен только для результата. Парная ей `juce::ToVar::convert(from(parameters))` выводит тип из аргумента. `static_cast<int>(x)` только похож на шаблон: это встроенная операция языка.

</MarginNote>

### Шаблон класса изнутри {#class-template-body}

<MarginNote items={[
  { label: 'Learn C++ → 15.5 Class templates with member functions', description: 'Методы шаблона класса и где их определять.', target: { url: 'https://www.learncpp.com/cpp-tutorial/class-templates-with-member-functions/' } },
]}>

`SampleFifo` целиком, вместе с телами методов, объявлен в заголовке `SampleFifo.h`. Имя `SampleType` внутри класса обозначает тип, который подставят при использовании. Отдельной строки `template` перед методами нет: методы, определённые внутри шаблона класса, пользуются его параметрами.

</MarginNote>

```cpp
// SampleFifo.h, сокращено
template <typename SampleType>
class SampleFifo {
public:
  void push(SampleType sample) { /* ... */ }
  void popAll(juce::AudioBuffer<SampleType>& bufferToFill) { /* ... */ }
  // ...

private:
  static constexpr auto initialCapacity = 1024;
  juce::AbstractFifo fifo{initialCapacity};
  juce::AudioBuffer<SampleType> buffer{1, initialCapacity};
};
```

Поле `SampleFifo<float> lfoSampleFifo;` в классе `Tremolo` заставляет компилятор создать класс, где `SampleType` заменён на `float`: метод `push(float)`, поле `juce::AudioBuffer<float> buffer`.

<MarginNote items={[
  { label: 'Learn C++ → 11.9 Non-type template parameters', description: 'Параметры шаблона, которые принимают значение, а не тип.', target: { url: 'https://www.learncpp.com/cpp-tutorial/non-type-template-parameters/' } },
  { label: 'Learn C++ → 26.2 Template non-type parameters', description: 'Те же параметры в шаблонах классов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/template-non-type-parameters/' } },
]}>

Второй параметр `StridedQueue` — не тип, а число (non-type template parameter). `Size` передаётся дальше в `std::array<T, Size>`, поэтому число точек графика становится частью типа, а массив лежит внутри объекта, без выделения памяти в куче.

</MarginNote>

```cpp
// detail/StridedQueue.h, сокращено
template <typename T, size_t Size>
class StridedQueue {
  // ...
private:
  std::array<T, Size> stridedElements{};
  size_t elementIndex{0u};
  size_t stride{1u};
};
```

Значение такого параметра должно быть известно при компиляции. В `LfoVisualizer` оно объявлено как `static constexpr auto pointsOnPath = 22050u;` и передано в поле `detail::StridedQueue<float, pointsOnPath> lfoSamplesToPlot;`. Обычная переменная на этом месте не подойдёт:

```cpp
auto points = 22050u;
detail::StridedQueue<float, points> queue;  // ошибка: points не константа времени компиляции
```

Каждый набор аргументов даёт отдельный класс. Тест берёт `StridedQueue<int, 5>`: на пяти целых проще проверить, какие элементы остались в очереди. `StridedQueue<int, 5>` и `StridedQueue<float, 22050>` — два не связанных между собой типа, присвоить объект одного другому нельзя. В тесте `testee.pushBack(std::vector{1, 0, 0, 2, ...})` компилятор выводит `std::vector<int>`, и вектор неявно превращается в параметр `std::span<const int>`. Запись `T(0)` в методе `pushBackZeros` даёт ноль нужного типа: `0.0f` для `float`, `0` для `int`.

<SelfCheck question="Почему detail::StridedQueue<float, points> не компилируется, если points — обычная переменная auto points = 22050u?">

`Size` — параметр шаблона, и его значение входит в тип: от него зависит размер поля `std::array<T, Size>`, то есть размер всего объекта. Тип должен быть известен при компиляции, а значение обычной переменной существует только во время выполнения. Подходит константа `constexpr`, как `pointsOnPath`, или литерал.

</SelfCheck>

### Типы и функции в аргументах {#template-arguments}

Аргументом шаблона бывает и тип без данных, который выбирает поведение. Во втором аргументе `juce::SmoothedValue<float, juce::ValueSmoothingTypes::Linear>` пустая структура `Linear` задаёт линейное сглаживание: значение меняется на одну и ту же величину на каждом отсчёте. `Multiplicative` выбрала бы изменение в одно и то же число раз. `BypassTransitionSmoother` пишет короче, `juce::LinearSmoothedValue<float>`. Это шаблон-псевдоним (alias template) того же класса:

```cpp
// juce_SmoothedValue.h
template <typename FloatType>
using LinearSmoothedValue = SmoothedValue <FloatType, ValueSmoothingTypes::Linear>;
```

<MarginNote items={[
  { label: 'Learn C++ → 13.15 Alias templates', description: 'Псевдонимы для шаблонов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/alias-templates/' } },

`juce::MathConstants<float>::halfPi` — статическая константа шаблона структуры: внутри записано `static constexpr FloatType pi = static_cast<FloatType> (3.141592653589793238L);` и так же для других констант. Аргумент `float` даёт π сразу в нужном типе, и в выражении с `float` нет перехода к `double`.

</MarginNote>

Аргументом бывает и тип функции:

```cpp
// LfoVisualizer.h
using ReadAllLfoSamples = std::function<void(juce::AudioBuffer<float>&)>;
```

<MarginNote items={[
  { label: 'Стандартная библиотека C++ → std::function', description: 'Как LfoVisualizer хранит лямбды редактора в полях std::function.', target: { article: 'cpp-std', anchor: 'function' } },

Запись `void(juce::AudioBuffer<float>&)` описывает функцию, которая ничего не возвращает и принимает ссылку на буфер. Так `LfoVisualizer` объявляет, какой вызов ему нужен от процессора, и лямбды из `PluginEditor` подходят под эту сигнатуру. `juce::dsp::Oscillator<float>` хранит генератор формы волны так же, в `std::function<float (float)>`. Поэтому лямбда `[](auto phase) { ... }` из `Tremolo.h` при создании осциллятора получает параметр типа `float`.

</MarginNote>

### auto в параметрах {#auto-parameters}

<MarginNote items={[
  { label: 'Learn C++ → 11.8 Function templates with multiple template types', description: 'Раздел Abbreviated function templates: auto в параметрах (C++20).', target: { url: 'https://www.learncpp.com/cpp-tutorial/function-templates-with-multiple-template-types/' } },
  { label: 'Кто владеет объектом → Передача владения процессору', description: 'Что addParameterToProcessor делает с объектом параметра.', target: { article: 'cpp-ownership', anchor: 'juce-handover' } },

Функция `addParameterToProcessor` из `Parameters.cpp` объявлена с параметром `auto parameter`. С C++20 это сокращённая запись шаблона функции (abbreviated function template): каждый параметр `auto` становится отдельным параметром шаблона. Её объявление равносильно такому:

</MarginNote>

```cpp
template <typename Pointer>
auto& addParameterToProcessor (juce::AudioProcessor& processor, Pointer parameter);
```

Три функции `create…Parameter` передают в неё `std::unique_ptr<juce::AudioParameterFloat>`, `std::unique_ptr<juce::AudioParameterBool>` и `std::unique_ptr<juce::AudioParameterChoice>`. Компилятор создаёт три версии функции, и тип результата `auto&` в каждой выводится из `return result;`: `AudioParameterFloat&`, `AudioParameterBool&`, `AudioParameterChoice&`. Лямбда с параметром `auto` (C++14) устроена так же: шаблоном становится её оператор вызова, о чём сказано в разделе [«Лямбды»](/cpp-std/#lambdas) статьи о стандартной библиотеке.

### Требования к типу {#template-requirements}

<MarginNote items={[
  { label: 'Learn C++ → 11.7 Function template instantiation', description: 'Раздел о том, что шаблон с неподходящим типом не компилируется.', target: { url: 'https://www.learncpp.com/cpp-tutorial/function-template-instantiation/' } },
  { label: 'cppreference → Dependent names', description: 'Имена, смысл которых зависит от параметра шаблона.', target: { url: 'https://en.cppreference.com/w/cpp/language/dependent_name' } },
]}>

Шаблон не перечисляет, что должен уметь тип-аргумент. Требования следуют из тела: что тело вызывает у параметра, то у типа и должно быть. Компилятор проверяет это при инстанцировании, для конкретного типа:

</MarginNote>

```cpp
// Шаблон требует от Meter метод getLevel(), но нигде этого не объявляет
template <typename Meter>
float readLevel (const Meter& meter)
{
    return meter.getLevel();
}

struct PeakMeter
{
    float getLevel() const { return peak; }

    float peak = 0.5f;
};

auto level = readLevel (PeakMeter {});  // компилируется: метод есть
auto wrong = readLevel (0.5f);          // ошибка: у float нет getLevel()
```

Пока шаблон не использован, выражение `meter.getLevel()` полностью не проверяется: тип `Meter` неизвестен, и смысл выражения зависит от него (dependent name). Ошибка из последней строки указывает на `return meter.getLevel();` внутри шаблона, а строки `in instantiation of` в сообщении компилятора ведут к вызову, который её вызвал. Это похоже на утиную типизацию Python, только несоответствие обнаруживается при сборке. В Go такие требования записывают интерфейсом. В C++20 для этого есть концепты (concepts), но код курса и сериализация JUCE их не используют. По этому правилу компилируется и `archive.getVersion()` в методе `serialise` из раздела [«Сохранение параметров»](#serialise).

### Вариативные шаблоны, CTAD и span {#variadic-ctad}

Функция `juce::ignoreUnused`, о которой шла речь в первой части, написана как вариативный шаблон (C++11): пакет параметров `typename... Types` принимает любое число аргументов любых типов. Тело у неё пустое:

```cpp
template <typename... Types>
void ignoreUnused(Types&&...) noexcept {}
```

С C++17 компилятор выводит и аргументы шаблона класса (class template argument deduction, CTAD). Поэтому в `LfoVisualizer.cpp` записано `std::span{...}` без `<const float>`:

```cpp
lfoSamplesToPlot.pushBack(std::span{
    buffer.getReadPointer(0), static_cast<size_t>(buffer.getNumSamples())});
```

<MarginNote items={[
  { label: 'cppreference → std::span', description: 'Неуправляющее представление непрерывной области памяти.', target: { url: 'https://en.cppreference.com/w/cpp/container/span' } },
  { label: 'Learn C++ → 13.14 Class template argument deduction (CTAD) and deduction guides', description: 'Вывод аргументов шаблона класса и подсказки вывода.', target: { url: 'https://www.learncpp.com/cpp-tutorial/class-template-argument-deduction-ctad-and-deduction-guides/' } },
  { label: 'Основы C++ для JUCE → Массивы и std::span', description: 'std::span как параметр функции для std::array, std::vector и указателя с длиной.', target: { article: 'cpp-basics', anchor: 'arrays-span' } },
]}>

`std::span` (C++20) — «вид» на непрерывный кусок памяти: указатель и длина, без владения данными. Это аналог среза в Go без возможности расти или `memoryview` в Python. Через него в `pushBack` передаются указатель на отсчёты канала и их число, а сами отсчёты не копируются.

</MarginNote>

### enum class {#enum-class}

<MarginNote items={[
  { label: 'Learn C++ → 13.6 Scoped enumerations (enum classes)', description: 'Перечисления с областью видимости.', target: { url: 'https://www.learncpp.com/cpp-tutorial/scoped-enumerations-enum-classes/' } },
]}>

`enum class` (C++11) — перечисление со своей областью видимости: значения пишутся как `LfoWaveform::sine`, а не просто `sine`, и неявно в число не превращаются. Старый `enum` из C++98 выбрасывал имена значений наружу и молча приводился к `int`. `LfoWaveform` объявлено внутри `Tremolo` с явным базовым типом `size_t`, чтобы значение подходило как индекс массива.

</MarginNote>

```cpp
class Tremolo {
public:
  enum class LfoWaveform : size_t {
    sine = 0,
    triangle = 1,
  };
  // ...
};
```

Переход к числу и обратно делают явно. JUCE предоставляет `juce::toUnderlyingType` для первого направления, `static_cast` — для второго:

```cpp
lfos[juce::toUnderlyingType(currentLfo)].processSample(0.f);
static_cast<Tremolo::LfoWaveform>(parameters.waveform.getIndex())
```

Рядом в `Tremolo.h` объявлено и `enum class ApplySmoothing { no, yes };`. Это приём читаемости: вызов `setModulationRateHz(5.f, ApplySmoothing::no)` понятнее, чем `setModulationRateHz(5.f, false)`.

## Сохранение параметров: шаблон serialise {#serialise}

Хост сохраняет состояние плагина в проекте: вызывает `getStateInformation`, и `PluginProcessor` передаёт параметры в `JsonSerializer::serialize`. Тот записывает их в JSON такого вида (ожидаемый результат из теста `JsonSerializerTest.cpp`):

```json
{
  "__version__": 1,
  "pluginName": "Tremolo",
  "modulationRateHz": 10.0,
  "bypassed": true,
  "modulationWaveform": "Triangle"
}
```

Преобразование в JSON и обратно выполняет JUCE, но список полей ей сообщает сам тип. В `JsonSerializer.cpp` для этого объявлена структура `SerializableParameters`:

```cpp
// JsonSerializer.cpp
struct SerializableParameters {
  float rate;
  bool bypassed;
  juce::String waveform;

  static constexpr auto marshallingVersion = 1;

  template <typename Archive, typename T>
  static void serialise(Archive& archive, T& p) {
    using namespace juce;

    if (archive.getVersion() != 1) {
      return;
    }

    std::string pluginName = TREMOLO_PLUGIN_NAME;

    archive(named("pluginName", pluginName));

    if (pluginName != TREMOLO_PLUGIN_NAME) {
      return;
    }

    archive(named("modulationRateHz", p.rate), named("bypassed", p.bypassed),
            named("modulationWaveform", p.waveform));
  }
};
```

Отдельная структура нужна, потому что `Parameters` хранит ссылки на объекты параметров процессора, а в JSON попадают значения: число, флаг и название формы волны. Функция `from()` копирует их в `SerializableParameters`, и результат передаётся в JUCE:

```cpp
// JsonSerializer::serialize
const auto json = juce::ToVar::convert(from(parameters));

// JsonSerializer::deserialize
const auto parsedParameters =
    juce::FromVar::convert<SerializableParameters>(parsedResult);
```

### Кто вызывает serialise {#serialise-call}

<MarginNote items={[
  { label: 'JUCE → SerialisationTraits', description: 'Документация: что должно быть у типа, чтобы его сериализовать.', target: { url: 'https://docs.juce.com/master/structjuce_1_1SerialisationTraits.html' } },
  { label: 'Learn C++ → 26.4 Class template specialization', description: 'Отдельная версия шаблона класса для конкретного типа.', target: { url: 'https://www.learncpp.com/cpp-tutorial/class-template-specialization/' } },
]}>

Ни одна строка плагина не вызывает `serialise` по имени: его вызывает JUCE внутри `ToVar::convert` и `FromVar::convert`. Документация `juce::SerialisationTraits` описывает договор: у типа есть константа `marshallingVersion` и либо один шаблон `serialise (Archive&, Item&)`, либо пара `load` и `save`. Договор можно выполнить и снаружи типа, специализацией шаблона `juce::SerialisationTraits<T>`; так JUCE сама поддерживает `std::vector`, `std::optional`, `std::string` и `juce::StringArray`.

</MarginNote>

Наличие этих членов JUCE проверяет при компиляции. Она пробует вызвать `T::serialise` с пробным архивом `juce::detail::DummyArchive` и через `if constexpr` (C++17) выбирает подходящую ветку; сам вызов при этом не выполняется. Если у типа нет ни `marshallingVersion`, ни функций сериализации, сборка остановится на `static_assert` с сообщением `No serialisation function found or marshallingVersion unset`.

### Archive и T: одна функция для записи и чтения {#archive-types}

JUCE подставляет параметры шаблона `serialise` по-разному в зависимости от направления. Типы и значения ниже проверены на JUCE 8.0.12.

- Сохранение, `ToVar::convert`. `Archive` — `juce::ToVar::Visitor`, `T` — `const SerializableParameters`. `getVersion()` возвращает `marshallingVersion`, то есть 1; `archive(named(...))` добавляет свойство в объект JSON.
- Загрузка, `FromVar::convert<SerializableParameters>`. `Archive` — `juce::FromVar::Visitor`, `T` — `SerializableParameters`. `getVersion()` возвращает значение `"__version__"` из JSON или `std::nullopt`; `archive(named(...))` читает свойство и записывает его в поле.
- Проверка договора при компиляции. `Archive` — `juce::detail::DummyArchive`, `T` — `SerializableParameters`; вызов не выполняется.

`Visitor` — закрытые вложенные классы `ToVar` и `FromVar`, в своём коде их имя не написать. Шаблону `serialise` имя и не нужно: он примет любой тип, у которого есть `getVersion()` и оператор вызова, по правилу из раздела [«Требования к типу»](#template-requirements).

Параметр `T` нужен из-за константности. При сохранении JUCE передаёт объект по `const&`, ведь запись в JSON не должна его менять. При загрузке объект передаётся по обычной ссылке, чтобы архив заполнил поля. Параметр типа `SerializableParameters&` не принял бы константный объект, а шаблон по `T` принимает оба варианта, и одно тело описывает и запись, и чтение.

<MarginNote items={[
  { label: 'JUCE → juce_Serialisation.h 8.0.12', description: 'Исходник Named, named() и проверки договора сериализации.', target: { url: 'https://github.com/juce-framework/JUCE/blob/8.0.12/modules/juce_core/serialisation/juce_Serialisation.h' } },
]}>

`named` — шаблон функции JUCE с двумя перегрузками. Обе возвращают `Named<T>`: структуру из имени `std::string_view name` и ссылки `T& value`. Значение при этом не копируется.

</MarginNote>

```cpp
// juce_Serialisation.h
template <typename T> constexpr auto named (std::string_view c, T& t)       { return Named<T>       { c, t }; }
template <typename T> constexpr auto named (std::string_view c, const T& t) { return Named<const T> { c, t }; }
```

При сохранении `p.rate` — поле константного объекта, и подходит вторая перегрузка: получается `Named<const float>`. При загрузке выбирается первая, `Named<float>`, и через ссылку архив записывает прочитанное число прямо в поле.

### getVersion() {#get-version}

<MarginNote items={[
  { label: 'Learn C++ → 12.15 std::optional', description: 'Значение, которого может не быть.', target: { url: 'https://www.learncpp.com/cpp-tutorial/stdoptional/' } },
  { label: 'cppreference → operator== (std::optional)', description: 'Раздел Compare an optional object with a value: пустой optional не равен никакому значению.', target: { url: 'https://en.cppreference.com/w/cpp/utility/optional/operator_cmp' } },
  { label: 'Стандартная библиотека C++ → std::optional', description: 'Проверка и чтение значения, операторы * и -> без проверки на пустоту.', target: { article: 'cpp-std', anchor: 'optional' } },
]}>

`getVersion()` — метод класса архива: оба `Visitor` объявляют `std::optional<int> getVersion() const`. При сохранении он возвращает версию, с которой пишется объект, то есть `marshallingVersion`, и `ToVar` записывает её в JSON как `"__version__": 1`. При загрузке метод возвращает значение `"__version__"` из JSON, а если такого свойства нет — `std::nullopt`.

</MarginNote>

`archive.getVersion() != 1` сравнивает `std::optional<int>` с числом. Результат `true`, если значения нет или оно отличается от 1, и тогда `serialise` выходит, не читая полей. `FromVar::convert` всё равно возвращает объект: его поля остаются нулевыми, `waveform` — пустой строкой. `deserialize` отклоняет такой результат, потому что пустого названия нет в списке форм волны, и параметры плагина не меняются.

### archive(a, b, c) {#archive-call}

<MarginNote items={[
  { label: 'Learn C++ → 21.10 Overloading the parenthesis operator', description: 'Объект, который вызывают как функцию.', target: { url: 'https://www.learncpp.com/cpp-tutorial/overloading-the-parenthesis-operator/' } },
  { label: 'cppreference → Fold expressions', description: 'Свёртка пакета параметров по оператору (C++17).', target: { url: 'https://en.cppreference.com/w/cpp/language/fold' } },
  { label: 'cppreference → Forwarding references', description: 'Ссылка T&& в шаблоне, которая принимает и переменные, и временные объекты.', target: { url: 'https://en.cppreference.com/w/cpp/language/reference#Forwarding_references' } },
]}>

`archive(named(...))` вызывает объект как функцию. У обоих `Visitor` перегружен оператор вызова `operator()`, и он объявлен [вариативным шаблоном](#variadic-ctad):

</MarginNote>

```cpp
// juce_JSONSerialisation.h, ToVar::Visitor и FromVar::Visitor
template <typename... Ts>
void operator() (Ts&&... ts)
{
    (visit (std::forward<Ts> (ts)), ...);
}
```

- `typename... Ts` — пакет параметров: вызов с одним аргументом даёт один тип, с тремя — три.
- `Ts&&` у параметра шаблона — пересылающая ссылка (forwarding reference). Она принимает и переменную, и временный объект. Результат `named(...)` временный, и обычная ссылка `Ts&` к нему не привязалась бы.
- `(visit (std::forward<Ts> (ts)), ...)` — выражение свёртки (fold expression, C++17) по оператору «запятая». Компилятор разворачивает его в `visit(a), visit(b), visit(c)`, и вызовы выполняются слева направо. `std::forward` передаёт каждый аргумент дальше в том виде, в каком он пришёл: временный остаётся временным.

`visit` перегружен для разных аргументов. Для `Named<T>` версия `ToVar` добавляет в объект JSON свойство с именем `name` и значением `value`. Версия `FromVar` ищет свойство с этим именем и записывает его в `value`; если свойства нет или его тип не подходит, загрузка помечается неудачной, и `convert` возвращает пустой `std::optional`. Поэтому `archive(a, b, c)` делает то же, что `archive(a); archive(b); archive(c);`, а свойства в JSON идут в порядке аргументов.

Переменная `pluginName` работает в обе стороны. При сохранении архив пишет в JSON её начальное значение — название плагина из макроса `TREMOLO_PLUGIN_NAME`, который задаёт CMake ([«Макросы из CMake»](/cpp-basics/#cmake-macros)). При загрузке архив заменяет значение переменной прочитанным из JSON. Если состояние сохранил другой плагин, названия не совпадут, `serialise` выйдет до чтения параметров, и `deserialize` отклонит результат, как при чужой версии.

<SelfCheck question="Почему serialise принимает T&, а не SerializableParameters&?">

При сохранении JUCE передаёт объект как константный, и `T` выводится как `const SerializableParameters`. Ссылка `SerializableParameters&` к константному объекту не привязывается. Шаблон принимает и константный объект при записи, и изменяемый при чтении, поэтому одна функция описывает оба направления.

</SelfCheck>

<SelfCheck question="Что вернёт archive.getVersion() при загрузке JSON без свойства __version__, и что станет с параметрами плагина?">

`std::nullopt`. Сравнение `std::nullopt != 1` истинно, и `serialise` выходит, не читая полей. `FromVar::convert` вернёт объект с нулевой частотой и пустым названием формы волны, `deserialize` не найдёт пустое название в списке и вернёт ошибку, не меняя параметры.

</SelfCheck>

## Время жизни объектов и RAII {#lifetime}

<MarginNote items={[
  { label: 'Learn C++ → 15.4 Introduction to destructors', description: 'Деструктор: что делает класс в конце жизни объекта.', target: { url: 'https://www.learncpp.com/cpp-tutorial/introduction-to-destructors/' } },
  { label: 'Кто владеет объектом → Стек, поля и куча', description: 'Где живут локальные переменные, поля и объекты из new.', target: { article: 'cpp-ownership', anchor: 'storage' } },
]}>

В C++ нет сборщика мусора, объект существует столько, сколько определено правилами языка. Локальная переменная живёт до конца блока `{ }`, и при выходе из него вызывается её деструктор (метод `~ClassName()`) в порядке, обратном объявлению. Поле живёт, пока жив объект-владелец. Объект из `new` живёт, пока его не удалят через `delete`. Подробно эти три случая разобраны в статье [«Кто владеет объектом»](/cpp-ownership/).

</MarginNote>

<Term id="raii" firstMention define>RAII</Term> — идиома, при которой ресурс захватывается в конструкторе и освобождается в деструкторе. В `processBlock` плагина её показывает одна строка:

```cpp
void PluginProcessor::processBlock(juce::AudioBuffer<float>& buffer,
                                   juce::MidiBuffer& midiMessages) {
  juce::ignoreUnused(midiMessages);

  juce::ScopedNoDenormals noDenormals;
  // ...
}
```

`ScopedNoDenormals` в конструкторе переключает процессор в режим, где очень малые числа с плавающей точкой (денормализованные) обнуляются: арифметика с ними выполняется заметно медленнее. Деструктор возвращает прежний режим при выходе из `processBlock`. Переменная `noDenormals` нигде не используется, её смысл целиком в конструкторе и деструкторе. Освобождение срабатывает при любом выходе из области видимости, включая `return` и исключение; в Python для этого служит `with`, в Go — `defer`. Так же работают `std::unique_ptr`, блокировки мьютексов и файловые потоки.

Временный объект без имени, например `juce::String{"Triangle"}` или `BusesProperties()`, живёт до конца полного выражения, обычно до `;`. Сохранять ссылку на него дольше нельзя.

## Копирование и запрет копирования {#copying}

<MarginNote items={[
  { label: 'Learn C++ → 14.14 Introduction to the copy constructor', description: 'Конструктор копирования.', target: { url: 'https://www.learncpp.com/cpp-tutorial/introduction-to-the-copy-constructor/' } },
  { label: 'Learn C++ → 11.4 Deleting functions', description: 'Запрет функций через = delete.', target: { url: 'https://www.learncpp.com/cpp-tutorial/deleting-functions/' } },
]}>

По умолчанию объекты C++ копируются при присваивании, передаче по значению и возврате: компилятор сам создаёт конструктор копирования и оператор присваивания, которые копируют поле за полем. Для некоторых классов копия не имеет смысла: копия процессора плагина или окна редактора — ошибка. Запрет записывается так (C++11):

</MarginNote>

```cpp
PluginProcessor(const PluginProcessor&) = delete;
PluginProcessor& operator=(const PluginProcessor&) = delete;
```

`= delete` удаляет функцию: любая попытка скопировать объект становится ошибкой компиляции. В C++98 эти функции объявляли `private` и не определяли, и ошибка появлялась позже, при компоновке.

В `PluginProcessor` эти две строки пишет макрос JUCE (см. [раздел о макросах](#juce-macros)). В C++11 появилась и семантика перемещения (`T&&`, `std::move`): вместо копирования содержимое «забирается» у объекта, который больше не нужен, например у временного. Поэтому возврат большого объекта из функции по значению в современном C++ обычно не копирует данные. `std::unique_ptr` не копируется, а только перемещается, и в статье [«Кто владеет объектом»](/cpp-ownership/#unique-ptr) это объяснено на примере параметров плагина.

## Неявные преобразования и перегрузка операторов {#operator-overloading}

<MarginNote items={[
  { label: 'Learn C++ → 21.1 Introduction to operator overloading', description: 'Перегрузка операторов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/introduction-to-operator-overloading/' } },
  { label: 'Learn C++ → 21.11 Overloading typecasts', description: 'Перегрузка операторов приведения типов.', target: { url: 'https://www.learncpp.com/cpp-tutorial/overloading-typecasts/' } },
]}>

Класс может определить собственные версии операторов: `operator==`, `operator!=`, `operator=`, `operator[]` и других, а также операторы преобразования к другому типу. Перегрузка операторов есть в Python (`__eq__`, `__add__`), но нет в Go и TypeScript. Из-за неявных преобразований часть строк плагина выглядит проще, чем работает.

</MarginNote>

Параметры плагина хранятся как ссылки на объекты JUCE, а не как числа. Эти классы определяют оператор преобразования и перегруженное присваивание:

```cpp
tremolo.setModulationRateHz(parameters.rate, applySmoothing);  // operator float()
bypassTransitionSmoother.setBypass(parameters.bypassed);       // operator bool()
parameters.rate = 10.f;                                        // operator=(float)
```

`juce::AudioParameterFloat` объявляет `operator float() const noexcept` и `operator=(float)`, `juce::AudioParameterBool` — `operator bool()` и `operator=(bool)`. Присваивание числа выглядит обычно, но вызывает метод, который уведомляет хост о смене значения. Поэтому `parameters.rate` читается как число, хотя это объект.

Другой вид неявного преобразования — конструктор с одним параметром. Метод `juce::dsp::AudioBlock<float> getBlock() { return buffer; }` в тестах возвращает `AudioBlock`, хотя `buffer` — `AudioBuffer<float>`: у `AudioBlock` есть конструктор из буфера, и компилятор вызывает его сам. Блок — «вид» на данные буфера, отсчёты не копируются. Так же строковый литерал `"None"` превращается в `juce::String` в `return "None";`.

## Макросы JUCE {#juce-macros}

Макрос (`#define`) — текстовая подстановка препроцессора. Имена макросов по соглашению пишут заглавными буквами. В классах плагина используются макросы JUCE `jassert` и семейство `JUCE_DECLARE_NON_COPYABLE`.

### jassert {#jassert}

Макрос `jassert(условие)` проверяет инвариант. В отладочной сборке при ложном условии срабатывает точка останова в отладчике на этой строке. В релизной сборке макрос превращается в пустую инструкцию, условие даже не вычисляется, поэтому внутри `jassert` нельзя писать код с побочными эффектами. Это определено в `juce_PlatformDefs.h`. Аналог стандартного `assert` из `<cassert>`.

```cpp
jassert(0.0 < crossfadeLengthSeconds);
jassert(buffer.getNumSamples() <= dryBuffer.getNumSamples());
```

### Запрет копирования и детектор утечек {#non-copyable}

Макрос `JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR(Class)` раскрывается в две удалённые функции, `Class(const Class&) = delete;` и `Class& operator=(const Class&) = delete;` (их даёт макрос `JUCE_DECLARE_NON_COPYABLE`), и в `JUCE_LEAK_DETECTOR(Class)`. Второй добавляет счётчик живых объектов, который сообщает об утечке при завершении программы. Макрос ставят в конец класса: им пользуются `PluginProcessor` и `PluginEditor`, а `Parameters` — парой `JUCE_DECLARE_NON_COPYABLE(Parameters)` и `JUCE_DECLARE_NON_MOVEABLE(Parameters)`, которая запрещает и перемещение. О детекторе утечек подробнее в статье [«C++ в аудиопотоке»](/cpp-audio-thread/#leak-detector).

Макрос `JUCE_CALLTYPE`, который задаёт соглашение о вызове, разобран в [первой части](/cpp-basics/#entry-point).

## Тесты на GoogleTest {#tests}

<MarginNote items={[
  { label: 'GoogleTest → Primer', description: 'Основы TEST, TEST_F и проверок EXPECT и ASSERT.', target: { url: 'https://google.github.io/googletest/primer.html' } },
]}>

Тесты плагина написаны на GoogleTest и лежат в папке `test/`. `TEST(Группа, Имя)` раскрывается в определение класса-наследника `testing::Test` и его метода, тело которого вы пишете в фигурных скобках. `TEST_F` делает то же, но наследуется от вашего класса-фикстуры (fixture), как `BypassTransitionSmootherTest`: перед каждым тестом создаётся новый объект фикстуры и вызывается её `SetUp()`. Аналог — `setUp` в `unittest` Python или `beforeEach` в Jest.

</MarginNote>

```cpp
class BypassTransitionSmootherTest : public testing::Test {
protected:
  void SetUp() override { /* подготовка */ }

  BypassTransitionSmoother testee{1.0};
  juce::AudioBuffer<float> buffer;
};

TEST_F(BypassTransitionSmootherTest, OffOnTransitionIsSmooth) {
  testee.setBypass(true);
  ASSERT_TRUE(testee.isTransitioning());
  // ...
  EXPECT_FALSE(testee.isTransitioning());
}
```

Проверки `EXPECT_EQ`, `EXPECT_TRUE`, `EXPECT_NEAR`, `EXPECT_FLOAT_EQ` при неудаче помечают тест проваленным, но он продолжает выполняться. `ASSERT_*` при неудаче прерывает тест сразу, и его берут для предусловий, без которых дальнейшие проверки бессмысленны. Поля фикстуры объявлены `protected`, потому что каждый `TEST_F` технически является наследником фикстуры. Для сравнения вещественных чисел используют `EXPECT_NEAR` и `EXPECT_FLOAT_EQ`, а не `==`, о чём предупреждает флаг `-Wfloat-equal`.

## Самопроверка {#self-check}

<SelfCheck question="Что произойдёт, если в PluginEditor написать void resize() вместо void resized() и не поставить override?">

Компилятор примет `resize()` как новый метод. JUCE вызывает виртуальный `resized()` базового класса `Component`, он останется пустым, и компоненты редактора не получат размеры. Ошибки при сборке не будет. С `override` опечатка остановит компиляцию: у базы нет метода `resize()`, который можно переопределить.

</SelfCheck>

<SelfCheck question="Почему в конструкторе BypassTransitionSmoother параметр назван crossfadeLengthSecondsValue, а не crossfadeLengthSeconds?">

Параметр с тем же именем, что и поле, скрыл бы его в теле конструктора, и `-Wshadow` предупредил бы об этом. Разные имена позволяют использовать поле в `jassert(0.0 < crossfadeLengthSeconds)` и в теле, не путая его с параметром.

</SelfCheck>

<SelfCheck question="Почему вместо parameters.rate в processBlock иногда пишут parameters.bypassed.get()?">

`parameters.bypassed` — ссылка на объект `AudioParameterBool`, а не `bool`. Там, где нужен `bool`, компилятор сам вызывает `operator bool()`. Явный `.get()` делает то же самое и показывает, что читается значение параметра, а не передаётся сам объект; это нужно, например, в выражении `parameters.bypassed.get() && !bypassTransitionSmoother.isTransitioning()`.

</SelfCheck>

<SelfCheck question="Что делает JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR(PluginEditor)?">

Удаляет конструктор копирования и оператор присваивания `PluginEditor`, поэтому копировать редактор нельзя: попытка не скомпилируется. Кроме того, добавляет детектор утечек, который при завершении программы сообщает об объектах `PluginEditor`, не удалённых к этому моменту.

</SelfCheck>
