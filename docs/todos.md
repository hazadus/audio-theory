# Задачи реализации

Список раскрывает [план реализации](plan.md) в задачи размером с один логичный коммит. Требования и контракты находятся в [спецификации](spec.md), целевые пути — в [structure.md](structure.md), правила UI — в [дизайн-системе](design-system.md).

Нумерация сквозная; выполненная задача отмечается `- [x]`. Отмечать задачу после реализации, указанной проверки и коммита. Код, необходимые тесты и документация одной функции входят в тот же коммит. Новые дефекты оформлять отдельными задачами с очередными номерами, не перенумеровывая существующие.

Порядок учитывает зависимости плана. Команды `just` добавляются вместе с работающей реализацией, без пустых заглушек. Выбор дополнительных инструментов фиксируется в `techstack.md` при подключении. После настройки GitHub Pages готовые изменения проверяются также на публичном сайте. Статьи и изменения их текста включаются в коммит только после локальной проверки и одобрения автором; редакционная проверка по tropes.md выполняется до передачи автору.

Проверка сборки новых статей до коммита использует локальный режим с состоянием «Черновик». Публикуемая сборка после коммита требует настоящую Git-дату; обход этой проверки в CI не допускается.

При изменении команд, путей, проверок или процесса подготовки и публикации материалов обновлять затронутые скиллы в `.agents/skills/` и `.claude/skills/` в том же пункте. Общие правила подготовки статей после задачи 27 хранить в `docs/authoring/`; в скиллах оставлять ссылки и необходимые ограничения их процесса. Различия вызовов и инструментов Codex и Claude Code сохранять.

## Этап 1. Приложение и ранний деплой

Уточнить в обоих вариантах `execute` и `issue` фактический запуск сайта, получение локального адреса и управление запущенным для проверки процессом; в `commit` — доступную команду сборки.
  **Проверка:** установить зависимости из чистого checkout; `just dev` открывает начальную страницу, `just build` создаёт статические файлы без серверной части. Инструкции скиллов используют работающие команды; при завершении локальной проверки останавливаются только процессы, запущенные агентом для неё.

- [x] 2. **Подключить MDX и KaTeX.**

  **Проверка:** собрать и открыть сайт в корне и под непустым префиксом. Проверить ссылки и ресурсы, сохранение query и якоря, отсутствие двойного префикса и неизменность внешних URL; автоматические сценарии подключаются в задаче 4.

- [x] 4. **Настроить инструменты проверки и общий интерфейс команд.**
  Подключить форматирование, линтер, проверку типов, unit- и браузерные тесты; добавить `just fmt`, `lint`, `typecheck`, `test`, `test-e2e`. Сверить названия с `~/Projects/table/justfile`; `just` выводит список с русскими комментариями. Сверить проверки в `commit`, `execute` и `issue` обоих агентов с рецептами и выбранными инструментами; убрать оговорки об отсутствии уже созданных команд, уточнить условия полного E2E-прогона и доступный способ проверки DOM.
  **Проверка:** все добавленные команды выполняются; тесты проверяют построитель URL и открытие начальной страницы. Контрольные ошибки линтера, типов и тестов возвращают ненулевой код. Фактический выбор инструментов записан в `techstack.md`; скиллы не ссылаются на отсутствующие команды или инструменты и не выдают пропущенную проверку за успешную.

- [x] 5. **Добавить Pagefind и проверку начального артефакта.**
  Включить построение индекса в `just build`, проверку существования ресурсов, внутренних страниц и якорей; на этом этапе индексировать содержимое начальной страницы.
  **Проверка:** после сборки присутствуют HTML и индекс; поиск по тексту начальной страницы работает через API. Несуществующая внутренняя цель блокирует сборку, внешние ссылки не требуют сети для проверки артефакта.

- [x] 6. **Настроить CI и первый деплой GitHub Pages.**
  Создать workflow с полной Git-историей, зафиксированными зависимостями, проверками готового каркаса, публикацией того же проверенного артефакта, необходимыми правами и защитой от конфликтующих деплоев. Настроить Pages и описать это в README. Уточнить в `execute` и `issue` обоих агентов фактическую основную ветку, workflow и способ проверить завершение CI и деплоя при порученной публикации; согласовать с `commit` границы коммита и пуша.
  **Проверка:** пуш технического каркаса запускает проверки и успешный деплой; страница и ресурсы доступны по публичному адресу. Контрольная ошибка обязательной проверки останавливает публикацию. Тестовые материалы отсутствуют в артефакте; инструкции скиллов позволяют проверить именно деплой нужного коммита и сохраняют исключение неодобренных материалов из публикации.

- [x] 7. **Добавить production smoke-проверку.**
  Реализовать `just test-production` для опубликованной начальной страницы и ресурсов с учётом базового пути; описать способ указать публичный адрес. В обоих вариантах `execute` и `issue` заменить условную ссылку на будущую команду её фактическим вызовом с нужными параметрами после успешного деплоя.
  **Проверка:** команда проходит для реального GitHub Pages и завершается ошибкой для недоступного адреса или отсутствующего обязательного ресурса. Параметры запуска документированы; вызов из скиллов проверяет настоящий публичный адрес с базовым путём.

## Этап 2. Коллекция и проверка материалов

- [x] 8. **Создать коллекцию статей и справочник групп.**
  Реализовать схему frontmatter и четыре группы `basics`, `digital`, `conv`, `data` по спецификации; добавить генерацию маршрутов из `slug`.
  **Проверка:** корректная тестовая статья получает ожидаемый маршрут; повторный slug, неизвестная группа, пустые обязательные поля и неверное `readingMinutes` отвергаются. Тестовые статьи не публикуются.

- [x] 9. **Создать единый источник глоссария и разрешение целей ссылок.**
  Добавить схему `glossary.json`, внутренние цели `{ article, anchor? }` и внешние `{ url }`, проверку идентификаторов терминов и существующих статей.
  **Проверка:** тесты подтверждают разрешение внутренних и внешних целей; повторный термин, неизвестный slug и неполная запись глоссария вызывают ошибку. Ссылки учитывают базовый путь.

- [x] 10. **Вычислять дату обновления из Git.**
  Добавить получение последнего коммита файла, локальное состояние «Черновик» и ошибку отсутствующей даты в публикуемой сборке. Указать в `commit`, `execute` и `issue` обоих агентов точный способ локальной сборки новой статьи до коммита и отличия от публикуемой сборки.
  **Проверка:** тесты во временном Git-репозитории различают новый файл и файл с несколькими коммитами. Дата не зависит от даты сборки; в CI доступна полная история. По инструкции скиллов новая статья проверяется до коммита как «Черновик», а отсутствие Git-даты в публикуемой сборке остаётся ошибкой.

- [x] 11. **Вычислять время чтения по тексту MDX.**
  Исключить frontmatter, код, формулы и служебную разметку, учитывать видимый текст учебных блоков и ручное `readingMinutes`.
  **Проверка:** unit-тесты подтверждают минимум 1 минуту, округление вверх при 180 словах в минуту, исключения и ручную замену оценки.

- [x] 12. **Добавить стабильные якоря и извлечение заголовков.**
  Поддержать `{#anchor}` для английских идентификаторов, единый набор заголовков для HTML и оглавления, обработку внутренних ссылок MDX через общий построитель URL.
  **Проверка:** переименование русского заголовка не меняет якорь; повторные якоря отвергаются. Заголовки H2/H3 извлекаются в правильном порядке, ссылки на разделы работают под префиксом.

- [x] 13. **Проверять содержимое статьи и нумерацию учебных блоков.**
  Требовать источники, связанные темы, язык листингов и корректные идентификаторы; проверять общую последовательность рисунков и отдельные последовательности таблиц и формул.
  **Проверка:** положительные и отрицательные тестовые материалы подтверждают правила. Отсутствие источников, неверные ссылки и нумерация блокируют сборку; рекомендательные лимиты тегов, врезок и длины кода её не блокируют.

- [x] 14. **Включить проверки материалов в CI.**
  Подключить новые валидаторы к сборке и workflow, исключить служебные материалы из публикации и индекса. Уточнить в `commit`, `execute` и `issue` обоих агентов реальные команды проверки метаданных, ссылок, якорей и нумерации; указать, какие проверки входят в `just build`.
  **Проверка:** CI проходит на корректной коллекции и останавливает деплой при ошибке метаданных, отсутствующей странице или якоре. В собранном артефакте и индексе нет тестовых статей; локальные проверки по скиллам обнаруживают те же ошибки контента до коммита.

  **Проверка:** начальная страница в обеих темах использует нужные шрифты и семантические токены; ресурсы загружаются локально под префиксом. Значимые текст, линии графиков и фокус проходят пороги контраста дизайн-системы.

  **Проверка:** перезагрузка сохраняет тему без вспышки; авто реагирует на изменение системы. Отказ чтения или записи `localStorage` не ломает управление; без JS работает системная тема.

  **Проверка:** служебный образец отображает обязательные элементы на 390 и 1440 px; крошки учитывают группу и базовый путь, текст читается без JS. Пустой необязательный блок предварительных знаний не выводится.

- [x] 19. **Добавить адаптивное оглавление.**

  **Проверка:** длинное оглавление прокручивается отдельно; H4 не включается. Переход закрывает компактный список, раздел не скрыт шапкой, клавиатура и раскрытие работают без JS.

- [x] 20. **Добавить ссылки и копирование адресов разделов.**

  **Проверка:** clipboard получает URL с доменом, базовым путём и нужным якорем. При отказе нет сообщения об успехе, обычная ссылка продолжает работать.
