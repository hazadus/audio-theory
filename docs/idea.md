# Идея проекта

## Замысел

Личный учебник по теории аудио и цифровой обработке звука в виде статического сайта. При помощи агентов я создаю и постепенно дорабатываю статьи и визуализации по темам, которые хочу изучить.

Практический контекст изучения — освоение JUCE для разработки аудиоплагинов и другого аудиософта. Возникла идея дополнять теорию объяснениями аудиоалгоритмов и примерами кода; конкретный формат пока обсуждается.

Материалы связаны между собой: из статьи можно перейти к объяснениям нужных понятий. Учебник растёт по мере появления новых вопросов; агент может как создать статью, так и дополнить существующую.

## Предложения для обсуждения

### Аудиоалгоритмы и практика с JUCE

Предлагается связывать объяснение понятия с его применением в аудиософте: теория → алгоритм → реализация → наблюдаемый и слышимый результат.

В подходящих статьях могут появляться:

- Пошаговое объяснение алгоритма, формулы и описание состояния, которое сохраняется между отсчётами и блоками.
- Небольшая реализация на C++, позволяющая понять сам алгоритм.
- Пример применения в JUCE и ссылка на официальную документацию соответствующего API.
- Условия работы примера: частота дискретизации, число каналов, параметры и ограничения; особенности обработки в реальном времени (real-time processing), если они относятся к теме.
- Упражнение: изменить параметр или реализацию и сопоставить ожидаемый результат с графиком либо звуком.

Это возможное дополнение к статье, а не обязательный набор разделов. Объём кода зависит от темы. Для примеров нужно явно различать фрагмент для объяснения и собираемый проект; для проверенных проектов указывать версию JUCE и способ сборки.

Примеры связей между темами и практикой: амплитуда и децибелы → регулировка усиления; отсчёты, каналы и буферы → обработка блока в JUCE; периодические сигналы → осциллятор; задержка → линия задержки; фильтрация → простой цифровой фильтр.

Официальные материалы для подготовки примеров: [введение в DSP в JUCE](https://juce.com/tutorials/tutorial_dsp_introduction/) и [создание базового аудиоплагина](https://juce.com/tutorials/tutorial_code_basic_plugin/).

### Как устроен материал

Статья отвечает на конкретный вопрос, например: «Почему при понижении частоты дискретизации возникает алиасинг?»

Возможная структура:

1. Какую задачу решает изучаемое понятие или метод, где оно применяется на практике.
2. Какие знания нужны для понимания; ссылки на соответствующие материалы.
3. Интуитивное объяснение на простом примере.
4. Формулы с пояснением обозначений, единиц измерения и условий применимости.
5. Визуализация, а там, где это полезно, — интерактивный эксперимент или звуковой пример.
6. Типичные ошибки и короткие вопросы для самопроверки.
7. Источники и связанные темы.

Это ориентир для автора, а не обязательный набор разделов для каждой статьи.

### Визуализации и звук

Визуализация должна помогать проверить объяснение. Например, изменение частоты сигнала показывает, как меняются его форма и спектр. Звуковой пример позволяет услышать результат обработки.

Интерактивные примеры могут работать в браузере без серверной части. Звук запускается пользователем; рядом указаны параметры примера. Ключевая мысль статьи должна быть понятна и без взаимодействия с примером.

### Работа агентов

Согласованные правила работы агента описаны в [спецификации](spec.md#работа-агента).

Предлагаемый процесс:

1. Проверить существующие материалы, найти связанные темы и выбрать подходящую статью для дополнения либо обосновать создание новой. Если тема уже раскрыта, доработать материал только там, где это необходимо.
2. Определить вопрос статьи и необходимые предварительные знания.
3. Подготовить объяснение, источники, формулы и примеры.
4. Проверить согласованность текста, вычислений и визуализаций; явно указать упрощения.
5. Добавить или обновить внутренние ссылки, при необходимости направляя их на раздел с нужным понятием; проверить сборку и отображение страницы.
6. Представить материал для моей личной проверки и доработать непонятные места перед публикацией.

Для Codex и Claude Code согласован один общий набор правил подготовки материалов в репозитории; требование зафиксировано в [спецификации](spec.md#работа-агента).

### Первая версия

Согласованы пять стартовых статей, включая материал о кривых равной громкости, и один интерактивный пример по дискретизации из [макета статьи](design/3-article.html), с добавлением прослушивания восстановленного сигнала. Состав первого выпуска зафиксирован в [спецификации](spec.md#первый-выпуск), распределение тем — в [topics.md](topics.md#статьи-первого-выпуска).

Первый выпуск проверяет весь путь: создание материала агентом, личную проверку контента, чтение на телефоне и десктопе, переходы между понятиями и публикацию.

### После готовности основной части: RSS

Идея для развития после завершения первого выпуска — RSS-лента статей, чтобы подписываться на материалы через RSS-ридер. Лента может создаваться при сборке и публиковаться вместе со статическим сайтом.

Перед реализацией нужно определить, включать ли в ленту только новые статьи или также обновления существующих, и какой объём текста отдавать: краткое описание или статью целиком. RSS не входит в обязательный объём первого выпуска.
