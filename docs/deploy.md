# CI и GitHub Pages

Основная ветка репозитория `hazadus/audio-theory` — `main`. GitHub Pages включён с источником **GitHub Actions** (`build_type: workflow`, HTTPS включён). Целевой публичный адрес — https://hazadus.github.io/audio-theory/. Первый деплой проверен 1 октября 2026 года для коммита `65fdac87331e4dda885ea42c8c6e0a73ff9f501b`: [CI и деплой](https://github.com/hazadus/audio-theory/actions/runs/36903493614) прошли успешно. Задание проверки и сборки заняло 1 минуту 40 секунд, деплой — 18 секунд. Публичная страница, ресурсы и API Pagefind проверены в браузере.

Workflow [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) называется **GitHub Pages**. Он запускается при пуше в `main`, для pull request в `main` и вручную через Actions. PR проверяется без публикации; ручной запуск публикует только `main`. Публикация обычной задачи не требует PR.

Runner — Ubuntu 24.04, задание `build` работает в официальном контейнере Playwright `v1.63.0-noble`, закреплённом digest в workflow. Он уже содержит Chromium, Firefox, WebKit и системные библиотеки; версия образа должна совпадать с `@playwright/test` в `package.json`. Контейнер запускается под UID 1001, владельцем домашнего каталога GitHub Actions, чтобы Firefox не завершался из-за несовпадения пользователя. Node.js — 22.23.1. Официальные Actions закреплены SHA с комментариями о версиях; npm-зависимости устанавливаются через `npm ci` по `package-lock.json`. Checkout получает полную историю (`fetch-depth: 0`) для будущих Git-дат статей. Кеш npm ускоряет загрузку пакетов и не заменяет установку по lock-файлу.

CI выполняет `npm run fmt:check`, `lint`, `typecheck`, `test`, `test:mdx` и полный `test:e2e`. Отдельного шага `playwright install --with-deps` в CI нет: браузеры запускаются из образа. Образ загружается при подготовке задания; кеш npm хранит пакеты и не кеширует системные библиотеки. Лимит времени `build` — 10 минут. Это те же npm-команды, что вызывают локальные рецепты `just`; установка `just` в CI не нужна. Проверка MDX включает ошибочную формулу и отсутствие тестовых материалов в обычной сборке; unit-тесты подтверждают, что ошибочная внутренняя ссылка блокирует сборку.

`test:e2e` строит HTML и Pagefind в `.e2e/root/` и `.e2e/prefixed/`, проверяет локальные страницы, якоря и ресурсы, затем запускает браузерные сценарии и настоящий поиск. После успеха всех проверок `upload-pages-artifact` загружает **именно `.e2e/prefixed/`**, проверенный браузерами под `/audio-theory/`. Деплой получает этот артефакт того же запуска, без новой сборки. Локальный `just build` по-прежнему создаёт `dist/`. В CI сейчас проверяется готовый каркас; проверки метаданных и нумерации будут подключены вместе с коллекцией статей.

У всего workflow только `contents: read`; дополнительные `pages: write` и `id-token: write` выдаются заданию `deploy`, которое зависит от успешного `build` и использует окружение `github-pages`. Ошибка любого обязательного шага блокирует загрузку артефакта и деплой: `continue-on-error` и обхода через `always()` нет. Группа concurrency `pages-${{ github.ref }}` с `cancel-in-progress: false` не допускает одновременных публикаций из `main` и даёт текущему деплою завершиться; PR проверяются независимо.

## Настройка Pages в новом репозитории

В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**. Для существующего репозитория это уже сделано. Эквивалент создания сайта через GitHub CLI:

```sh
gh api --method POST repos/hazadus/audio-theory/pages -f build_type=workflow
```

Если сайт уже существует с другим источником, использовать `--method PUT`. Проверить настройку:

```sh
gh api repos/hazadus/audio-theory/pages --jq '{build_type, html_url, https_enforced}'
```

Окружение `github-pages` должно разрешать деплой из `main`; если в нём настроено ручное одобрение, дождаться его. Персональный токен в workflow не нужен. Правила и необходимые права описаны в [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Проверка публикации нужного коммита

Проверки, которые требуют нового коммита на GitHub (CI, деплой и публичный сайт), выполняются после разрешённого технического коммита и пуша. Их ожидание не запрещает необходимый для запуска проверок коммит: сначала завершить все доступные локальные проверки, затем выполнить порученную публикацию, не отмечая задачу выполненной до успешных CI, деплоя и публичной проверки. Явная просьба пользователя отложить коммит имеет приоритет.

Коммит и пуш — отдельные действия. Перед коммитом проверить состав изменений; неодобренные статьи, определения глоссария и текст «О проекте» оставить вне публикуемого коммита. Технический каркас можно публиковать до готовности материалов. Если пользователь попросил сначала проверить изменения, дождаться его ответа до коммита и пуша. Скилл `commit` сам не публикует сайт; пуш допустим по явной просьбе либо по прямому требованию выбранного пункта плана.

После разрешённого коммита и при порученной публикации:

```sh
TASK_DEPLOY_SHA=$(git rev-parse HEAD)
git push origin main
gh run list --repo hazadus/audio-theory --workflow pages.yml --branch main --commit "$TASK_DEPLOY_SHA" --event push --limit 10 --json databaseId,headSha,status,conclusion,url
```

Если запуск ещё не появился, повторить получение списка. Сохранить `databaseId` запуска нужного SHA как `TASK_RUN_ID`; не выбирать просто последний workflow репозитория:

```sh
TASK_RUN_ID=123456789 # Заменить на databaseId найденного запуска.
gh run watch "$TASK_RUN_ID" --repo hazadus/audio-theory --exit-status --interval 10
gh run view "$TASK_RUN_ID" --repo hazadus/audio-theory --json headSha,headBranch,event,conclusion,jobs,url
```

Убедиться, что `headSha` совпадает с `TASK_DEPLOY_SHA`, ветка — `main`, итог — `success`, а задание **Деплой GitHub Pages** и шаг **Опубликовать проверенный артефакт** завершились с `success`, не `skipped`. Успех только задания сборки ещё не означает публикацию. При ошибке прочитать `gh run view "$TASK_RUN_ID" --repo hazadus/audio-theory --log-failed`, исправить причину и проверить новый запуск по его SHA.

После успешного деплоя выполнить `just test-production https://hazadus.github.io/audio-theory/`, передав фактический URL окружения `github-pages` из этого запуска с базовым путём. Команда проверяет опубликованную начальную страницу, её локальные ресурсы и модуль Pagefind; параметры и границы проверки описаны в [разделе ниже](#проверка-опубликованного-сайта).

Открыть тот же URL в браузере. Проверить отображение страницы, переход на главную, `/audio-theory/licenses/katex.txt` и запрос API Pagefind из [обзора](overview.md#поисковый-индекс-и-проверка-артефакта): он должен найти начальную страницу. Сетевая smoke-команда не заменяет эти браузерные проверки.

При проверке настройки CI использовать также контрольную ошибку обязательной проверки: неуспешный `build` должен оставить загрузку Pages-артефакта и зависимый `deploy` невыполненными. Ошибочную правку не публиковать как готовый каркас; после её удаления проверить успешный запуск исправленного SHA. Первичная [контрольная проверка](https://github.com/hazadus/audio-theory/actions/runs/36901175290) в отдельной временной ветке завершилась ожидаемой ошибкой линтера: следующие проверки и деплой были пропущены, Pages-артефакт не создан. Ветка после проверки удалена. В артефакте успешного деплоя нет служебных страниц и файлов MDX; сайт проверен также без JavaScript на 390 и 1440 px.

В итоговом отчёте о публикации указать проверенный полный SHA, ссылку на запуск workflow, публичный адрес и результаты проверок. Если коммит или пуш отложен пользователем либо обязательная проверка недоступна, не отмечать пункт выполненным и назвать оставшиеся проверки.

## Проверка опубликованного сайта

После успешного деплоя нужного SHA по [инструкции выше](#проверка-публикации-нужного-коммита) выполните:

```sh
just test-production https://hazadus.github.io/audio-theory/
# Эквивалент без just:
npm run test:production -- https://hazadus.github.io/audio-theory/
```

Единственный обязательный параметр — полный HTTP(S)-адрес начальной страницы вместе с фактическим базовым путём. Для размещения в корне передайте `https://example.org/`; для префикса — `https://example.org/audio-theory/`. Последний `/` добавляется автоматически. Query, якорь и учётные данные не допускаются; переменные окружения не нужны.

Команда проверяет HTTP-ответ, HTML с `<main>`, `<title>` и `<h1>` «Теория аудио», локальные ресурсы из HTML и вложенные ресурсы CSS (включая шрифты и `@import`), а также обязательный `pagefind/pagefind.js`. Ссылки ресурсов того же origin должны оставаться внутри указанного базового пути. Внешние ресурсы и обычные ссылки не запрашиваются. Таймаут каждого запроса — 10 секунд, перенаправления считаются ошибкой. Недоступный адрес, HTTP-ошибка, пустой ответ, HTML вместо ресурса или неправильный тип CSS/JavaScript дают ненулевой код завершения и адрес ошибки.

Это сетевая smoke-проверка готового каркаса: она не проверяет отображение страницы или запросы API Pagefind. Браузерные проверки остаются отдельными; smoke-сценарий будет расширяться вместе с готовыми страницами и функциями.
