# Стайлгайд

Общие соглашения проекта «Теория аудио». Требования к сайту, материалам и работе агента находятся в [спецификации](./spec.md), визуальные параметры и правила реализации UI — в [дизайн-системе](./design-system.md). Статусы технологий указаны в [техническом стеке](./techstack.md); предварительный выбор не считается окончательным.

## Простота

- Читаемость важнее абстракций и заделов на будущие функции.
- Три похожих фрагмента допустимы, пока обобщение не делает код яснее.
- Функция или компонент решает одну задачу; большой модуль делится по смысловым границам.
- Зависимости, состояния и имена должны быть явными.
- Возможности вне [спецификации](./spec.md) не добавляются без отдельного решения.
- Реализация сохраняет статическое размещение на GitHub Pages: интерактивные примеры работают в браузере, серверная часть не требуется.

## Язык

- Материалы, интерфейс и пользовательские ошибки — на русском.
- При первом упоминании основного понятия в каждой статье после русского названия приводится английское в скобках: «частота дискретизации (sample rate)». При последующих упоминаниях повторять английское название не обязательно.
- Рабочее название сайта — «Теория аудио».
- Идентификаторы в коде, имена файлов и машинные коды ошибок — на английском. Адреса статей называются по понятиям, например `/sampling/` и `/buffer-size/`.
- Комментарии и JSDoc в коде, документация и описания коммитов — на русском.
- Каждый скрипт, включая unit- и E2E-тесты, начинается с комментария-заголовка, кратко описывающего его назначение.
- Структурные имена событий логов — на английском.

## Команды разработки

Общие операции запускаются через `just` из корня проекта. Названия и назначение согласованы с `~/Projects/table/justfile`; реализация рецептов соответствует Astro и инструментам этого проекта.

| Команда | Назначение |
| --- | --- |
| `just` | Показать список доступных команд |
| `just dev` | Запустить сайт в режиме разработки |
| `just fmt` | Отформатировать код |
| `just lint` | Проверить код линтером |
| `just typecheck` | Проверить типы |
| `just test` | Запустить unit-тесты |
| `just test-e2e` | Запустить обязательный набор сквозных тестов (не более 12), как в CI |
| `just test-e2e-full` | Запустить полную матрицу сквозных тестов для диагностики |
| `just test-production` | Выполнить smoke-проверку опубликованного сайта |
| `just build` | Собрать сайт для публикации |

Комментарии к рецептам — на русском. Если команда использует переменные окружения, они описываются в `.env.example` по правилам ниже.

**Жёсткое правило: E2E-тесты в CI не плодить.** Обязательный набор ограничен 12 проверками (метки `@ci`, `@ci-root`), а прогон тестов — несколькими десятками секунд. Новым сценариям метка `@ci` не ставится, лимит в `scripts/check-e2e-budget.mjs` не повышается; более важный сценарий заменяет существующий `@ci`, который остаётся в `just test-e2e-full`. Подробности — в [обзоре](overview.md#браузерные-проверки).

## Конфигурация

В коде приложения и Astro/MDX-компонентах импорты файлов из `src/` записываются через алиас `@/`, заданный в `tsconfig.json`: например, `@/lib/urls`, а не `../../../src/lib/urls`. Файлы вне `src/` импортируются по относительным путям. Конфигурации и служебные скрипты, исполняемые непосредственно Node.js без поддержки алиаса, используют относительные пути.

Если проект использует переменные окружения, `.env.example` служит их единственным перечнем. Каждая новая переменная появляется там с назначением и допустимым примером значения в том же изменении, где код начинает её читать. Реальные значения и секреты в Git не попадают. Неиспользуемые переменные удаляются.

Переменные, встроенные при сборке в HTML и клиентский код, считаются публичными и не содержат секретов. Ссылки и пути к ресурсам учитывают базовый путь размещения на GitHub Pages по [дизайн-системе](./design-system.md).

## Git: сообщения коммитов

Формат: `<тип>(<scope>): <краткое описание на русском>`. `scope` необязателен; например, `articles`, `glossary`, `audio`, `charts`, `search`, `ui`, `deploy`.

| Тип | Когда использовать |
| --- | --- |
| `feat` | Новая функциональность |
| `fix` | Исправление ошибки |
| `refactor` | Изменение устройства без изменения поведения |
| `docs` | Статьи и документация |
| `chore` | Инфраструктура, зависимости и конфигурация |
| `test` | Тесты |
| `style` | Форматирование без изменения логики |

Тема без точки, не длиннее 72 символов. Тело добавляется для причины или важного контекста, строки в нём — до 90 символов. Один логический коммит содержит одно изменение. Трейлеры об использованных инструментах, включая `Co-Authored-By`, не пишутся.
