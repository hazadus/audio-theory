# Спецификация проекта

Документ фиксирует согласованные требования. Замысел и предложения для обсуждения находятся в [idea.md](idea.md), темы — в [topics.md](topics.md), варианты технологий — в [techstack.md](techstack.md), открытые вопросы — в [questions.md](questions.md).

Общие соглашения о коде, языке, конфигурации и сообщениях коммитов собраны в [styleguide.md](styleguide.md).

## Назначение и название

- Сайт предназначен прежде всего для личного изучения теории аудио; материалы также могут читать друзья пользователя.
- Рабочее название — «Теория аудио». Название не принципиально и может быть изменено.

## Сайт

- Статический сайт со статьями и визуализациями по теории аудио и цифровой обработке звука.
- Статический генератор — Astro. Страницы создаются при сборке; опубликованный сайт работает без серверной части.
- Удобная вёрстка для десктопа и смартфонов.
- Переключение темы оформления между светлой, тёмной и автоматической. В автоматическом режиме тема следует системным настройкам пользователя.
- Автоматический деплой на GitHub Pages.
- Адреса статей — английские, по названию понятия, например `/sampling/` и `/buffer-size/`.
- Репозиторий публичный; предложения тем и исправлений принимаются через GitHub Issues. Ссылка на репозиторий подписывается «GitHub».

## Первый выпуск

- В первый выпуск входит полный набор согласованных функций сайта: главная, список материалов с фильтрами и сортировкой, страницы статей, глоссарий, поиск, страницы «О проекте» и 404, темы оформления и автоматический деплой на GitHub Pages.
- Стартовый контент — четыре статьи: «Звуковая волна и аналоговый аудиосигнал»; «Дискретизация: отсчёты, период и частота дискретизации»; «АЦП и ЦАП»; «Аудиоданные в программах: представление отсчётов, каналы, кадры и буферы». Распределение тем описано в [topics.md](topics.md#статьи-первого-выпуска).
- Первый выпуск включает один интерактивный пример в статье о дискретизации. За основу берётся блок «Отсчёты синусоиды при разной частоте дискретизации» из [макета статьи](design/3-article.html): график, параметры, легенда, состояния и мобильный вариант с уточнениями [дизайн-системы](design-system.md#визуализации-и-аудио). Согласованное прослушивание восстановленного сигнала дополняет график; его реализация следует правилам аудио из дизайн-системы.
- Скилл подготовки и дополнения материалов для Codex и Claude Code входит в первый выпуск; первые статьи создаются с его помощью.
- Примеры C++/JUCE не входят в обязательный объём первого выпуска; они добавляются по мере необходимости.

## Команды разработки

- В корне проекта настраивается `justfile` по аналогии с `~/Projects/table/justfile`, чтобы привычные команды сохраняли названия и назначение при переключении между проектами.
- Команды: `dev`, `fmt`, `lint`, `typecheck`, `test`, `test-e2e`, `test-production`, `screenshots`, `build`. Их назначение описано в [styleguide.md](styleguide.md#команды-разработки).
- Вызов `just` без аргументов показывает список доступных команд. Комментарии к командам пишутся на русском; внутренние команды адаптируются к стеку этого проекта.

## Страницы и навигация

- Главная — тематические группы с карточками статей (вариант 2b из [макета страниц](design/4-pages.html)).
- Исходные группы: «Основы звука», «Цифровой сигнал», «АЦП и ЦАП», «Аудиоданные в программах». Агент может предложить новую группу; её добавление согласовывает автор.
- «Все материалы» — отдельная страница со списком статей, фильтрами по темам и сортировкой по дате обновления, названию или теме. Фильтр и сортировка сохраняются в URL.
- Глоссарий — отдельная страница; определения для него и подсказок терминов берутся из единого источника.
- Также предусмотрены страницы статьи, «О проекте» и 404.
- Статьи связываются предварительными знаниями, перекрёстными ссылками и связанными темами; глобальной навигации «предыдущая / следующая статья» нет.

## Дизайн

- Визуальный характер сайта определяет дизайнер.
- Компоновку страницы статьи и оформление её содержимого предлагает дизайнер с учётом требований к материалам и адаптации для десктопа и смартфонов.
- Принято направление «Лабораторная тетрадь»: Literata для текста и основных заголовков, Golos Text для интерфейса, JetBrains Mono для кода; словесный знак «Теория аудио», иконки Lucide.
- На странице статьи под шапкой показывается индикатор прогресса чтения высотой 2 px.
- Правила реализации UI и уточнения к макетам собраны в [design-system.md](design-system.md).

## Материалы

- Все материалы пишутся на русском языке.
- Единый формат исходников статей — MDX: текст пишется в Markdown, визуализации и учебные блоки подключаются готовыми компонентами. HTML страниц создаётся при сборке.
- Блоки кода с указанным языком получают подсветку синтаксиса через встроенный в Astro Shiki при сборке. Цвета используют токены дизайн-системы и следуют светлой, тёмной и автоматической теме; подсветка работает без JavaScript в браузере.
- При первом упоминании основного понятия или термина в каждой статье приводится его английское название в скобках после русского: например, «частота дискретизации (sample rate)» или «аналого-цифровой преобразователь (analog-to-digital converter, ADC)». При последующих упоминаниях повторять английское название не обязательно.
- Основной формат — самостоятельные статьи. Последовательное прохождение курса не требуется.
- По умолчанию объяснения начинаются с основ. Пользователь может уточнить для агента нужный уровень конкретного материала.
- Интерактивные элементы добавляются там, где действительно помогают лучше понять материал. Они не обязательны для каждой статьи.
- Одна статья может раскрывать несколько связанных тем. Запрос новой темы не означает обязательного создания отдельной статьи.
- Обязательные элементы статьи: заголовок с названием понятия, подзаголовок-вопрос, метаданные (дата обновления, время чтения, теги тем), источники и связанные темы. Остальная структура зависит от объяснения.
- Дата обновления — дата последнего коммита файла статьи в Git.
- При локальном просмотре новой статьи без коммита вместо даты показывается «Черновик».
- Оценка времени чтения: число слов текста / 180 слов в минуту, округление вверх, минимум 1 минута. Листинги кода и математическая разметка не учитываются; для сложной статьи автор может задать ручную поправку.
- Числовые ограничения из руководства дизайнера (например, 1–3 тега, до 4 врезок, до 25 строк кода) — рекомендации, а не жёсткие ограничения.
- Синтетические аудиопримеры создаются в браузере через Web Audio; аудиофайлы используются для записей. Звук запускается действием пользователя.

## Ссылки между материалами

- Статьи содержат перекрёстные ссылки на связанные материалы и объяснения необходимых понятий внутри сайта.
- Если нужного материала на сайте нет, ссылка ведёт на соответствующую статью Википедии.
- Внутренняя ссылка может вести прямо на раздел статьи с нужным понятием.

## Поиск

- Полнотекстовый поиск по текстам статей, включая английские названия понятий и терминов.
- Поисковый движок — Pagefind. Индекс создаётся из готовых HTML-страниц при каждой сборке и публикуется вместе с сайтом.
- До полной реализации поискового попапа проверяется поиск по первым статьям: русский текст и словоформы, английские термины на русскоязычных страницах и переходы к разделам.
- Поиск открывается в попапе с полем запроса и результатами.
- Глобальный поиск по страницам сайта открывается с любой страницы горячей клавишей `/`; фокус сразу переходит в поле поискового запроса. При вводе текста в поле ввода или редактируемой области эта горячая клавиша не срабатывает.
- Стрелки `↑` и `↓` перемещают выделение по результатам поиска; выбранный результат визуально выделяется. Клавиша `Enter` открывает выбранный результат.
- Поиск работает в браузере без серверной части и совместим со статическим размещением на GitHub Pages.

## Поддерживаемые браузеры

- Поддерживаются актуальные стабильные Chrome и Firefox на компьютерах, Safari на macOS и iOS, Chrome на Android.
- Приоритетные браузеры для автора — Safari на macOS и iOS. Основные сценарии чтения, поиска, навигации, переключения темы и интерактивного примера со звуком проверяются в них в первую очередь.

## Работа агента

- Скилл для Codex и Claude Code запускает создание или дополнение материалов на указанную пользователем тему.
- Скиллы Codex и Claude Code используют один общий набор правил подготовки статей, хранящийся в репозитории. Правила не дублируются для каждого агента; конкретные пути и способ подключения определяются в плане реализации.
- Перед написанием агент изучает существующие статьи и связанные темы.
- Если запрошенную тему лучше раскрыть внутри существующей статьи, агент дополняет эту статью.
- Новая статья создаётся, когда теме подходит самостоятельное изложение.
- Если тема уже раскрыта, агент дорабатывает материал только там, где это необходимо, избегая дублирования.
- При подготовке материала агент соблюдает требования к языку и уровню объяснений и учитывает уточнения пользователя.
- После написания или дополнения текста агент проверяет его по [каталогу избитых LLM-тропов tropes.md](https://tropes.fyi/tropes-md) и исправляет найденные шаблонные обороты, повторы и другие перечисленные в каталоге приёмы. Проверка учитывает их русскоязычные аналоги; правки должны сохранять техническую точность и понятность объяснений. Агент завершает эту проверку до передачи материала пользователю на личную проверку.

## Проверка и публикация

- Агент готовит новую статью или изменения существующей локально; пользователь читает материал на локально запущенном сайте.
- Пользователь задаёт уточняющие вопросы и просит доработки. Агент дорабатывает материал, пока объяснения не станут понятны пользователю и статья не будет его устраивать.
- После одобрения пользователем выполняются коммит и пуш в основную ветку. PR для этого процесса не требуется; непроверенные изменения материалов не включаются в публикуемый коммит.
- Пуш в основную ветку запускает автоматическую сборку и деплой на GitHub Pages. Один процесс применяется к новым статьям и доработкам опубликованных материалов.
- Перед деплоем в CI обязательны проверка линтером, проверка типов, тесты, сборка сайта и поискового индекса, проверка метаданных, внутренних ссылок и якорей, а также основные браузерные сценарии. Ошибка любой обязательной проверки останавливает деплой.
- Соответствие макетам и работа в настоящем Safari на Mac и iPhone проверяются вручную до публикации, включая интерактивный пример и звук. Личная проверка контента остаётся обязательной частью процесса.
