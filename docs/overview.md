# Обзор устройства

Короткие описания того, как работают отдельные части сайта. Требования и контракты находятся в [спецификации](spec.md), пути — в [структуре проекта](structure.md), команды — в [README](../README.md). Новые обзорные описания добавляются в этот файл отдельными разделами.

## Общие правила подготовки материалов

`docs/authoring/` содержит [правила](authoring/rules.md), [чеклист](authoring/checklist.md), пополняемый [список источников](authoring/sources.md), [шаблон MDX](authoring/article-template.mdx) и [шаблон записи журнала](authoring/update-template.md). После новой статьи или существенного дополнения правила требуют подготовить запись журнала обновлений (`new` или `updated`, опечатки не записываются): её показывают автору вместе с материалом и включают в тот же коммит после одобрения, неверная цель ссылки останавливает сборку. Те же правила описывают сопровождение треков: при создании или дополнении статьи агент читает `src/content/tracks/`, предлагает автору изменение состава или пояснений (новая статья в маршрут сама не попадает), сохраняет постоянные `slug` и `id`, а создание и содержательное изменение трека сопровождает собственной записью журнала с целью `track`; правка статьи без изменения маршрута и опечатки записи о треке не требуют. Состав и запись показывают автору на локальном сайте и включают в тот же коммит после одобрения. Все шесть скиллов `commit`, `execute`, `issue` в `.agents/skills/` и `.claude/skills/` читают правила и чеклист при работе с материалами. Редакционные требования хранятся в общих документах, авторское одобрение и ограничения коммита/публикации сохраняются в процессах. Тонкие точки входа [Codex](../.agents/skills/write-article/SKILL.md) и [Claude Code](../.claude/skills/write-article/SKILL.md) читают те же общие документы. `execute` и `issue` вызывают соответствующий `write-article` для подготовки материалов с темой, уровнем и ограничениями пользователя. Самостоятельный вызов заканчивается передачей на авторскую проверку; при вложенном вызове приёмка, отметка задачи, коммит и публикация остаются в исходном процессе. Формат вызова описан в [README](../README.md#скиллы-агентов).

Шаблон находится вне публичной коллекции. Проверка из корня использует уже существующие переменные только локально:

```sh
ARTICLES_DIR=./docs/authoring ALLOW_DRAFT_ARTICLES=1 npm run build -- --outDir .e2e/authoring-template --base /audio-theory/
ARTICLES_DIR=./docs/authoring just dev --host 127.0.0.1 --port 4321
```

Открывать `<origin>/audio-theory/authoring-template/`, взяв фактический origin из вывода Astro. Результат прохождения чеклиста записан в [проверке шаблона](authoring/template-review.md). Обычная сборка без подмены `ARTICLES_DIR` не содержит шаблон; служебный артефакт `.e2e/authoring-template/` не публикуется. Сборку с подменённой коллекцией, обычную сборку и `just typecheck` выполнять последовательно; перед dev-просмотром после них заново запустить собственный сервер с нужным `ARTICLES_DIR`, чтобы кеш коллекции соответствовал каталогу. Управление сервером и авторская проверка описаны в скиллах.

## Браузерные проверки

`just test-e2e` собирает сайт последовательно в `.e2e/root/` и `.e2e/prefixed/`, проверяя ссылки, ресурсы и индекс в обеих сборках, затем служебную сборку с конфигурацией `tests/fixtures/mdx/astro.config.mjs` в `.e2e/fixture/` (под `/audio-theory/`, порт 4393). `playwright.config.ts` запускает обязательный сокращённый набор; CI использует ту же команду `npm run test:e2e:ci`. Полная диагностика `just test-e2e-full` вызывает `npm run test:e2e`, который дополнительно собирает журнал обновлений в `.e2e/updates/` (`scripts/build-updates-fixture.mjs`); обязательному набору эта сборка не нужна.

| Проект | Сценарии | Назначение |
| --- | --- | --- |
| `prefixed-webkit` | `@ci` | Ключевые сценарии всех страниц, настоящий поиск, темы, клавиатура, визуализации и звук под адресом GitHub Pages в приоритетном движке Safari |
| `prefixed-chromium`, `prefixed-firefox` | `@ci-cross-browser` | Переключение темы, клавиатура и фокус меню и поиска, синхронность параметров визуализаций |
| `root-chromium` | `@placement` | Ресурсы, навигация, query и история, настоящий индекс и переходы к якорям при размещении в корне |
| `fixture-webkit` | `@sampling` или `@margin-notes` с `@ci` | Эксперимент дискретизации и заметки: параметры, звук, сброс, уход, недоступность API; сетка, печать, увеличение текста и клавиатура без JS |
| `fixture-chromium`, `fixture-firefox` | `@sampling` или `@margin-notes` с `@ci-cross-browser` | Синхронность параметров и графика; сетка заметок в обеих темах |

Обязательный набор содержит 86 проверок вместо 176: 47 в `prefixed-webkit`, по 8 в `prefixed-chromium` и `prefixed-firefox`, 10 в `root-chromium`, 9 в `fixture-webkit` и по две в остальных служебных проектах. CI перед сборками запускает `node scripts/check-e2e-budget.mjs`: он считает тесты через Playwright `--list` и останавливает проверку, если их больше 88. Лимит сохраняет сокращение минимум вдвое относительно прежнего набора и оставляет небольшой запас для новых критичных сценариев.

Новый сценарий автоматически входит только в полный диагностический набор. Метку `@ci` добавляют для ключевого пути или существенной регрессии, `@ci-cross-browser` — для выбранных проверок зависимости от браузерных API, фокуса, клавиатуры или вёрстки; такой сценарий также помечают `@ci`, чтобы он выполнялся в WebKit. Метка `@cross-browser` обозначает браузерную зависимость остальных сценариев, но сама по себе не включает повторы в CI. `@placement` сохраняется для зависимости от базового пути. При достижении лимита пересматривают состав обязательного набора, а не увеличивают лимит автоматически. Детальные варианты данных, ошибок и интерфейсных состояний остаются в полном прогоне; чистая логика также проверяется всеми unit-тестами.

Сценарии `@sampling` и `@margin-notes` идут только на служебной сборке: их образцы находятся в `tests/fixtures/mdx/`, а публичные сборки не содержат служебных страниц; основные проекты исключают их через `grepInvert`. Все сценарии также доступны в полном диагностическом прогоне.

`just test-e2e-full` использует `playwright.full.config.ts` и запускает прежнюю полную матрицу: все сценарии в Chromium, Firefox и WebKit в корне и под префиксом. Она нужна для диагностики и проверки изменений самой матрицы. Обычная обязательная проверка критичных путей — `just test-e2e`. WebKit не заменяет ручную проверку настоящего Safari на Mac и iPhone.

## Тема оформления

Режимы: светлая, тёмная и авто. Светлая и тёмная ставят `data-theme` на `<html>`, авто убирает атрибут, и `color-scheme` следует системе без перезагрузки (токены — `src/styles/tokens.css`). Выбор хранится в `localStorage` под ключом `theme`; пустое или неверное значение означает авто.

Синхронный скрипт `themeInitScript` встроен в `<head>` до CSS и восстанавливает выбор до первой отрисовки. Кнопка `ThemeToggle` по кругу меняет режим (светлая → тёмная → авто), скрыта без JS и обновляется при изменении выбора в другой вкладке. Режим в окне хранится в самой кнопке, поэтому отказ чтения или записи `localStorage` (`try/catch`) не ломает переключение, а выбор не сохранится. Без JS действует системная тема.

Логика и тесты — `src/lib/theme.ts`, `tests/unit/theme.test.ts`, `tests/e2e/home.spec.ts`. Кнопка стоит в шапке на широком экране; в компактном меню те же состояния выбирает группа из трёх переключателей (`ThemeChoice`). Оба контрола работают через общий `theme-controller.ts` и всегда показывают одинаковый режим.

## Шапка, подвал и меню

Все страницы собираются в `src/layouts/BaseLayout.astro`: скрипт темы, ссылка «Перейти к содержимому» (ведёт на `main#content`, видна при фокусе), шапка, содержимое страницы, подвал. Страница выводит основное содержимое в `<main id="content">`.

Пункты навигации перечислены в `src/lib/navigation.ts`. Пункт добавляется вместе со страницей, на которую ведёт: ссылок на несуществующие маршруты нет. Активный пункт получает `aria-current="page"`, линию и вес 600; `activeUnder` задаёт разделы, где он тоже активен (например, статьи для «Материалов»).

Ширина от 1024 px — полная шапка 64 px с кнопкой темы. Уже — шапка 56 px и кнопка «Меню» с `aria-expanded` и `aria-controls`. Меню не модальное: при открытии фокус переходит внутрь, закрывают Escape, повторное нажатие кнопки, клик вне шапки, уход фокуса из шапки и расширение окна; Escape и кнопка возвращают фокус на кнопку. Без JS кнопки меню и выбора темы скрыты, действует системная тема.

В подвале и в меню «Предложить тему» ведёт к разделу `#propose` страницы «О проекте» (`/about/`), где кнопка «Создать issue» открывает `<repository>/issues/new`. «GitHub» берётся из `siteConfig.repository`. Ссылки подвала: «О проекте», «Обновления», «RSS», «Предложить тему», «GitHub».

Вне `main` шапка и подвал помечены `data-pagefind-ignore`, в индекс поиска они не попадают.

## Время чтения

Время чтения — `max(1, ceil(слова / 180))` по тексту MDX; ручное `readingMinutes` во frontmatter заменяет оценку.

Не считаются frontmatter, блоки и строчный код, формулы, `import`/`export`, выражения `{…}`. Считается видимый текст, включая текст ссылок, таблиц и атрибутов `title`, `question`, `caption` учебных блоков. Слово — последовательность букв и цифр, дефисное слово считается одним, пунктуация не считается.

Расчёт — `src/lib/reading-time.ts`, тесты — `tests/unit/reading-time.test.ts`; контракт описан в [спецификации](spec.md#данные-материалов-и-учебные-компоненты).

## Якоря и оглавление

Английский идентификатор раздела задаётся в конце заголовка: `## Частота Найквиста {#nyquist-frequency}`. Он становится `id` заголовка в HTML и не попадает в его текст, поэтому переименование русского заголовка адрес раздела не меняет. Формат — латиница, цифры и дефисы (`[a-z0-9]` через дефис); повторный якорь, неверный формат и `{#…}` вне конца заголовка останавливают сборку. Заголовок без `{#…}` получает автоматический id по тексту, но стабильные ссылки требуют явного якоря.

Синтаксис `{#…}` обычный MDX считает ошибочным выражением JavaScript, поэтому его разбирает расширение `src/lib/remark-heading-anchors.mjs`, подключённое в `astro.config.mjs` и в разбор для времени чтения. Остальные выражения `{…}` в заголовках работают как прежде.

Набор заголовков берётся один раз из `render()` Astro и идёт и в HTML, и в оглавление. `getToc` в `src/lib/headings.ts` оставляет H2 и H3 в порядке документа, `assertUniqueAnchors` отвергает повтор id, в том числе явного с автоматическим. Ссылки на разделы пишутся как обычные ссылки MDX `[текст](/slug/#anchor)`: `rehype-site-urls` добавляет базовый путь через `withBase`, якорь сохраняется, а сборка проверяет, что он существует.

## Поисковый индекс и проверка артефакта

После создания HTML интеграция `scripts/build-artifact.mjs` проверяет готовые файлы через `scripts/check-artifact.mjs`, затем строит индекс Pagefind в `<outDir>/pagefind/`. Это происходит при каждом `astro build`, в том числе через `just build` и с переопределёнными `--base` и `--outDir`. В HTML проверяются `href`, `src`, `poster`, ресурсы `object`, встроенные стили и `<style>`; в CSS — `url(...)`. Ссылки разрешаются относительно страницы или CSS-файла, query не меняет целевой файл, HTML-якорь должен существовать. Адреса того же origin считаются внутренними и должны учитывать `base`; внешние адреса и схемы вроде `mailto:` и `data:` не требуют сети. Метаданные, источники, ссылки и нумерацию блоков проверяет отдельный шаг до генерации страниц ([ниже](#проверка-содержимого-статьи)); оба шага выполняются в одной сборке.

Индексируется `<main data-pagefind-body>` начальной страницы и статей; заголовок страницы — её `<h1>`, а заголовки с `id` (H2/H3 с `{#anchor}`) становятся разделами с адресом `<страница>#<якорь>`. Через `data-pagefind-ignore` исключены шапка, подвал, ссылка перехода, хлебные крошки, оглавление, дата и время чтения, блоки «Что нужно знать заранее», «Связанные темы» и заметки «Подробнее», кнопка и всплывающее определение термина (`Term.astro`), а также визуальная копия и TeX-аннотация формул KaTeX (`src/lib/rehype-pagefind.mjs`): из формулы в индекс попадает только MathML. Определения терминов в текст статей не индексируются: они индексируются на странице глоссария `/glossary/` (`<main data-pagefind-body>`; указатель букв, ссылки-якоря «#» и подвал исключены). Записи глоссария — не заголовки, поэтому отдельных разделов с адресом `/glossary/#термин` в выдаче нет: результат ведёт на страницу глоссария. Служебные маршруты из `tests/fixtures/` обычная сборка не создаёт. Pagefind для слова без совпадений откатывается на короткий префикс («космос» находит слово «ко», «Shannon» — символ «s» из формул), поэтому выдачу фильтрует `searchIndex` из `src/lib/search.ts`: слово статьи подходит, если делит с токеном запроса общее начало не короче четырёх символов (для коротких токенов — всего токена), «ё» и «е» не различаются. Позиции найденных слов берутся из `words` и `locations` Pagefind. Модуль использует диалог поиска; `tests/e2e/search.spec.ts` собирает его esbuild и проверяет на настоящем индексе русские словоформы, английские термины, пустую выдачу для посторонних запросов и переходы к якорям под обоими базовыми путями. Dev-сервер индекс не строит. Для ручной проверки соберите сайт и откройте preview:

```sh
just build
npm run preview -- --ignore-lock --host 127.0.0.1 --port 4322
```

Откройте адрес из вывода Astro с фактическим базовым путём, например `http://127.0.0.1:4322/audio-theory/`. В консоли браузера на этой странице:

```js
const pagefind = await import('/audio-theory/pagefind/pagefind.js');
const results = await pagefind.search('цифровой обработке');
const pages = await Promise.all(results.results.map((result) => result.data()));
console.table(pages.map(({ url, meta }) => ({ url, title: meta.title })));
```

Ожидается одна страница «Теория аудио» с адресом `/audio-theory/`; запрос `GitHub` не даёт результатов, поскольку навигация исключена. При сборке с `--base /` используйте импорт `/pagefind/pagefind.js` и запускайте preview с `--base /`. После проверки остановите свой foreground preview через `Ctrl-C`.

Unit-тесты проверяют отсутствующие страницы, якоря и ресурсы, query, относительные и внешние адреса и неверный базовый путь. Контрольная сборка со служебной ошибочной ссылкой должна завершиться с ненулевым кодом.

## Диалог поиска

`SearchDialog.astro` выводится в `BaseLayout` на каждой странице и построен на нативном `<dialog>`: `showModal()` даёт модальность, недоступный фон и слой над страницей. Открывают его кнопка `SearchButton.astro` в шапке (на ширине от 1024 px — поле-подсказка «Поиск» с `/`, ниже — иконка), любой элемент с `data-search-open` и клавиша `/`. Правила клавиши — `shouldOpenSearch` в `src/lib/search-dialog.ts`: не срабатывает в `input`, `textarea`, `select`, редактируемой области, с Ctrl/Cmd/Alt, при композиционном вводе и повторе; Shift допустим, потому что на русской раскладке `/` набирается с ним. Фокус сразу переходит в поле; Tab и Shift+Tab замкнуты внутри окна (Safari по умолчанию пропускает кнопки, поэтому переход выполняет скрипт). Закрытие — `Esc`, «Отмена» и нажатие на затемнение (нажатие и отпускание должны прийтись на сам `<dialog>`); фокус возвращается к кнопке, открывшей окно, а при `/` — к элементу, где он был. Пока окно открыто, на `<html>` стоит `data-search-active` и прокрутка страницы отключена. На ширине до 600 px окно занимает весь экран, вместо крестика показана «Отмена». Высота слоя — `--search-viewport-height` (из `visualViewport`, который в iOS уменьшает экранная клавиатура; без значения — `100dvh`), положение — `--search-viewport-top`; значения ставятся при открытии и на `resize`/`scroll` viewport и снимаются при закрытии. Результаты прокручиваются внутри `.body` (`overscroll-behavior: contain`), отступы верхней строки, списка и низа учитывают `env(safe-area-inset-*)`; для этого в `BaseLayout` задан `viewport-fit=cover`, а `--page-gutter` не меньше левого и правого safe-area. Без JS кнопка скрыта, вместо неё в шапке текст «Поиск работает только с JavaScript.». Выдачу и состояния ведёт `initSearchResults` (`src/lib/search-controller.ts`): модуль `pagefind.js` загружается при первом запросе по адресу с базовым путём, запрос идёт через `searchIndex`, каждый найденный раздел становится ссылкой «Статья → Раздел» с фрагментом. Состояния (`data-state` у `[data-search-body]`): пустой запрос (пояснение), загрузка («Ищем…», поле остаётся доступным), результаты («Найдено: N»), «Ничего не нашлось» с подсказкой и ошибка с кнопкой «Повторить» и ссылкой «Все материалы». Текст состояния объявляется через `role="status"`. Ответ запроса принимается, только если он последний: номер запроса сравнивается после ожидания. Пока идёт следующий запрос, прежняя выдача остаётся на месте, а «Ищем…» появляется только из пустого состояния или ошибки и не раньше чем через 150 мс, чтобы список не мигал при наборе. Неудачную загрузку модуля браузер запоминает по адресу, поэтому повтор добавляет `?retry=N`. Фрагмент разбирает `parseExcerpt` (`src/lib/search-view.ts`): остаётся `<mark>`, прочие теги отбрасываются, сущности декодируются, текст вставляется через `textContent`. Клавиатурное управление: поле — `role="combobox"` с `aria-controls`, `aria-expanded` (истина только при результатах) и `aria-activedescendant`; список — `role="listbox"`, каждый результат — ссылка `role="option"` с уникальным `id` (`search-option-N`), `aria-selected` и `tabindex="-1"`, поэтому фокус остаётся в поле, а Tab результаты не обходит. `↓` из состояния без выбора выбирает первый результат, `↑` выбор не создаёт, на границах списка выделение останавливается (`moveSelection`). `Enter` нажимает на выбранную ссылку; без выбора и без результатов он ничего не открывает. Выбранный пункт прокручивается в видимую область (`scrollIntoView({ block: 'nearest' })`) и отмечен плашкой, полосой слева и значком ↵. Выбор сбрасывается при каждом вводе, до прихода ответа нового запроса `Enter` не открывает результат прежней выдачи. Щелчок по результату без модификаторов закрывает окно, фокус не возвращается к кнопке, а остаётся за браузером на цели перехода; при повторном открытии прежний запрос остаётся и выделен. Разметка и размеры повторяют раздел «12. Поиск» макета `docs/design/2-components.html`. Сценарии — `tests/e2e/search-dialog.spec.ts` (оболочка) и `tests/e2e/search-results.spec.ts` (выдача: заглушка `pagefind.js` управляет задержкой и ошибкой, отдельный сценарий идёт по настоящему индексу; там же клавиатурное управление).

## Адреса сайта и базовый путь

`src/site.config.ts` задаёт адрес `https://hazadus.github.io`, базовый путь `/audio-theory/` и репозиторий `https://github.com/hazadus/audio-theory`. Astro берёт `site` и `base` из этой конфигурации. GitHub Pages настроен на публикацию через Actions; процесс описан в [инструкции по CI и деплою](deploy.md).

Страницы и ресурсы используют `withBase` из `src/lib/urls.ts`, например `withBase('/sampling/?mode=demo#nyquist-frequency')`. Функция берёт фактический `import.meta.env.BASE_URL`, сохраняет query и якорь, добавляет префикс один раз. Внешние URL (включая `//…`), схемы `mailto:` и `data:`, ссылки на якорь или query текущей страницы, относительные `./…` и `../…` сохраняются. Строки без начального `/` считаются логическими маршрутами от корня сайта. В MDX обычные ссылки и ресурсы преобразуются при сборке через `rehype-site-urls`; адреса в выражениях и свойствах встроенных компонентов формируются явным вызовом `withBase`.

Проверка размещения в корне без изменения конфигурации:

```sh
npm run build -- --base /
just dev --host 127.0.0.1 --port 4321 --base /
```

Для стандартного префикса используйте `just build` и `just dev`. `dist/` содержит корень публикуемого артефакта: каталог `audio-theory/` внутри него не создаётся. Статический сервер должен размещать содержимое `dist/` по выбранному базовому пути. CSS и импортированные ресурсы получают префикс средствами Astro.

## Проверка MDX и формул

MDX использует официальный `@astrojs/mdx` и обработчик `@astrojs/markdown-remark` с `remark-math` и `rehype-katex`. Строчные формулы записываются как `$T_s = 1/f_s$`, блочные — между отдельными строками `$$`. HTML и MathML создаются при сборке; неверная формула останавливает её. JavaScript для чтения формул не нужен. Временные сборки проверки создаются в `.e2e/mdx-*/` рядом с кешем Astro на одной файловой системе и удаляются после прогона.

На странице с формулами подключается `src/styles/math.css`: CSS и шрифты KaTeX входят в локальные ресурсы сборки; небольшие шрифты могут встраиваться в CSS. Кириллица внутри `\text{}` использует шрифт статьи. Длинные строчные формулы внутри абзацев ограничены шириной абзаца и прокручиваются внутри себя, в том числе при увеличении текста. Лицензия KaTeX сохранена в `public/licenses/katex.txt`.

Проверка корректного MDX в корне и под `/audio-theory/`, ссылок, ошибочной формулы, компонента, MathML, локальных ресурсов и отсутствия проверочных материалов в публикуемой сборке:

```sh
npm run test:mdx
```

Проверочные исходники находятся в `tests/fixtures/mdx/`, отдельно от статей и обычных маршрутов. Проверка собирает и обычный сайт, поэтому до коммита новой статьи её запускают как `ALLOW_DRAFT_ARTICLES=1 npm run test:mdx`. Сборки проверки создаются во временном каталоге и удаляются после выполнения. Для просмотра служебного материала:

```sh
just dev --host 127.0.0.1 --port 4321 --config tests/fixtures/mdx/astro.config.mjs
```

К адресу сервера с фактическим базовым путём добавьте `__test/mdx/`, например `http://127.0.0.1:4321/audio-theory/__test/mdx/`. Эта страница доступна только с тестовой конфигурацией; обычный `just build` её не публикует. Разделы страницы показывают `SelfCheck`, `Term` с подсказками и пять типов `Callout` (для ошибки — с блоками `CalloutCase`) три `Equation` (с номером и обозначениями, длинная, без номера), `Figure`, `SamplingDemo` (визуализация 2), `DataTable` и блоки кода (JavaScript, C++). Отдельный служебный маршрут `__test/margin-notes/` показывает `MarginNote` с одной, двумя и тремя ссылками, соседними заметками и широким рисунком в настоящем `ArticleLayout` с оглавлением.

### Коллекция журнала обновлений

Коллекция `updates` объявлена в `src/content.config.ts`: одна запись — `src/content/updates/<id>.json`, схема — `src/lib/updates.ts`. Публичный каталог содержит по одной записи «Новое» (`<slug>-published.json`) для каждой статьи с датой первого коммита её файла по `Europe/Moscow`; порядок записей одного дня задал автор. Для проверки статей используются `tests/fixtures/updates/`, явно подключаемые через `UPDATES_DIR` из `.env.example`; обычная сборка их не читает. Эти записи относятся к служебным статьям `tests/fixtures/articles/valid/`, поэтому для их сборки также задаётся `ARTICLES_DIR`.

`loadUpdates` (`src/lib/update-list.ts`) загружает коллекцию и проверяет её при построении маршрутов статей. Неверные поля, календарные и будущие даты (день в Москве), повторные id, несовпадение имени файла и id, повторный порядок внутри дня, несколько записей «Новое» одного материала и дополнение раньше записи публикации останавливают сборку. Схема требует описание для `new`, допускает 0–4 пункта публикации и требует 1–4 пункта дополнения; текст не содержит HTML или Markdown. Опубликованные id и даты сохраняются при редактуре вручную, как требует [спецификация](spec.md#записи-и-даты).

Общий контракт `internalTarget` из `src/lib/links.ts` допускает `{ article, anchor? }`, `{ glossary }` и `{ track, anchor? }`, исключая внешние адреса. Загрузчик сверяет статьи, треки, термины и якоря; `getArticleAnchors` использует тот же разбор учебных блоков, что проверка статей, и заголовки из `render()`, включая стандартные id визуализаций. `resolveTarget` строит адреса через `withBase`, для термина — `/glossary/#<id>`, для трека — `/tracks/<slug>/#stage-<id>` (якорь необязателен). Прежние цели статей и внешних ссылок сохраняют свой контракт.

Загрузчик возвращает записи по убыванию даты и `order`, добавляя актуальные название и адрес материала, адреса пунктов и метаданные: «Статья», группа и время чтения либо «Трек», число этапов и элементов. Эти метаданные не дублируются в JSON. Страницы журнала описаны [ниже](#страница-обновления); RSS описан [ниже](#rss-лента-обновлений); главная, статья и подвал используют загрузчик, как описано в [разделе о связях журнала](#связи-журнала-с-главной-статьёй-и-подвалом). Unit-проверки схемы, дат, связей, сортировки и адресов находятся в `tests/unit/updates.test.ts`.

### Страница «Обновления»

`src/pages/updates/index.astro` и `src/pages/updates/[year].astro` выводят один компонент `UpdatesList.astro` по макету `docs/design/9-updates.html`: заголовок, вводный абзац, фильтр типа, секции дат и строка «Ранее:». `/updates/` показывает последний непустой год журнала (максимум по `date`, а не год сборки) и указывает его под заголовком; `/updates/YYYY/` создаётся для каждого непустого года, включая последний, с заголовком «Обновления за YYYY год» и ссылкой «Последние обновления». Пустой или чужой год даёт 404. Пустой журнал показывает «Обновлений пока нет» без фильтра, года и архива. Логика годов, секций дат, строки метаданных и параметра `type` лежит в `src/lib/update-view.ts` (unit-тесты `tests/unit/update-view.test.ts`).

Дата — `<h2 id="YYYY-MM-DD">` с `<time>`: на ширине от 600 px в колонке 200 px слева, на узком экране над записями. Запись — `<article id="update-<id>">`: метка «Новое» (заливка) или «Дополнено» (рамка), название статьи ссылкой, для «Новое» краткое описание, пункты ссылками на изменённые места (весь текст пункта — ссылка) и строка «Статья · группа · время чтения». Названия и длинные слова переносятся; ширина при 320 px и увеличенном тексте не требует горизонтальной прокрутки.

Без JS видны все записи года, фильтр скрыт, `?type=` не действует. `initUpdates` (`src/lib/updates-controller.ts`) показывает фильтр «Все · Новое · Дополнено», скрывает записи и пустые секции через `hidden` и пишет выбор в `?type=new` или `?type=updated` через `pushState`: «Назад» и «Вперёд» восстанавливают состояние, остальные параметры и якорь сохраняются, неизвестное значение считается «Все» и убирается при следующем изменении. Если ничего не подошло, показывается «Нет обновлений этого типа за <год>». Якорь на скрытую фильтром запись или дату переключает «Все» с `replaceState` и затем прокручивает к цели. Ссылки на другие годы не несут `?type=`, поэтому фильтр при переходе сбрасывается. Страницы журнала не размечены `data-pagefind-body`, а `<main>` имеет `data-pagefind-ignore`: в индекс они не попадают, это проверяет `npm run test:articles` (число фрагментов Pagefind). Ссылка «RSS-лента» появится вместе с лентой (задача 59): без файла `/updates/feed.xml` проверка артефакта останавливает сборку на битой ссылке.

Сценарии `tests/e2e/updates.spec.ts` (метка `@updates`) не зависят от публичного журнала и идут на служебной сборке: `scripts/build-updates-fixture.mjs` собирает сайт с `ARTICLES_DIR=tests/fixtures/articles/valid` и `UPDATES_DIR=tests/fixtures/updates-page` в `.e2e/updates/`, а `playwright.full.config.ts` поднимает для неё preview на порту 4394. Метки `@ci` у сценариев нет (обязательный набор уже на лимите 88), поэтому они входят в `just test-e2e-full`, как и в `npx playwright test --config playwright.full.config.ts --project 'updates-*'`. Посмотреть служебный журнал в браузере: `ARTICLES_DIR=./tests/fixtures/articles/valid UPDATES_DIR=./tests/fixtures/updates-page just dev`, затем `/audio-theory/updates/`.

### RSS-лента обновлений

`src/pages/updates/feed.xml.ts` при сборке отдаёт `/updates/feed.xml` (RSS 2.0) из `loadUpdates`; формирование XML — чистая функция `buildFeed` в `src/lib/updates-feed.ts`. Канал: «Теория аудио — обновления», `link` на `/updates/`, вводный абзац журнала, `language` `ru`, `atom:link rel="self"`; пустой журнал даёт канал без элементов. Одна запись журнала — один `item` в порядке журнала (дата, затем `order` по убыванию), без ограничения числа. «Новое»: `link` — статья или трек, `description` — `summary` и «Читать статью» либо «Открыть трек». «Дополнено»: `link` — `/updates/YYYY/#update-<id>`, `description` — ссылка на материал и список пунктов со ссылками; HTML в `description` экранирован для XML. `guid` — `audio-theory-update:<id>` (`isPermaLink="false"`), `pubDate` — дата записи, 00:00:00 `+0300`; дата сборки в ленту не входит, поэтому прежние `guid` и даты не меняются при добавлении записей. Адреса абсолютные: `site` из конфигурации плюс фактический `base` (ровно один раз).

Ссылка `<link rel="alternate" type="application/rss+xml">` стоит в `<head>` `BaseLayout.astro`, ссылка «RSS-лента» — в шапке страниц `/updates/` и `/updates/YYYY/`; ссылка «RSS» есть и в подвале ([ниже](#связи-журнала-с-главной-статьёй-и-подвалом)). Лента попадает в `dist/` и артефакт GitHub Pages, в индекс Pagefind не входит. Unit-тесты — `tests/unit/updates-feed.test.ts`, браузерная проверка ленты на служебной сборке — сценарий `@updates` в `tests/e2e/updates.spec.ts`. Просмотр служебной ленты: после `node scripts/build-updates-fixture.mjs` файл лежит в `.e2e/updates/updates/feed.xml`; корректность XML проверяет `xmllint --noout`.

### Связи журнала с главной, статьёй и подвалом

Даты статьи считает `resolveArticleDates` (`src/lib/article-dates.ts`) из записей журнала и Git. «Опубликовано» — дата записи «Новое», а до её появления дата первого коммита файла с учётом переименований (`getPublishedDate` в `src/lib/git-date.ts`, `git log --follow`); новый файл без истории — «Черновик». «Дополнено» — дата последней записи «Дополнено», ссылкой на `/updates/YYYY/#update-<id>`; без дополнений метки нет. Git-дата правок под заголовком не выводится и порядок не меняет. Дата карточек главной, списка «Все материалы» и сортировки (`HomeArticle.updated`, считает `loadArticleList`) — последнее дополнение, а без дополнений публикация. Публичный журнал содержит только записи «Новое», поэтому «Опубликовано» берётся из них, а ссылка «Дополнено» видна пока на служебной сборке.

`RecentUpdates.astro` на главной между визуализациями и тематическими группами выводит «Недавно на сайте»: три первые записи журнала (`recentUpdates`, `src/lib/recent-updates.ts`) — дата, метка «Новое»/«Дополнено» и текст-ссылка на запись архива. Текст — название статьи, для «Дополнено» через двоеточие добавлен первый пункт. Рядом ссылка «Все обновления» на `/updates/`. Пустой журнал блок не выводит; блок исключён из поиска (`data-pagefind-ignore`). На ширине до 600 px дата с меткой стоят в первой строке, ссылка занимает вторую. В подвале `SiteFooter.astro` добавлены «Обновления» (`/updates/`) и «RSS» (`/updates/feed.xml`); шапка не менялась. Сценарии — `@updates` в `tests/e2e/updates.spec.ts`, unit-тесты — `tests/unit/article-dates.test.ts`, `tests/unit/recent-updates.test.ts`.

### Главная

`src/pages/index.astro` по варианту 2b макета `docs/design/4-pages.html` выводит название, назначение, кнопку «Найти статью или термин» (`data-search-open`, без JS скрыта), раздел визуализаций ([ниже](#визуализации-на-главной)) и тематические группы. Состав групп считает `buildHomeGroups` (`src/lib/home.ts`): порядок групп — как в `src/data/topics.ts`, внутри группы статьи идут по дате обновления по убыванию, при равных днях — по русскому названию, «Черновик» без даты считается самым свежим. Карточек не больше четырёх (`homeCardLimit`), «Все N» считает все статьи группы; пустые группы скрыты, группа с одной статьёй остаётся. ### Ссылки на разделы

Плагин `src/lib/rehype-heading-links.mjs` при сборке добавляет в заголовки H2–H4 с `id` ссылку `<a class="heading-link" href="#id" aria-label="Ссылка на раздел «…»">`. Знак `#` рисует CSS (`::before`), поэтому он не попадает в текст оглавления и индекс поиска. Ссылка видна при наведении на заголовок и при клавиатурном фокусе, на устройствах без hover — приглушённо. Без JS это обычная ссылка на якорь. Заголовок без явного `{#…}` получает `id` позже, чем отрабатывает плагин, и ссылки не получает.

`src/lib/heading-links-controller.ts` по нажатию копирует адрес через `navigator.clipboard.writeText`: домен, базовый путь и якорь, без query (`headingLinkUrl` в `src/lib/heading-links.ts`, тесты — `tests/unit/heading-links.test.ts`). Переход по якорю выполняет браузер независимо от результата копирования. Область `role="status"` в `ArticleLayout.astro` на 2,5 с показывает «Адрес раздела скопирован» только после успешной записи; при отказе или отсутствии Clipboard API — «Не удалось скопировать адрес. Он доступен в адресной строке».

### Статичный график равной громкости

Статья `/equal-loudness/` использует `EqualLoudnessChart` внутри `Figure`. Коэффициенты 29 частот 20–12 500 Гц из таблицы 1 ISO 226:2023 и ссылка на источник хранятся в `src/data/equal-loudness.json`. `src/lib/equal-loudness.ts` вычисляет только три кривые: 20, 40 и 80 фон. Компонент строит SVG при сборке с логарифмической осью частоты и разными типами линий; соседние точки соединяются отрезками, без экстраполяции. Подписи осей, деления и HTML-легенда имеют постоянный размер 14 px; область кривых меняется по ширине отдельно от текста. Таблица в статье берёт значения из того же расчёта и округляет до 0,1 дБ SPL. Основной график, формула, легенда и самопроверка работают без JavaScript; звука и регуляторов нет. Контроль редакции стандарта, равенство фонов и SPL на 1 кГц и независимо рассчитанные значения проверяет `tests/unit/equal-loudness.test.ts`.

### Модель эксперимента дискретизации

Расчёты эксперимента из статьи о дискретизации — чистые функции `src/lib/sampling.ts` без DOM и Web Audio; статичный SVG при сборке, интерактивный график и звук используют одну модель. Параметры: сигнал 1 кГц, интервал 0–3 мс, начальная частота дискретизации 8 000 Гц. `samplingExperiment(sampleRate)` возвращает период дискретизации, частоту Найквиста, положение сигнала относительно неё (`below`, `nyquist`, `above`), число отсчётов на период тона, отсчёты, признак нулевых отсчётов и результат восстановления.

Исходный сигнал — $x(t) = \sin(2\pi f t)$: амплитуда 1, начальная фаза 0. Отсчёты $x[n] = \sin(2\pi f n / f_s)$ берутся в моменты $n T_s$ от 0 до конца интервала включительно; фаза $f n / f_s$ сокращается до доли оборота до вызова синуса, а значения у нуля приводятся к точному 0.

Восстановление — идеальное, по бесконечной последовательности отсчётов фильтром нижних частот с границей $f_s / 2$. Для синусоиды его результат — единственная синусоида ниже $f_s / 2$ с теми же отсчётами: частота сигнала переносится в полосу $[-f_s/2, f_s/2]$ вычитанием ближайшего кратного $f_s$, $f' = f - \mathrm{round}(f / f_s) \cdot f_s$. Результат $y(t) = \mathrm{sign}(f') \sin(2\pi |f'| t)$: отрицательная видимая частота означает синусоиду с противоположным знаком, например при $f_s = 1{,}5$ кГц отсчёты совпадают с $-\sin(2\pi \cdot 500\,t)$. Ниже частоты Найквиста результат совпадает с исходным сигналом и между отсчётами.

Если $|f'| = f_s / 2$, восстановление не однозначно: модель возвращает `ambiguous` и не предлагает сигнал. При нулевой фазе такие отсчёты все равны нулю, и с ними совпадает синусоида $f_s / 2$ любой амплитуды, в том числе исходная. В диапазоне 1–16 кГц вырожденных частот две: 2 кГц — граница, отсчёты в нулях синусоиды; 1 кГц — $f' = 0$, отсчёты нулевые, результат однозначен — постоянный ноль (0 Гц).

Упрощения модели: дискретизация мгновенная и точная, без квантования и шума; антиалиасинговый фильтр перед дискретизацией не применяется, чтобы показать наложение; сигнал считается бесконечным, поэтому края показанного интервала не влияют на восстановление; реальный ЦАП с конечным фильтром не моделируется. Частота дискретизации эксперимента не связана с аппаратной частотой `AudioContext`.

`SamplingDemo` (`src/components/SamplingDemo.astro`) принимает `figure` (номер в общей последовательности рисунков) и необязательный `id` (по умолчанию `sampling-demo`). Порядок блоков: метка «Визуализация N» и название, график, легенда, строка состояния, параметры и подпись «Рис. N.» с условиями. При сборке рисуется начальное состояние 8 000 Гц; тексты статуса, подписи, название и описание SVG и саму разметку SVG (`samplingChartSvg`) даёт `src/lib/sampling-view.ts`, поэтому сборка и браузер рисуют график одной функцией.

Параметры (`src/lib/sampling-controls.ts`): ползунок 1 000–16 000 Гц с шагом 100 Гц и риской 2f = 2 000 Гц, кнопки 1,5, 2 и 8 кГц с `aria-pressed`, переключатель «Видимая синусоида» (`role="switch"`) и «Сбросить» — к 8 000 Гц с включённой видимой синусоидой. Ползунок — нативный `input type="range"`: стрелки меняют значение на шаг, `Home`/`End` — к границам, касание дорожки ставит значение; `aria-valuetext` и `<output>` показывают значение с единицей. Контроллер `sampling-demo-controller.ts` при каждом изменении перерисовывает SVG, легенду, статус, подпись и состояние кнопок; объявление в скрытой `aria-live="polite"` области появляется через 0,7 с после последнего изменения, без потока сообщений на каждый шаг ползунка. Видимая синусоида (пунктир и пункт легенды) показывается только при наложении с однозначным результатом; без наложения (выше 2f и ровно на 2 кГц) переключатель неактивен, рядом пояснение «появляется при fₛ < 2f», а выбранное состояние сохраняется до появления наложения.

Параметры лежат в `<fieldset disabled>`: без JS и до запуска скрипта они неактивны, приглушены, и сообщение объясняет, что рисунок показывает начальное состояние. Скрипт снимает `disabled` после первой отрисовки. Если запуск или перерисовка падает, график, легенда, статус и подпись возвращаются к разметке сборки, параметры снова неактивны, а сообщение говорит, что эксперимент не запустился.

Звук (`src/lib/sampling-audio.ts`): фрагмент длиной 2 с — восстановленный результат модели $y(t) = \mathrm{sign}(f') \sin(2\pi |f'| t)$ при текущей частоте дискретизации эксперимента; длительность не связана с 3 мс графика. `renderResult` записывает тот же непрерывный $y(t)$ в буфер с частотой `AudioContext` (44,1 или 48 кГц): аппаратная частота задаёт только шаг записи, а частота тона определяется моделью, например при $f_s = 1{,}5$ кГц звучит 500 Гц с противоположным знаком. Края фрагмента — нарастание и затухание по приподнятому косинусу за 20 мс; первый и последний отсчёт нулевые, поэтому щелчка нет. Начальный уровень регулятора — 30 % (усиление 0,3), mute даёт 0.

Плеер по макету компонентов: над ним предупреждение «Громкость.» с частотой текущего тона, затем круглая кнопка запуска, «Стоп», позиция с временем и длительностью (`0:00,0`), mute и громкость с процентами, под плеером строка состояния (`role="status"`). Тексты, имена кнопок и правила клавиш — в `src/lib/sampling-player.ts`. Главная кнопка называет действие: «Воспроизвести», «Пауза», «Продолжить»; mute — «Выключить звук» / «Включить звук». Состояния: «Остановлен», «Загрузка…», «Воспроизводится», «Пауза», недоступность и ошибка. Позиция — `input type="range"` с шагом 0,1 с и `aria-valuetext` «0,3 с из 2 с», громкость — шаг 5 %.

Клавиши обрабатываются только в группе плеера: на ползунке позиции пробел ставит на паузу или продолжает, стрелки двигают позицию нативно на 0,1 с; на кнопках стрелки ←/→ перематывают на 0,1 с, а пробел оставлен собственному действию кнопки. Ползунок громкости и сочетания с модификаторами не перехватываются.

`ResultPlayer` (`sampling-audio-player.ts`) создаёт `AudioContext` только при первом нажатии и при необходимости вызывает `resume()`; при загрузке страницы звук не создаётся. Источник буфера нельзя поставить на паузу, поэтому пауза запоминает позицию, а продолжение и перемотка запускают новый источник со смещением `start(when, offset)`. У каждого источника свой узел огибающей: запуск с середины нарастает, пауза, стоп и перемотка затухают за 20 мс, при перемотке старый и новый источники перекрываются без щелчка; общий узел после них задаёт громкость и mute. Смена частоты дискретизации останавливает фрагмент и сбрасывает позицию, следующий запуск создаёт буфер для нового результата; `pagehide` и скрытие вкладки (`visibilitychange`) останавливают звук; переключение видимой синусоиды звук не меняет. «Сбросить» возвращает и параметры, и плеер: остановка, позиция 0, громкость 30 %, звук включён, сообщение об ошибке убрано. На границе 2 кГц и при 1 кГц запуск, стоп и позиция неактивны, строка состояния объясняет почему. Без Web Audio плеер неактивен с сообщением «Звук недоступен…»; если браузер не создал или не запустил контекст, строка состояния говорит «Не удалось воспроизвести звук…», а график продолжает работать.

График — внешний SVG без `viewBox` шириной в контейнер: сетка, стебли, маркеры и подписи делений расположены в процентах области построения, поэтому текст и кружки не масштабируются. Линии сигнала и видимой синусоиды — во вложенном SVG с `preserveAspectRatio="none"` и `vector-effect: non-scaling-stroke`: они растягиваются по ширине, а толщина и пунктир остаются в пикселях. Подписи делений выходят за область построения в поля обёртки. Контейнерный запрос: уже 560 px график ниже, поля меньше, второстепенные деления (половины миллисекунд и ±0,5) скрыты; по каждой оси остаётся не больше пяти делений. Числа записываются через `formatNumber`: `toLocaleString('ru-RU')` не разделяет четырёхзначные числа, а в макете — «8 000».

### Визуализация фазы

`PhaseDemo` (`src/components/PhaseDemo.astro`) принимает `figure` и необязательный `id` (по умолчанию `phase-demo`) и стоит в статье о звуковой волне. Модель (`src/lib/phase.ts`): две синусоиды 1 кГц с амплитудой 1 на интервале 0–2 мс, опорная $\sin(2\pi f t)$ и сдвинутая $\sin(2\pi f t + \varphi)$. Сдвинутая опережает опорную на $\Delta t = \varphi / 360° \cdot T$; отрезок $\Delta t$ соединяет её максимум с ближайшим следующим максимумом опорной в 1,25 мс, поэтому при $0 \le \varphi \le 360°$ оба конца остаются на графике. При 360° синусоиды совпадают, а отрезок равен целому периоду.

Тексты значения («90° (π/2 рад)»), статуса, подписи, названия и описания SVG и разметку окружности и графика даёт `src/lib/phase-view.ts`; сборка и браузер рисуют их одними функциями. Δt округляется до тысячных миллисекунды, при неточной записи формула пишет «≈» вместо «=». График устроен как у эксперимента дискретизации; окружность — SVG с `viewBox` в том же вертикальном масштабе ±1,4, поэтому на широком экране концы векторов стоят на высоте значений синусоид в момент $t = 0$.

Параметры: ползунок 0–360° с шагом 15°, кнопки 0, 90, 180 и 270° с `aria-pressed` и «Сбросить» — к 90°. Контроллер `phase-demo-controller.ts` перерисовывает оба SVG, статус, подпись и кнопки; объявление в `aria-live="polite"` — через 0,7 с после последнего изменения. Поведение без JS и при ошибке то же, что у `SamplingDemo`: параметры в `<fieldset disabled>`, рисунок показывает начальное состояние. Звука нет. Браузерные сценарии `tests/e2e/phase-demo.spec.ts` идут на публичной статье `/sound-wave/` в обычном наборе.

### Генератор тона

`ToneDemo` (`src/components/ToneDemo.astro`) принимает `figure` и необязательный `id` (по умолчанию `tone-demo`) и стоит в разделе о частоте статьи о звуковой волне. Модель (`src/lib/tone.ts`): ползунок 0–600 с частотой $f = 20 \cdot 10^{n/200}$ Гц, то есть 200 шагов на декаду и 20 Гц – 20 кГц на всей длине; частота округляется до герц ниже 1 кГц и до десятков герц выше. Кнопки примеров ставят точную частоту (20, 100, 440 Гц, 1 и 20 кГц), а ползунок — в ближайшее положение. Период и длина волны при $c = 343$ м/с записываются тремя значащими цифрами с округлением половины вверх, как в таблице 1. Статус называет область: до 30 Гц и от 15 кГц — края слуха, 1–4 кГц — наибольшая чувствительность.

`TonePlayer` (`tone-audio-player.ts`) создаёт `AudioContext` только при первом нажатии; каждый запуск создаёт новый `OscillatorNode` (синус) со своим узлом огибающей: нарастание и затухание за 20 мс, как у эксперимента дискретизации. Остановка во время ожидания `resume()` отменяет запуск. `pagehide` и скрытие вкладки останавливают тон; «Сбросить» возвращает 1 кГц, останавливает звук, громкость 30 % и включённый звук. Без Web Audio плеер неактивен с сообщением «Звук недоступен…», значения работают. Поведение без JS и при ошибке то же, что у других визуализаций. Браузерные сценарии `tests/e2e/tone-demo.spec.ts` идут на `/sound-wave/`; звуковые — только в WebKit, остальные помечены `@cross-browser`.

### Визуализация компрессора

`CompressorDemo` (`src/components/CompressorDemo.astro`) принимает `figure` и необязательный `id` (по умолчанию `compressor-demo`) и стоит в статье `/compressor/`. Модель (`src/lib/compressor.ts`) повторяет описание компрессора MATLAB Audio Toolbox: статическая характеристика в децибелах с порогом $T$, степенью сжатия $R$ и коленом шириной $W$, симметричным относительно порога; подавление усиления сглаживается однополюсным фильтром $g_s[n] = \alpha g_s[n-1] + (1-\alpha) g_c[n]$ с $\alpha = e^{-\ln 9/(f_s t)}$, где $t$ — время атаки, когда подавление растёт, и восстановления, когда оно спадает (переход от 10 до 90 %). Тестовый сигнал — четыре удара тона 220 Гц с гармониками и пиками −2, −16, −8, −26 dBFS за 2 с; удары не перекрываются, поэтому пик каждого равен его уровню. Уровень на входе вычислителя — аналитическая пиковая огибающая. Фрагмент повторяется по кругу, поэтому сглаживание проходит один круг вхолостую.

`src/lib/compressor-view.ts` даёт тексты, описания и разметку обоих SVG: характеристика с диагональю, порогом, полосой колена и точками пиков; уровни входа и выхода во времени (1 000 значений в секунду) и полоса подавления усиления. Уровни ограничены областью −60…0 dBFS, выход выше 0 dBFS показан на полной шкале, а статус предупреждает о перегрузке. Параметры: порог −60…0 dBFS, степень сжатия 1; 1,5; 2; 3; 4; 6; 8; 12; 20; ∞, колено 0–24 дБ, атака 0,1–100 мс и восстановление 10–1 000 мс по фиксированным положениям, компенсация 0–24 дБ. Примеры «Без сжатия», «Медленная атака», «С компенсацией», «Лимитер» с `aria-pressed`; «Сбросить» возвращает −24 dBFS, 4:1, 6 дБ, 1 мс, 100 мс, 0 дБ и плеер в начальное состояние.

`CompressorPlayer` (`compressor-audio-player.ts`) создаёт `AudioContext` по первому нажатию, рассчитывает исходный и обработанный буферы той же моделью с частотой контекста и запускает оба по кругу одновременно; переключатель «Исходный / После компрессора» меняет их узлы выбора за 20 мс. Смена параметров во время звучания через 120 мс пересчитывает обработанный буфер: новый источник стартует с текущей позиции, старый затухает за 20 мс. Отсчёты выше полной шкалы ограничиваются. Громкость, mute, остановка при `pagehide` и скрытой вкладке, недоступность Web Audio — как у генератора тона. Браузерные сценарии `tests/e2e/compressor-demo.spec.ts`; звуковые — только в WebKit, остальные помечены `@cross-browser`.

### Визуализация форм LFO

`LfoDemo` (`src/components/LfoDemo.astro`) принимает `figure` и необязательный `id` (по умолчанию `lfo-waveforms`) и стоит в статье `/lfo/` на месте прежнего статичного рис. 2. Модель (`src/lib/lfo.ts`) хранит фазу в целых градусах [−180, 180) — так ползунок, курсоры и расчёты совпадают точно; `waveValue` повторяет формулы статьи: $\sin\varphi$, $1 - 2|\varphi|/\pi$, ±1 по знаку фазы (в нуле +1) и $\varphi/\pi$. `wrapPhase` переносит угол через полный оборот, `advance` двигает непрерывное положение анимации на 90° в секунду (оборот за 4 с), `angleFromPoint` переводит смещение указателя от центра окружности в угол против часовой стрелки.

`src/lib/lfo-view.ts` даёт тексты (фаза в градусах и радианах, расчёт `formulaHtml`, статус по части цикла, объявление) и разметку: окружность с изменяемой группой `[data-circle-state]` и четыре графика. Как у визуализации фазы, внешний SVG графика без `viewBox` с сеткой, курсором и подписями в процентах, а линия формы — во вложенном SVG, растянутом по ширине. Меняется только группа `[data-cursor]`, поэтому кадр анимации обновляет курсоры, расчёты, окружность и статус без перерисовки линий.

Контроллер `lfo-demo-controller.ts`: перетаскивание по окружности через Pointer Events с захватом указателя; ползунок, примеры и «Сбросить» вызывают одно обновление, которое останавливает анимацию. «Запустить» крутит фазу через `requestAnimationFrame`; кадр длиннее 100 мс считается паузой вкладки, а `visibilitychange` (скрытие) и `pagehide` останавливают вращение. Объявление в `aria-live="polite"` — через 0,7 с после ручного изменения, отпускания точки или паузы, во время анимации его нет. Поведение без JS и при ошибке — как у `PhaseDemo`. Проверки: `tests/unit/lfo.test.ts`, `tests/e2e/lfo-demo.spec.ts` (сценарий `@ci` — перетаскивание, клавиатура, примеры, анимация и сброс), размер подписей без JS — `tests/e2e/lfo.spec.ts`.

### Визуализация микширования

`MixingDemo` рисует начальный график при сборке; `src/lib/mixing.ts` задаёт общую модель и SVG для сборки и браузера. На двух периодах показаны вклады после gain, сумма и результат ограничения до ±1. Анимации и звука нет. Unit-тесты проверяют фазовые случаи и ограничения; сценарии `@mixing` запускаются отдельно на полной конфигурации, сохраняя лимит обязательного CI-набора.

### Визуализация байтов WAV-файла

`WavDumpDemo` (`src/components/WavDumpDemo.astro`) принимает `figure` и необязательный `id` (по умолчанию `wav-dump`); в статье `/wav-file/` он задан явно, чтобы на него можно было сослаться `#wav-dump`. Модель `src/lib/wav-dump.ts` собирает байты учебного файла из списка полей: смещения и длины полей, размеры чанков (`RIFF` = длина − 8, `LIST` с байтом выравнивания `INAM`), `byteRate` и `blockAlign` выводятся из параметров формата, поэтому байты и описания не расходятся. Там же чтение little-endian без знака и `int16`, поиск поля по байту и символ для колонки ASCII. `src/lib/wav-dump-view.ts` даёт тексты поля: смещение («60–63, 4 байта»), байты (одинаковые подряд сокращаются до «00 × 28»), чтение значения по виду поля, объявление и подпись.

Дамп собирается при сборке: строки по 8 байт, колонка смещения в десятичной записи, байты и ASCII. Каждый байт и символ — `span` с `data-field`; выбранное поле получает класс `is-current`, остальные байты его чанка — `is-chunk`, идентификаторы чанков набраны полужирным. Контроллер `wav-dump-controller.ts` делает дамп фокусируемым (`tabindex="0"`, роль `group`): стрелки и Home/End выбирают соседнее, первое и последнее поле; мышь выбирает поле наведением, касание и перо — нажатием, чтобы прокрутка не меняла выбор. Кнопки чанков на карте (`aria-pressed` у чанка текущего поля) переходят к его первому полю, «Предыдущее / Следующее поле» и «Сбросить» — по полям. Объявление в `aria-live="polite"` — через 0,7 с после последнего выбора. Без JS и при ошибке видно первое поле, карта и кнопки неактивны с пояснением. Проверки: `tests/unit/wav-dump.test.ts` (байты сверены с файлом, собранным независимо, непрерывность полей, размеры чанков, тексты, клавиши), `tests/e2e/wav-dump-demo.spec.ts` — только в полном наборе (`just test-e2e-full`), потому что обязательный набор CI заполнен до лимита.

### Статичные графики тремоло

Статья `/tremolo/` использует `TremoloPlot.astro` внутри `Figure`. Свойство `kind` выбирает аудиоволну до/после (`signal`), три шага преобразования LFO при глубине 40 % (`stages`) или сравнение двух шкал глубины (`depths`). SVG создаётся при сборке; название и описание добавляет `Figure`. Графики используют синусоидальный LFO 5 Гц и интервал 0,4 с, а иллюстративный аудиосигнал — тон 40 Гц с амплитудой 0,7. Формулы усиления хранятся в `src/lib/tremolo.ts`; unit-тесты проверяют диапазоны, нулевую и полную глубину и перевод между шкалами с учётом фазы. Серии отличаются сплошной и пунктирной линией, подписи масштабируются до читаемых 12–16 px по тому же правилу, что в рисунках LFO. Управления и звука у рисунков нет.

### Статичные рисунки психоакустики

Статья `/psychoacoustics/` использует `PsychoacousticsPlot.astro` внутри `Figure`. Свойство `kind` выбирает слуховую область (`field`), порог маскировки тоном 1 кГц, 80 дБ SPL (`masking`) или схему временной маскировки (`temporal`). Порог в тишине — столбец `T_f` таблицы 1 ISO 226:2023 из `src/data/equal-loudness.json`, точки соединяются отрезками по логарифмической оси без экстраполяции. Модель маскировки в `src/lib/psychoacoustics.ts` повторяет формулы (3), (7) и (8) обзора Painter и Spanias (2000): шкала барков, функция распространения и сдвиг 14,5 + z дБ; она иллюстративна и не зависит от уровня маскера. Там же хранится выборка полос для таблицы статьи. Схема временной маскировки условна: у шкалы уровня нет чисел, у трёх участков оси времени свой масштаб. Подписи масштабируются до 12–16 px по правилу рисунков тремоло. Unit-тесты `tests/unit/psychoacoustics.test.ts` проверяют данные порога, интерполяцию, шкалу барков по границам полос, склоны функции распространения и опорный порог около 57 дБ SPL. `tests/e2e/psychoacoustics.spec.ts` без метки `@ci` проверяет размер и положение подписей без JS в обеих темах при 320, 390 и 1440 px.

### Блоки кода и копирование

Блоки кода в MDX подсвечивает встроенный Shiki с темой `css-variables` (`shikiConfig` в `astro.config.mjs`): токены получают цвета `--astro-code-*`, а `src/styles/code.css` связывает их с `--syntax-*`, `--color-code-bg` и `--color-code-text`. Эти токены уже заданы через `light-dark()`, поэтому подсветка следует светлой, тёмной и автоматической теме без JavaScript. Плагин `src/lib/rehype-code-blocks.mjs` оборачивает каждый такой блок в `<figure class="code-block">` с шапкой: название языка (`languageLabel`; неизвестный язык показывается как указан) и кнопка «Копировать». Без JS кнопка скрыта, текст остаётся доступным для выделения.

Номера строк рисует CSS-счётчик (`.line::before` в `code.css`), как в макете: колонка закреплена при горизонтальной прокрутке и не входит в DOM-текст. `src/lib/code-block-controller.ts` по нажатию записывает в clipboard `textContent` блока `pre code`: номеров в тексте нет, поэтому копируется весь исходный код. Кнопка на 2 с меняется на «Скопировано» с галочкой после успешной записи; статус «Код скопирован» объявляется через `role="status"`. При отказе (нет `navigator.clipboard` или запись отклонена) над кодом на 8 с появляется «Не удалось скопировать код. Выделите текст вручную». Блок `pre` получает `tabindex="0"`, чтобы прокручиваться с клавиатуры.

### Дата обновления и «Черновик»

Дата обновления статьи — дата последнего коммита её файла (`git log -1 --format=%cI -- <файл>`); дата сборки её не заменяет. Новый файл без коммита в публикуемой сборке (`just build`) останавливает сборку с ошибкой, так же как неполная история клона. Для локальной проверки до коммита:

```sh
ALLOW_DRAFT_ARTICLES=1 just build
```

Страница такой статьи показывает «Черновик» вместо даты. `just dev` включает этот режим сам. Переменную не задают в CI и при публикации; в Actions история загружается полностью (`fetch-depth: 0`). Расчёт — в `src/lib/git-date.ts`, тесты — `tests/unit/git-date.test.ts` и `npm run test:articles`.

## Проверка содержимого статьи

Перед генерацией страниц `getStaticPaths` в `src/pages/[slug].astro` передаёт всю коллекцию в `assertValidArticles` (`src/lib/article-content.ts`). Функция разбирает MDX каждой статьи и бросает одну ошибку со списком нарушений вида `файл: проблема`, поэтому сборка останавливается до публикации:

- раздел `## Источники {#sources}` обязателен и содержит хотя бы одну ссылку; связанные темы обязательны уже в схеме frontmatter (`related` не пуст);
- внутренние ссылки `/slug/#anchor`, `#anchor` и цели `related` и `prerequisites` ведут на существующую статью и существующий раздел или идентификатор блока; внешние ссылки не проверяются;
- у каждого блока кода указан язык (``` ```ts ```, для простого текста — ` ```text`); строчный код не проверяется;
- блоки `Figure`, `SamplingDemo`, `DataTable` и `Equation` задают `id` (английский kebab-case, уникальный в статье, в том числе среди якорей заголовков; у `SamplingDemo` необязателен) и числовой номер (`number={1}`; у `SamplingDemo` — `figure={1}`; у `Equation` номер необязателен);
- рисунки, `SamplingDemo`, `PhaseDemo`, `ToneDemo`, `CompressorDemo`, `LfoDemo` и `WavDumpDemo` нумеруются одной последовательностью 1, 2, 3…, таблицы и формулы с номером — каждые своей; пропуск, повтор и порядок, отличный от порядка в документе, останавливают сборку.

Рекомендательные пределы из [спецификации](spec.md#данные-статей-и-ссылки) (число тегов, врезок, строк кода) не проверяются. Правила работают по разметке MDX и не зависят от самих компонентов; служебные статьи используют заглушку `tests/fixtures/articles/components/Block.astro`. Тесты: `tests/unit/article-content.test.ts` и `npm run test:articles` (положительная коллекция `content-valid` и по одной ошибочной статье на правило).

## Заметки «Подробнее»

`src/components/MarginNote.astro` получает `items` и один абзац в default-слоте. `src/lib/margin-note.ts` проверяет 1–3 записи с непустыми `label`, `description` и общей схемой `target` из `links.ts`. `resolveTarget` строит адреса через `withBase`; готовая сборка проверяет внутренние страницы и якоря, включая ссылки из свойств MDX. Названия и пояснения выводятся обычным текстом в одной ссылке. Заметка исключена из поискового индекса, абзац остаётся в нём.

Компонент выводит контейнер `.margin-note-block` с `<p>` и следующим `<aside aria-label="Подробнее">`. На узком экране и в печати это две строки. На широком экране — две колонки с зазором 48 px и правой шириной 208 px. Высота строки учитывает оба блока, поэтому следующий элемент не перекрывает высокую заметку. Клиентский скрипт не нужен. `ArticleLayout` через `:has(.margin-note)` резервирует поле только на страницах с заметками; обычные элементы остаются в колонке текста, рисунки и таблицы могут использовать ширину до `--wide-width` ниже заметки.

Статичные рисунки LFO (`src/styles/lfo.css`) и тремоло (`TremoloPlot`) учитывают это расширение: при ширине рамки от 700 px контейнерный запрос уменьшает исходный кегль SVG до 8,5 px. После масштабирования рисунка с `viewBox` шириной 480 единиц подписи остаются в диапазоне 12–16 px, в том числе при заполнении поля рисунком шириной до 880 px.

Служебный образец: `<origin><base>__test/margin-notes/#margin-notes`. `npm run test:mdx` проверяет его HTML и внутренние ссылки при сборке в корне и под префиксом, а также исключение служебной страницы из публикации. `tests/e2e/margin-notes.spec.ts` с меткой `@margin-notes` выполняется на служебной сборке: WebKit проверяет размеры в обеих темах, печать, увеличение текста, порядок и клавиатурные переходы без JS; Chromium и Firefox — сетку и отсутствие перекрытий. Правила использования — в [общих правилах](authoring/rules.md#учебные-компоненты), [чеклисте](authoring/checklist.md#контент-и-связи) и [шаблоне](authoring/article-template.mdx).

## Разбор целочисленного PCM

`src/lib/integer-pcm.ts` читает байты WAV PCM, кодирует центрированное целое и нормирует его степенью двойки. `pcmToFloat` явно округляет до binary32; `floatToPcm` округляет половины от нуля, ограничивает целую шкалу и отклоняет нечисловые/бесконечные значения. Эти функции и полный диапазон i16 проверяются в `tests/unit/integer-pcm.test.ts`.

`PcmSampleDemo.astro` создаёт статичный разбор −256 в статье `/integer-pcm/`. `pcm-sample-controller.ts` включает два способа ввода 24-битного отсчёта; успешное применение синхронизирует оба поля и все значения, ошибочное сохраняет предыдущий разбор. Визуализация зарегистрирована вместе с декоративным превью `pcm`. Сценарии `tests/e2e/pcm-sample-demo.spec.ts` входят в диагностическую матрицу; отдельно выполняются командой `npx playwright test pcm-sample-demo.spec.ts --config playwright.full.config.ts` на готовых сборках E2E. Обязательный набор CI остаётся в лимите 88 сценариев.

## Предсказание FLAC

`src/lib/flac-prediction.ts` хранит три учебных сигнала по 32 целых отсчёта (тоны записаны явно, чтобы сборка и браузеры получали одинаковые числа), считает фиксированные предсказатели порядков 0–4 по RFC 9639, остаток, свёртку знака, коды Райса, лучший параметр от 0 до 14 и размер подкадра: 18 служебных бит, разогрев и коды остатка. `decodeFixed` восстанавливает отсчёты; обратимость, пример кода из RFC и размеры проверяет `tests/unit/flac-prediction.test.ts`.

## Данные треков и проверка целей

Коллекция `tracks` зарегистрирована в `src/content.config.ts`: JSON из `src/content/tracks/<slug>.json`, id записи — имя файла с расширением. Это сохраняет разные файлы с одинаковым slug для последующего обнаружения повтора, вместо молчаливой потери записи. Схема `trackSchema` в `src/lib/tracks.ts` проверяет [контракт](spec.md#контракт-данных-трека): постоянные идентификаторы, непустые тексты и массивы этапов/элементов, строгие поля, только внутренние цели статей/разделов. `optional` по умолчанию `false`, `related` — пустой массив. Состав всех пяти маршрутов и записи «Новое» созданы в задаче 69 и одобрены автором; страницы реализованы в 66. Отсутствующая/пустая коллекция до наполнения допустима; фикстуры не копируются в публичный каталог.

`loadTrackData()` в `src/lib/track-data.ts` загружает треки, статьи и исходные записи журнала, проверяет уникальность slug и якорей статей и получает заголовки через `render()`. Опубликованные статьи определяются по записям `new` с целью `article`. `loadUpdates()` использует эти данные для проверки целей журнала и вычисляет актуальное название и метаданные материала: для трека — число этапов и элементов. Запись требует ровно одну цель `article` или `track`; пункты могут вести на `stage-<id>` существующего этапа. Публикуемая сборка требует собственную запись «Новое» для каждого трека; дополнение без публикации или до неё запрещено.

`loadTracks()` в `src/lib/track-list.ts` передаёт уже загруженные данные в `loadUpdates()` и добавляет даты через `resolveArticleDates(null, …)`: публикация и последнее дополнение берутся только из журнала. Циклической загрузки нет. В dev и с `ALLOW_DRAFT_ARTICLES=1` трек без записей допускается и имеет пустые даты для отображения «Черновик».

`assertValidTracks()` проверяет уникальность slug и совпадение с именем файла, id этапов внутри трека и id элементов во всём треке, повторные цели `article/anchor`, существование опубликованной статьи и заголовка H2–H4. Якорь рисунка или визуализации не подменяет раздел. Статья целиком и разные её разделы допустимы как разные элементы. Проверяются существование связанных треков, повтор ссылки и ссылка на себя; взаимная связь не обязательна. Ошибки собираются в одно сообщение с именами файлов. `getStaticPaths()` страницы статьи вызывает `loadUpdates()` до генерации страниц: неверные связи останавливают обычную сборку, даже пока страниц треков ещё нет.

`buildTrackList()` формирует представление после проверки. Порядок пяти аудиторий постоянный, порядок этапов/элементов берётся из массивов, id сохраняются. Названия статей и разделов актуальные, счётчики включают необязательные элементы, позиции элементов сквозные. Вычисляются якоря этапов `stage-<id>`, адреса статей/разделов и связанных треков с учётом `base`. Адрес элемента всегда содержит контекст `?track=<slug>&item=<id>` перед якорем раздела (для целой статьи — без якоря); блок статьи читает его для выбора текущего элемента. `getArticleTracks()` возвращает все этапы с вхождениями статьи, сворачивая несколько разделов одного этапа в одну ссылку; пустая обратная связь — пустой массив.

`tests/unit/tracks.test.ts` проверяет схему, ошибки связей, порядок, счётчики, актуальные названия, неизменность id при перестановке и обратные вхождения в корне и под префиксом. Служебные JSON находятся только в `tests/fixtures/tracks/`: `valid/` и контрольные наборы с неизвестной статьёй, разделом, повторным id элемента и пустым этапом. Они ссылаются на существующие опубликованные статьи; записи журнала статей остаются обычными. Никакой тестовый трек не публикуется.

`npm run test:tracks` запускает `scripts/check-tracks.mjs`: собирает корректные служебные треки в корне и под префиксом, подтверждает отказ сборки на контрольных ошибках, затем последовательно собирает обычный сайт под обоими базовыми путями. Последние сборки подтверждают, что кеш Astro не перенёс фикстуры в HTML, RSS, клиентские ресурсы или поисковый индекс. Для подмены коллекции треков используется `TRACKS_DIR`; служебные записи добавляются к копии журнала через `UPDATES_DIR`. В копию попадают только записи статей не новее последней служебной записи, поэтому новые публикации не вытесняют фикстуры из блока последних обновлений. `test:tracks` также проверяет обязательную публикацию и «Черновик» без записи в локальном режиме. Переменная `TRACKS_DIR` описана в `.env.example`; на публичной сборке её не задают. Артефакты проверки создаются во временном каталоге `.e2e/tracks-*` и удаляются после проверки. Команда входит в CI до E2E-сборок; эти служебные артефакты не являются артефактом деплоя. Проверки сборки и `just typecheck` выполняются последовательно, поскольку используют общий кеш Astro.

`npm run test:track-updates` отдельно собирает служебные треки с журналом и публичными страницами с конфигурацией из `tests/fixtures/tracks/astro.config.mjs` в `.e2e/track-updates-root/` и `.e2e/track-updates-prefixed/`. `playwright.tracks.config.ts` запускает Chromium в корне и WebKit под префиксом: журнал, архив, фильтр и история, RSS, последние обновления, даты, ссылки этапов, обе темы на 320/390/1440 px и работа без JS. Сценарии `@track-updates` исключены из обычных публичных прогонов: их данные и маршруты не публикуются. Тот же набор собирает реальные страницы треков, поэтому `tests/e2e/tracks.spec.ts` (метка `@tracks`) выполняется вместе с ними: каталог, страница трека, адреса элементов с контекстом, якорь этапа, 404 неизвестного slug, отсутствие горизонтальной прокрутки на 320–1440 px и границах 599/600, 1023/1024, 1279/1280 в обеих темах, работа без JS. Служебная сборка не подменяет маршруты: `tests/fixtures/tracks/astro.config.mjs` использует публичную конфигурацию, фикстуры подключаются только `TRACKS_DIR` и `UPDATES_DIR`. Сценарии `@tracks` исключены из обязательного набора `test:e2e` и запускаются отдельным шагом CI после него.

Сборки служебных статей (`npm run test:articles`) и журнала (`scripts/build-updates-fixture.mjs`) задают пустую коллекцию через `TRACKS_DIR`: публичные маршруты ссылаются на реальные статьи и не должны попадать в эти наборы. Обычная сборка использует все пять треков и их записи «Новое».

### Страницы треков

`src/pages/tracks/index.astro` строит каталог `/tracks/` из `loadTracks()`: `TrackCard` — одна ссылка с названием, аудиторией, счётчиками и (в каталоге) названиями этапов; без треков выводится «Треки готовятся». `src/pages/tracks/[slug].astro` создаёт `/tracks/<slug>/` для каждого проверенного трека, поэтому неизвестный slug даёт 404. Страница содержит крошки, H1 «Трек для …» (родительный падеж задан для пяти постоянных slug в `src/lib/track-view.ts`, для прочих — «Трек «название»»), описание, переключатель `nav[aria-label="Треки чтения"]`, счётчики с легендой, `TrackStages` (этапы с якорями `#stage-<id>`, осью и ссылками на статьи и разделы), дату `Трек обновлён <time>` либо «Черновик» и связанные треки. Страницы целиком исключены из Pagefind (`data-pagefind-ignore`) и не используют JS и storage. Склонения и подписи проверяет `tests/unit/track-view.test.ts`.

### Входы в треки и навигация статьи

В `src/lib/navigation.ts` «Треки» стоят после «Материалов» (во втором пункте компактного меню) и активны на `/tracks/` и под ним через `activeUnder`; на статье, в том числе открытой из трека, активны «Материалы». На главной `src/pages/index.astro` после кнопки поиска выводит блок «С чего начать»: те же `TrackCard` в порядке `trackOrder` (одна колонка, от 600 px — две, от 1024 px — три) и ссылка «Все треки». Без треков блок не выводится, как и пустые группы. Блок исключён из Pagefind.

Под метаданными статьи `ArticleLayout.astro` выводит строку «В треках:» — ссылки «<название>, этап N» из `getArticleTracks()`: разделы одного этапа сворачиваются в одну ссылку, а разные этапы сохраняются. Строки нет, если статья не входит в маршруты.

Блок трека в конце тела статьи (перед «Связанными темами») строится в браузере. Сервер выводит `nav[data-track-nav][hidden]` и `script[data-track-nav-data]` с JSON из `buildNavData()` (`src/lib/track-navigation.ts`): только треки, куда входит статья, с полным порядком элементов (id, цель, название, этап, адрес с `?track=&item=`). `initTrackNavigation()` (`src/lib/track-navigation-controller.ts`) разбирает `location` функцией `resolveTrackContext()`: нужен ровно один `track` и не более одного `item`; `item` должен принадлежать этой статье в этом треке. Без `item` допускается ровно один элемент статьи, чья цель совпадает с якорем адреса (без якоря — статья целиком). Неизвестный трек, чужой или повторный `item`, неоднозначное совпадение оставляют блок скрытым; лишние параметры игнорируются. Блок показывает «Трек «…» · этап N из K · элемент M из L», «Весь трек» (адрес этапа) и соседей в общем порядке, включая необязательные; на краях отсутствующий сосед не выводится. Ссылки соседей уже содержат контекст, обычные ссылки статьи его не получают. Узлы создаются через DOM API с `textContent`, JSON экранирует `<`. Без JS блок остаётся скрытым, а страница и ссылки работают. `pageshow` из bfcache перестраивает блок; `storage` не используется. Блок и строка «В треках» помечены `data-pagefind-ignore`.

Целевой заголовок H2–H4 по `:target` получает `--color-accent-soft` и кольцо той же заливки без смещения текста, как термин глоссария.

Проверки: `tests/unit/track-navigation.test.ts`, `tests/unit/navigation.test.ts`, `tests/e2e/track-navigation.spec.ts` (входит в `npm run test:track-updates` на служебных треках: шапка, меню, главная, «В треках», блок, края, история, обе темы, девять ширин, без JS). `npm run test:production` дополнительно требует «Треки» в шапке, блок «С чего начать» с числом карточек каталога и маркеры `data-in-tracks` и `data-track-nav` на статьях элементов.

## Шумовой эксперимент

При локальном просмотре новой статьи без коммита `getPublishedDate` возвращает `null`. Страница статьи и список материалов передают `isDraft` в `resolveArticleDates`, поэтому даже подготовленная запись «Новое» не заменяет метку «Черновик» датой. Даты опубликованных статей и треков по-прежнему определяются журналом.

`NoiseDemo` в `/noise/#noise-demo` получает начальные графики и значения при сборке. Модель `src/lib/noise.ts` воспроизводит 48-битный PRNG JUCE 9.0.3 через три 16-битных разряда без потери точности JavaScript и алгоритм Voss–McCartney из статьи. Каждый цвет даёт фрагмент 4 с при 48 кГц; конечный фрагмент отдельно нормируется до RMS 0,12. Среднее не вычитается. PSD оценивается методом Welch: FFT 8192, периодическое окно Hann, перекрытие 50 %, без удаления среднего; линия усредняет плотность в полосах 1/12 октавы, мощность октав считается суммированием PSD с шириной частотных ячеек.

`noise-view.ts` строит три графика из той же модели. После загрузки `noise-demo-controller.ts` адаптирует их к ширине контейнера; без JS SVG прокручивается внутри блока. `NoisePlayer` создаёт Web Audio только по нажатию, передаёт рассчитанные отсчёты в буфер 48 кГц и добавляет плавные края. Контроллер управляет seed, цветом для прослушивания, паузой, остановкой, позицией, громкостью и mute. Смена seed/цвета отменяет ожидающий запуск, останавливает звук и возвращает позицию в начало; скрытие вкладки и уход со страницы также прекращают воспроизведение. Ошибка аудио сохраняет работающие графики. Требования — в [спецификации](spec.md#материалы), проверка — в `tests/unit/noise.test.ts` и `tests/e2e/noise-demo.spec.ts`.
