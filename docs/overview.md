# Обзор устройства

Короткие описания того, как работают отдельные части сайта. Требования и контракты находятся в [спецификации](spec.md), пути — в [структуре проекта](structure.md), команды — в [README](../README.md). Новые обзорные описания добавляются в этот файл отдельными разделами.

## Тема оформления

Режимы: светлая, тёмная и авто. Светлая и тёмная ставят `data-theme` на `<html>`, авто убирает атрибут, и `color-scheme` следует системе без перезагрузки (токены — `src/styles/tokens.css`). Выбор хранится в `localStorage` под ключом `theme`; пустое или неверное значение означает авто.

Синхронный скрипт `themeInitScript` встроен в `<head>` до CSS и восстанавливает выбор до первой отрисовки. Кнопка `ThemeToggle` по кругу меняет режим (светлая → тёмная → авто), скрыта без JS и обновляется при изменении выбора в другой вкладке. Режим в окне хранится в самой кнопке, поэтому отказ чтения или записи `localStorage` (`try/catch`) не ломает переключение, а выбор не сохранится. Без JS действует системная тема.

Логика и тесты — `src/lib/theme.ts`, `tests/unit/theme.test.ts`, `tests/e2e/home.spec.ts`. Кнопка пока стоит на начальной странице; в шапку её переносит задача каркаса.

## Время чтения

Время чтения — `max(1, ceil(слова / 180))` по тексту MDX; ручное `readingMinutes` во frontmatter заменяет оценку.

Не считаются frontmatter, блоки и строчный код, формулы, `import`/`export`, выражения `{…}`. Считается видимый текст, включая текст ссылок, таблиц и атрибутов `title`, `question`, `caption` учебных блоков. Слово — последовательность букв и цифр, дефисное слово считается одним, пунктуация не считается.

Расчёт — `src/lib/reading-time.ts`, тесты — `tests/unit/reading-time.test.ts`; контракт описан в [спецификации](spec.md#данные-материалов-и-учебные-компоненты).

## Якоря и оглавление

Английский идентификатор раздела задаётся в конце заголовка: `## Частота Найквиста {#nyquist-frequency}`. Он становится `id` заголовка в HTML и не попадает в его текст, поэтому переименование русского заголовка адрес раздела не меняет. Формат — латиница, цифры и дефисы (`[a-z0-9]` через дефис); повторный якорь, неверный формат и `{#…}` вне конца заголовка останавливают сборку. Заголовок без `{#…}` получает автоматический id по тексту, но стабильные ссылки требуют явного якоря.

Синтаксис `{#…}` обычный MDX считает ошибочным выражением JavaScript, поэтому его разбирает расширение `src/lib/remark-heading-anchors.mjs`, подключённое в `astro.config.mjs` и в разбор для времени чтения. Остальные выражения `{…}` в заголовках работают как прежде.

Набор заголовков берётся один раз из `render()` Astro и идёт и в HTML, и в оглавление. `getToc` в `src/lib/headings.ts` оставляет H2 и H3 в порядке документа, `assertUniqueAnchors` отвергает повтор id, в том числе явного с автоматическим. Ссылки на разделы пишутся как обычные ссылки MDX `[текст](/slug/#anchor)`: `rehype-site-urls` добавляет базовый путь через `withBase`, якорь сохраняется, а сборка проверяет, что он существует.

## Поисковый индекс и проверка артефакта

После создания HTML интеграция `scripts/build-artifact.mjs` проверяет готовые файлы через `scripts/check-artifact.mjs`, затем строит индекс Pagefind в `<outDir>/pagefind/`. Это происходит при каждом `astro build`, в том числе через `just build` и с переопределёнными `--base` и `--outDir`. В HTML проверяются `href`, `src`, `poster`, ресурсы `object`, встроенные стили и `<style>`; в CSS — `url(...)`. Ссылки разрешаются относительно страницы или CSS-файла, query не меняет целевой файл, HTML-якорь должен существовать. Адреса того же origin считаются внутренними и должны учитывать `base`; внешние адреса и схемы вроде `mailto:` и `data:` не требуют сети. Метаданные, источники, ссылки и нумерацию блоков проверяет отдельный шаг до генерации страниц ([ниже](#проверка-содержимого-статьи)); оба шага выполняются в одной сборке.

Начальная страница индексирует `<main data-pagefind-body>`; навигация исключена через `data-pagefind-ignore`. Служебные маршруты из `tests/fixtures/` обычная сборка не создаёт. Интерфейс поиска появится позднее; сейчас API проверяется браузерными тестами. Dev-сервер индекс не строит. Для ручной проверки соберите сайт и откройте preview:

```sh
just build
npm run preview -- --ignore-lock --host 127.0.0.1 --port 4322
```

Откройте адрес из вывода Astro с фактическим базовым путём, например `http://127.0.0.1:4322/audio-theory/`. В консоли браузера на этой странице:

```js
const pagefind = await import('/audio-theory/pagefind/pagefind.js');
const results = await pagefind.search('цифровой обработке');
const pages = await Promise.all(results.results.map((result) => result.data()));
console.table(pages.map(({ url, meta }) => ({ url, title: meta.title })));
```

Ожидается одна страница «Теория аудио» с адресом `/audio-theory/`; запрос `GitHub` не даёт результатов, поскольку навигация исключена. При сборке с `--base /` используйте импорт `/pagefind/pagefind.js` и запускайте preview с `--base /`. После проверки остановите свой foreground preview через `Ctrl-C`.

Unit-тесты проверяют отсутствующие страницы, якоря и ресурсы, query, относительные и внешние адреса и неверный базовый путь. Контрольная сборка со служебной ошибочной ссылкой должна завершиться с ненулевым кодом.

## Адреса сайта и базовый путь

`src/site.config.ts` задаёт адрес `https://hazadus.github.io`, базовый путь `/audio-theory/` и репозиторий `https://github.com/hazadus/audio-theory`. Astro берёт `site` и `base` из этой конфигурации. Переменные окружения для адресов не используются; `.env.example` описывает тестовую `ARTICLES_DIR` и локальную `ALLOW_DRAFT_ARTICLES`. GitHub Pages настроен на публикацию через Actions; процесс описан в [инструкции по CI и деплою](deploy.md).

Страницы и ресурсы используют `withBase` из `src/lib/urls.ts`, например `withBase('/sampling/?mode=demo#nyquist-frequency')`. Функция берёт фактический `import.meta.env.BASE_URL`, сохраняет query и якорь, добавляет префикс один раз. Внешние URL (включая `//…`), схемы `mailto:` и `data:`, ссылки на якорь или query текущей страницы, относительные `./…` и `../…` сохраняются. Строки без начального `/` считаются логическими маршрутами от корня сайта. В MDX обычные ссылки и ресурсы преобразуются при сборке через `rehype-site-urls`; адреса в выражениях и свойствах встроенных компонентов формируются явным вызовом `withBase`.

Проверка размещения в корне без изменения конфигурации:

```sh
npm run build -- --base /
just dev --host 127.0.0.1 --port 4321 --base /
```

Для стандартного префикса используйте `just build` и `just dev`. `dist/` содержит корень публикуемого артефакта: каталог `audio-theory/` внутри него не создаётся. Статический сервер должен размещать содержимое `dist/` по выбранному базовому пути. CSS и импортированные ресурсы получают префикс средствами Astro.

## Проверка MDX и формул

MDX использует официальный `@astrojs/mdx` и обработчик `@astrojs/markdown-remark` с `remark-math` и `rehype-katex`. Строчные формулы записываются как `$T_s = 1/f_s$`, блочные — между отдельными строками `$$`. HTML и MathML создаются при сборке; неверная формула останавливает её. JavaScript для чтения формул не нужен. Временные сборки проверки создаются в `.e2e/mdx-*/` рядом с кешем Astro на одной файловой системе и удаляются после прогона.

На странице с формулами подключается `src/styles/math.css`: CSS и шрифты KaTeX входят в локальные ресурсы сборки; небольшие шрифты могут встраиваться в CSS. Кириллица внутри `\text{}` использует шрифт статьи. Лицензия KaTeX сохранена в `public/licenses/katex.txt`.

Проверка корректного MDX в корне и под `/audio-theory/`, ссылок, ошибочной формулы, компонента, MathML, локальных ресурсов и отсутствия проверочных материалов в публикуемой сборке:

```sh
npm run test:mdx
```

Проверочные исходники находятся в `tests/fixtures/mdx/`, отдельно от статей и обычных маршрутов. Сборки проверки создаются во временном каталоге и удаляются после выполнения. Для просмотра служебного материала:

```sh
just dev --host 127.0.0.1 --port 4321 --config tests/fixtures/mdx/astro.config.mjs
```

К адресу сервера с фактическим базовым путём добавьте `__test/mdx/`, например `http://127.0.0.1:4321/audio-theory/__test/mdx/`. Эта страница доступна только с тестовой конфигурацией; обычный `just build` её не публикует. Проверочный `SelfCheck` служит для проверки встраивания Astro-компонента, полноценные учебные компоненты добавляются позднее по плану.

## Коллекция статей

Статьи — файлы `src/content/articles/**/*.mdx`; коллекция `articles` объявлена в `src/content.config.ts`, схема frontmatter — в `src/lib/articles.ts`, четыре группы (`basics`, `digital`, `conv`, `data`) — в `src/data/topics.ts`. Страница `/<slug>/` создаётся из поля `slug` в `src/pages/[slug].astro`; id записи берётся из пути файла, поэтому повторный `slug` останавливает сборку, а не теряется молча. Неизвестная группа, пустые обязательные поля, неверные `slug` и `readingMinutes` также блокируют сборку. Отсутствие раздела «Источники» со ссылками, неверные внутренние ссылки и цели связанных тем, блок кода без языка, неверные идентификаторы и нумерация рисунков, таблиц и формул останавливают сборку; правила описаны в [ниже](#проверка-содержимого-статьи). Страница статьи пока минимальная: общий каркас и оформление добавляются отдельными задачами.

Проверка маршрутов, отказов при неверных данных и отсутствия служебных статей в публикации; unit-тесты схемы входят в `just test`:

```sh
npm run test:articles
```

Служебные статьи лежат в `tests/fixtures/articles/`. Проверка подменяет каталог коллекции переменной `ARTICLES_DIR` (описана в `.env.example`); публичная сборка её не использует. Чтобы посмотреть служебные статьи, запустите `ARTICLES_DIR=./tests/fixtures/articles/valid just dev`.

### Дата обновления и «Черновик»

Дата обновления статьи — дата последнего коммита её файла (`git log -1 --format=%cI -- <файл>`); дата сборки её не заменяет. Новый файл без коммита в публикуемой сборке (`just build`) останавливает сборку с ошибкой, так же как неполная история клона. Для локальной проверки до коммита:

```sh
ALLOW_DRAFT_ARTICLES=1 just build
```

Страница такой статьи показывает «Черновик» вместо даты. `just dev` включает этот режим сам. Переменную не задают в CI и при публикации; в Actions история загружается полностью (`fetch-depth: 0`). Расчёт — в `src/lib/git-date.ts`, тесты — `tests/unit/git-date.test.ts` и `npm run test:articles`.

## Проверка содержимого статьи

Перед генерацией страниц `getStaticPaths` в `src/pages/[slug].astro` передаёт всю коллекцию в `assertValidArticles` (`src/lib/article-content.ts`). Функция разбирает MDX каждой статьи и бросает одну ошибку со списком нарушений вида `файл: проблема`, поэтому сборка останавливается до публикации:

- раздел `## Источники {#sources}` обязателен и содержит хотя бы одну ссылку; связанные темы обязательны уже в схеме frontmatter (`related` не пуст);
- внутренние ссылки `/slug/#anchor`, `#anchor` и цели `related` и `prerequisites` ведут на существующую статью и существующий раздел или идентификатор блока; внешние ссылки не проверяются;
- у каждого блока кода указан язык (``` ```ts ```, для простого текста — ` ```text`); строчный код не проверяется;
- блоки `Figure`, `SamplingDemo`, `DataTable` и `Equation` задают `id` (английский kebab-case, уникальный в статье, в том числе среди якорей заголовков; у `SamplingDemo` необязателен) и числовой номер (`number={1}`; у `SamplingDemo` — `figure={1}`; у `Equation` номер необязателен);
- рисунки и `SamplingDemo` нумеруются одной последовательностью 1, 2, 3…, таблицы и формулы с номером — каждые своей; пропуск, повтор и порядок, отличный от порядка в документе, останавливают сборку.

Рекомендательные пределы из [спецификации](spec.md#данные-статей-и-ссылки) (число тегов, врезок, строк кода) не проверяются. Правила работают по разметке MDX и не зависят от самих компонентов; служебные статьи используют заглушку `tests/fixtures/articles/components/Block.astro`. Тесты: `tests/unit/article-content.test.ts` и `npm run test:articles` (положительная коллекция `content-valid` и по одной ошибочной статье на правило).
