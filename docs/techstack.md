# Технологический стек

Документ описывает используемые технологии и их назначение. Точные версии зависимостей — в `package.json` и `package-lock.json`. Требования к проекту находятся в [spec.md](spec.md), открытые вопросы — в [questions.md](questions.md).

## Поиск: Pagefind

Pagefind строит индекс через Node.js API в интеграции `scripts/build-artifact.mjs` после сборки Astro. Индекс размещается в `<outDir>/pagefind/`; начальная страница индексируется без навигации. Браузерные тесты проверяют настоящий API в корне и под `/audio-theory/`. Поиск открывается в собственном диалоге сайта.

[Pagefind](https://pagefind.app/) — библиотека полнотекстового поиска для статических сайтов.

### Как работает

1. После сборки сайта Pagefind индексирует содержимое готовых HTML-страниц.
2. Файлы индекса и код поиска публикуются вместе с сайтом.
3. Браузер загружает нужные части индекса и выполняет поиск без серверной части.
4. Индекс пересоздаётся при каждой сборке перед публикацией сайта.

Описание процесса: [документация Pagefind](https://pagefind.app/docs/).

Проверка артефакта выполняется до индексации и останавливает сборку при отсутствующей внутренней странице, HTML-якоре или ресурсе HTML/CSS. Для разбора HTML подключён `parse5`, для CSS `url(...)` — `postcss-value-parser`. Внешние адреса не проверяются по сети.

### Почему выбран

- Подходит для статического сайта без отдельного поискового сервиса.
- Есть готовый интерфейс поиска и возможность показывать результаты по разделам страниц.
- Поддерживает русский интерфейс и обработку основ русских слов для поиска по словоформам: [поддержка языков](https://pagefind.app/docs/multilingual/).

В начале реализации, до полной реализации попапа, нужно проверить реальный индекс на первых статьях: поиск по русскому тексту и словоформам, английским терминам на русскоязычных страницах и переходы к разделам. Также проверяются интеграция с Astro и базовый путь GitHub Pages. Интерфейс — собственный попап поверх JS API Pagefind, по [дизайн-системе](design-system.md#поиск), с проверкой светлой и тёмной тем.

## Формулы: KaTeX

KaTeX рендерит формулы при сборке через `remark-math` и `rehype-katex`. Вывод включает HTML и MathML; дополнительный обработчик ошибок останавливает сборку при неверной формуле. `strict: 'ignore'` допускает кириллицу, ошибки синтаксиса остаются обязательными; `trust: false` запрещает доверенные HTML-команды. CSS и шрифты входят в локальные ресурсы сборки, лицензия сохранена в `public/licenses/katex.txt`. Кириллица внутри `\text{}` оформляется шрифтом статьи.

## Статический генератор: Astro

Astro создаёт статические страницы при сборке для публикации на GitHub Pages. Интерактивные элементы работают в браузере. Дизайн-система задаёт CSS-токены и семантическую разметку независимо от генератора.

## TypeScript и зависимости

Проект использует Astro 7 и TypeScript 6 со строгой конфигурацией `astro/tsconfigs/strict`. Поддерживаемые версии окружения — Node.js 22 (≥ 22.13.0), 24 или ≥ 26 и npm ≥ 9.6.5. Диапазон Node.js учитывает совместимость ESLint 10 и Vitest 5. Прямые зависимости закреплены точными версиями, дерево зависимостей — `package-lock.json`; для воспроизводимой установки используется `npm ci`. `just typecheck` запускает Astro Check для компонентов и `tsc --noEmit` для TypeScript. TypeScript 6 выбран по диапазонам совместимости Astro Check и typescript-eslint; TypeScript 7 ими пока не поддерживается.

### Назначение прямых npm-зависимостей

| Зависимость | Зачем подключена |
| --- | --- |
| `astro` | Создаёт HTML и ресурсы статического сайта; предоставляет сервер разработки и сборку для GitHub Pages без серверной части. |
| `typescript` | Проверяет типы кода и контрактов компонентов через `just typecheck`. |
| `@astrojs/mdx` | Официальная интеграция для статей в MDX: позволяет использовать Markdown и встраивать Astro-компоненты в текст. |
| `@astrojs/markdown-remark` | Подключает обработчик remark/rehype в Astro 7, необходимый для выбранных плагинов математической разметки; его настройки наследует MDX. |
| `remark-math` | Разбирает строчные `$…$` и блочные `$$…$$` формулы в дереве Markdown до генерации HTML. |
| `unified`, `remark-parse`, `remark-mdx` | Разбирают текст MDX в дерево для подсчёта слов и времени чтения (`src/lib/reading-time.ts`); версии зафиксированы в `package.json`. |
| `rehype-katex` | Преобразует разобранные формулы в HTML и MathML при сборке, чтобы они читались без клиентского JavaScript. |
| `katex` | Предоставляет локальные CSS и шрифты для разметки формул. Прямая зависимость фиксирует версию ресурсов, совпадающую с версией рендерера `rehype-katex`; это проверяет `npm run test:mdx`. |

## Инструменты проверки

Prettier с `prettier-plugin-astro`, ESLint с `typescript-eslint` и `eslint-plugin-astro`, Astro Check, Vitest и Playwright. Конфигурации находятся в корне проекта. Форматирование охватывает код и JSON, сохраняя документацию, MDX и макеты без изменений. Линтер проверяет JavaScript, TypeScript и Astro; проверка типов включает компоненты и остальные TypeScript-файлы.

| Зависимость | Назначение |
| --- | --- |
| `@astrojs/check` | Проверяет компоненты Astro, типы frontmatter и свойств компонентов. |
| `@types/node` | Описывает Node.js API для конфигурации и проверочных скриптов. |
| `prettier`, `prettier-plugin-astro` | Форматируют исходники, включая Astro-компоненты. |
| `eslint`, `@eslint/js`, `globals` | Проверяют JavaScript; задают стандартные правила и глобальные имена Node.js и браузера. |
| `typescript-eslint`, `eslint-plugin-astro` | Подключают правила и разбор TypeScript и Astro для ESLint. |
| `vitest` | Запускает unit-тесты в Node.js. |
| `@playwright/test` | Проверяет собранный сайт в Chromium, Firefox и WebKit. |

Vitest запускает только `tests/unit/**/*.test.ts`. Playwright запускает `tests/e2e/` на двух статических сборках — в корне и под `/audio-theory/`. Проверяются начальная страница, навигация, ресурсы и чтение без JavaScript; серверы принадлежат тестовому прогону. После подключения Pagefind сценарии поиска используют настоящий индекс. DOM проверяется средствами Playwright, отдельная среда компонентных тестов не подключена. Инструкции установки браузеров, полного прогона и исследования DOM находятся в [README](../README.md#проверки-кода-и-браузерные-тесты).

## Формат статей: MDX

Все статьи хранятся в файлах `.mdx`. Текст использует Markdown, визуализации и учебные блоки подключаются готовыми компонентами. HTML создаётся при сборке Astro. Поддержка MDX подключена через официальную интеграцию [@astrojs/mdx](https://docs.astro.build/en/guides/integrations-guide/mdx/) и обработчик `@astrojs/markdown-remark` с поддержкой remark/rehype. `npm run test:mdx` проверяет сборку, формулы и изоляцию служебных материалов из `tests/fixtures/mdx/` от публичного артефакта.

## Подсветка синтаксиса: Shiki

Используется встроенная поддержка Shiki в Astro для блоков кода в MDX. Подсветка создаётся при сборке и работает без клиентского JavaScript. Цвета связываются с `--syntax-*` и токенами фона и текста кода из дизайн-системы, чтобы следовать теме сайта. Язык указывается в разметке блока кода.

Настройка: [подсветка синтаксиса в Astro](https://docs.astro.build/en/guides/syntax-highlighting/).

## Визуальные ресурсы

Literata (400, 600, 400 italic), Golos Text (400–600) и JetBrains Mono (400) лежат в `src/assets/fonts/` в WOFF2 с кириллицей и латиницей; `src/styles/fonts.css` подключает их с `font-display: swap`, сборка кладёт файлы в `_astro/` с учётом базового пути. Иконки — Lucide (`lucide-static`, компонент `Icon.astro`, подключаются только используемые). Шрифты формул поставляются с KaTeX. Лицензии шрифтов (SIL OFL 1.1) и Lucide (ISC) лежат в `public/licenses/`.

## Аудиопримеры

Синтетические сигналы создаются через Web Audio в браузере; файлы используются для записей. Запуск — только по действию пользователя.
