# Технологический стек

Документ содержит выбранные и рассматриваемые технологии с их статусом. Требования к проекту находятся в [spec.md](spec.md), открытые вопросы — в [questions.md](questions.md).

## Поиск: Pagefind

**Статус: выбран.**

[Pagefind](https://pagefind.app/) — библиотека полнотекстового поиска для статических сайтов.

### Как работает

1. После сборки сайта Pagefind индексирует содержимое готовых HTML-страниц.
2. Файлы индекса и код поиска публикуются вместе с сайтом.
3. Браузер загружает нужные части индекса и выполняет поиск без серверной части.
4. Индекс пересоздаётся при каждой сборке перед публикацией сайта.

Описание процесса: [документация Pagefind](https://pagefind.app/docs/).

### Почему выбран

- Подходит для статического сайта без отдельного поискового сервиса.
- Есть готовый интерфейс поиска и возможность показывать результаты по разделам страниц.
- Поддерживает русский интерфейс и обработку основ русских слов для поиска по словоформам: [поддержка языков](https://pagefind.app/docs/multilingual/).

В начале реализации, до полной реализации попапа, нужно проверить реальный индекс на первых статьях: поиск по русскому тексту и словоформам, английским терминам на русскоязычных страницах и переходы к разделам. Также проверяются интеграция с Astro и базовый путь GitHub Pages. Интерфейс — собственный попап поверх JS API Pagefind, по [дизайн-системе](design-system.md#поиск), с проверкой светлой и тёмной тем.

## Формулы: KaTeX

**Статус: подключён.** KaTeX 0.16.47 рендерит формулы при сборке через `remark-math` 6.0.0 и `rehype-katex` 7.0.1. Вывод включает HTML и MathML; дополнительный обработчик ошибок останавливает сборку при неверной формуле. `strict: 'ignore'` допускает кириллицу, ошибки синтаксиса остаются обязательными; `trust: false` запрещает доверенные HTML-команды. CSS и шрифты входят в локальные ресурсы сборки, лицензия сохранена в `public/licenses/katex.txt`. Кириллица внутри `\text{}` оформляется шрифтом статьи.

## Статический генератор: Astro

**Статус: выбран.** Astro создаёт статические страницы при сборке для публикации на GitHub Pages. Интерактивные элементы работают в браузере. Дизайн-система задаёт CSS-токены и семантическую разметку независимо от генератора.

## TypeScript и зависимости

**Статус: подключены.** Начальный проект использует Astro 7.3.5 и TypeScript 6.0.3 со строгой конфигурацией `astro/tsconfigs/strict`. Поддерживаемые версии окружения — Node.js 22 (≥ 22.13.0), 24 или ≥ 26 и npm ≥ 9.6.5. Диапазон Node.js учитывает совместимость ESLint 10 и Vitest 5. Прямые зависимости закреплены точными версиями, дерево зависимостей — `package-lock.json`; для воспроизводимой установки используется `npm ci`. `just typecheck` запускает Astro Check для компонентов и `tsc --noEmit` для TypeScript. TypeScript 6 выбран по диапазонам совместимости Astro Check и typescript-eslint; TypeScript 7 ими пока не поддерживается.

### Назначение прямых npm-зависимостей

| Зависимость | Зачем подключена |
| --- | --- |
| `astro` | Создаёт HTML и ресурсы статического сайта; предоставляет сервер разработки и сборку для GitHub Pages без серверной части. |
| `typescript` | Проверяет типы кода и контрактов компонентов через `just typecheck`. |
| `@astrojs/mdx` | Официальная интеграция для статей в MDX: позволяет использовать Markdown и встраивать Astro-компоненты в текст. |
| `@astrojs/markdown-remark` | Подключает обработчик remark/rehype в Astro 7, необходимый для выбранных плагинов математической разметки; его настройки наследует MDX. |
| `remark-math` | Разбирает строчные `$…$` и блочные `$$…$$` формулы в дереве Markdown до генерации HTML. |
| `rehype-katex` | Преобразует разобранные формулы в HTML и MathML при сборке, чтобы они читались без клиентского JavaScript. |
| `katex` | Предоставляет локальные CSS и шрифты для разметки формул. Прямая зависимость фиксирует версию ресурсов, совпадающую с версией рендерера `rehype-katex`; это проверяет `npm run test:mdx`. |

## Инструменты проверки

**Статус: подключены.** Prettier 3.9.9 с `prettier-plugin-astro` 1.1.0, ESLint 10.11.0 с `typescript-eslint` 8.71.0 и `eslint-plugin-astro` 3.2.1, Astro Check 0.9.10, Vitest 5.0.3 и Playwright 1.63.0. Конфигурации находятся в корне проекта. Форматирование охватывает код и JSON, сохраняя документацию, MDX и макеты без изменений. Линтер проверяет JavaScript, TypeScript и Astro; проверка типов включает компоненты и остальные TypeScript-файлы.

| Зависимость | Назначение |
| --- | --- |
| `@astrojs/check` | Проверяет компоненты Astro, типы frontmatter и свойств компонентов. |
| `@types/node` | Описывает Node.js API для конфигурации и проверочных скриптов. |
| `prettier`, `prettier-plugin-astro` | Форматируют исходники, включая Astro-компоненты. |
| `eslint`, `@eslint/js`, `globals` | Проверяют JavaScript; задают стандартные правила и глобальные имена Node.js и браузера. |
| `typescript-eslint`, `eslint-plugin-astro` | Подключают правила и разбор TypeScript и Astro для ESLint. |
| `vitest` | Запускает unit-тесты в Node.js. |
| `@playwright/test` | Проверяет собранный сайт в Chromium, Firefox и WebKit. |

Vitest запускает только `tests/unit/**/*.test.ts`. Playwright запускает `tests/e2e/` на двух статических сборках — в корне и под `/audio-theory/`. Проверяются начальная страница, навигация, ресурсы и чтение без JavaScript; серверы принадлежат тестовому прогону. После подключения Pagefind сценарии поиска используют настоящий индекс. DOM проверяется средствами Playwright, отдельная среда компонентных тестов не подключена. Инструкции установки браузеров, полного прогона и исследования DOM находятся в [README](../README.md#проверки-кода-и-браузерные-тесты).

## Формат статей: MDX

**Статус: подключён.** Все статьи хранятся в файлах `.mdx`. Текст использует Markdown, визуализации и учебные блоки подключаются готовыми компонентами. HTML создаётся при сборке Astro. Поддержка MDX подключена через официальную интеграцию [@astrojs/mdx](https://docs.astro.build/en/guides/integrations-guide/mdx/) 8.0.2 и обработчик `@astrojs/markdown-remark` 7.3.0 с поддержкой remark/rehype. `npm run test:mdx` проверяет сборку, формулы и изоляцию служебных материалов из `tests/fixtures/mdx/` от публичного артефакта. Коллекция статей и её схемы добавляются позднее.

## Подсветка синтаксиса: Shiki

**Статус: выбран.** Используется встроенная поддержка Shiki в Astro для блоков кода в MDX. Подсветка создаётся при сборке и работает без клиентского JavaScript. Цвета связываются с `--syntax-*` и токенами фона и текста кода из дизайн-системы, чтобы следовать теме сайта. Язык указывается в разметке блока кода.

Настройка: [подсветка синтаксиса в Astro](https://docs.astro.build/en/guides/syntax-highlighting/).

## Визуальные ресурсы

**Статус: выбраны в составе дизайна.** Literata, Golos Text и JetBrains Mono размещаются на сайте в WOFF2 с кириллицей и латиницей; иконки — Lucide. Шрифты формул поставляются с KaTeX. При подключении ресурсов сохраняются их лицензии.

## Аудиопримеры

**Статус: выбран подход.** Синтетические сигналы создаются через Web Audio в браузере; файлы используются для записей. Запуск — только по действию пользователя.
