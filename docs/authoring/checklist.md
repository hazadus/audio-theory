# Чеклист материала

Применять вместе с [правилами](rules.md), перед передачей автору и после доработок. Проверить каждый применимый пункт; результаты, причины неприменимости и оставшиеся препятствия кратко сообщить автору в ответе. Отдельные документы с отчётом о проверках не создавать. Невыполненная обязательная проверка блокирует завершение; неприменимость не заменяет проверку. Числовые рекомендации оцениваются редакционно и не блокируют материал.

## Выбор и объяснение

- [ ] Изучены существующие статьи, [темы](../topics.md), связи и глоссарий. Выбор дополнения или новой статьи обоснован, дублирования нет.
- [ ] Объяснение соответствует уточнениям пользователя, по умолчанию начинается с основ; понятия и предварительные знания позволяют читать статью самостоятельно.
- [ ] Математические инструменты сверены со статьёй [«Математика для аудио»](../../src/content/articles/audio-math.mdx): новые объяснены в ней с примером и условиями, для уже объяснённых добавлена ссылка на нужный раздел; дополнения включены в проверки и авторскую приёмку.
- [ ] Русский текст и английское название основного термина при первом упоминании; термины, обозначения и единицы последовательны.
- [ ] Просмотрен [список рекомендуемых источников](sources.md); найденные полезные и изученные источники добавлены с описанием тем.
- [ ] Скачанные ценные материалы сохранены в `scratch/books/` и описаны в [каталоге](books.md).
- [ ] Прочитаны подтверждающие источники, проверены факты, условия, определения, формулы, расчёты и граничные случаи; данные и заимствования имеют источник и допустимое использование.
- [ ] Весь изменённый текст, подписи и определения проверены по актуальному [tropes.md](https://tropes.fyi/tropes-md), а при недоступности сайта — по [локальной копии](tropes.md); русскоязычные шаблоны исправлены без потери точности.
- [ ] Рекомендации по тегам, врезкам и длине кода рассмотрены; превышение не превращено в запрет. Необязательные разделы и интерактивность добавлены по смыслу.

## Контент и связи

- [ ] MDX и импорты `@/`; обязательные `slug`, `title`, `question`, `topic`, `tags`, `related` заполнены по контракту. Группа существует, новый `slug` уникален, `readingMinutes` при наличии — положительное целое. `updated` отсутствует.
- [ ] Теги взяты из словаря `src/data/tags.ts` по [правилам](rules.md#теги): описывают сквозные темы, которые статья объясняет или заметно использует, рекомендуется 1–3 (четвёртый — по необходимости), от главного к второстепенному; `cpp-juce` стоит при примерах C++/JUCE. Новый тег объединяет хотя бы две статьи, не повторяет существующий и показан автору; подходящие существующие статьи предложено дополнить.
- [ ] Источники в `## Источники {#sources}` содержат хотя бы одну проверенную ссылку. Внешние страницы открыты отдельно: сборка их не проверяет.
- [ ] Связи имеют `label`, `description`, `target`; внутренние статьи, якоря и ресурсы существуют, для отсутствующей темы выбрана соответствующая Википедия. Нет глобального порядка «предыдущая / следующая».
- [ ] Якоря английские и стабильные, H2/H3 образуют оглавление, H4 не включён; `id` уникальны. Логические URL не содержат префикс; в HTML `base` добавлен один раз.
- [ ] При дополнении `slug`, явные якоря и `id` сравнены с исходной версией: прежние адреса сохранены, включая переименованные разделы. Удаление раздела или изменение маршрута, если требуется задачей, согласовано и проверено отдельно.
- [ ] Заметки `MarginNote`, если добавлены: один абзац в слоте и 1–3 ссылки с непустыми названиями и пояснениями; для раздела «Статья → раздел». Цели и пояснения соответствуют содержимому. Заметки не заменяют нужные ссылки в тексте, `Term` и итоговые связи.
- [ ] Для новой статьи или новых разделов просмотрены все существующие статьи: в абзацах, вопрос которых подробно разбирает новый материал, добавлены заметки «Подробнее» на него (без дублирования ссылок в тексте), заменены временные ссылки на Википедию; список затронутых мест передан автору.
- [ ] Используемые компоненты существуют и соответствуют текущему API. Номера рисунков/визуализаций, таблиц и формул идут по своим последовательностям, ссылки совпадают.
- [ ] Новые обозначения формул пояснены с единицами; MathML доступен, длинная формула прокручивается внутри блока.
- [ ] Рисунки имеют название, описание и содержательную подпись; таблицы — `caption`, заголовки и `scope`; серии различимы без опоры только на цвет, оси и единицы читаются.
- [ ] Подписи статичных SVG измерены на 320 и 1440 px: 12–16 px, без пересечений и выхода за рамку; `font-size` стоит на группах, ширина ограничена по [правилу кегля](../design-system.md#кегль-статичного-svg).
- [ ] Врезки различимы текстом и оформлением, ошибка содержит «Неверно / Верно», самопроверка раскрывается клавиатурой и без JS.
- [ ] Каждый листинг имеет язык; пример проверен, подсветка работает в обеих темах без JS, копируется весь исходный текст. Отказ clipboard не сообщает успех и позволяет выделить код вручную.
- [ ] Глоссарий и `Term` используют одну запись с коротким определением без HTML и существующей целью; подсказка доступна фокусом и касанием, закрывается по Esc, основная ссылка работает.

## Журнал обновлений

- [ ] Новая статья имеет одну запись «Новое» с кратким описанием и 0–4 пунктами; дополнение опубликованной статьи — запись «Дополнено» с 1–4 пунктами, ведущими на изменённые места. Для исправления опечатки, форматирования и технических правок записи нет.
- [ ] `id` уникален и совпадает с именем файла, `date` — день публикации по `Europe/Moscow`, `order` уникален в пределах дня. Цели (статья, якорь, термин) существуют; `just build` проходит.
- [ ] Запись показана автору вместе с материалом и войдёт в тот же коммит только после одобрения.

## Треки

- [ ] Прочитаны все `src/content/tracks/*.json`; применимость новой или дополненной статьи (целиком или раздела) к каждому из пяти маршрутов оценена, предложение автору названо конкретно (трек, этап, позиция, цель, «по желанию», пояснение) либо указано, что подходящего маршрута нет. Статья в трек автоматически не добавлена.
- [ ] Существующие `slug` треков, `id` этапов и элементов и якоря статей, на которые ссылаются цели, сохранены; цели `{ article, anchor? }` существуют, повторов цели, пустых этапов и неопубликованных материалов нет.
- [ ] Для созданного трека есть запись «Новое» с `summary`, для содержательного изменения состава, порядка или пояснений — «Дополнено» с 1–4 пунктами `{ track, anchor: stage-<id> }`; для опечатки, форматирования и правки статьи без смены маршрута записи о треке нет. Запись трека отделена от записи статьи.
- [ ] Состав, пояснения этапов и запись журнала просмотрены на `/tracks/<slug>/` и на странице затронутой статьи (блок «В треках», блок по `?track=<slug>&item=<id>`); `just build` проходит, при изменении схемы или загрузки — `npm run test:tracks`.
- [ ] Автор получил URL треков и записи и явно одобрил их до включения в коммит.

## Проверки сайта

- [ ] Применимые `just fmt`, `npm run fmt:check`, `just lint`, `just typecheck`, `just test` выполнены; новая предметная логика подтверждена осмысленными unit-тестами.
- [ ] `just build` прошёл (до коммита новой статьи — с `ALLOW_DRAFT_ARTICLES=1`): метаданные, формулы, контент, внутренние страницы/якоря/ресурсы и Pagefind. «Черновик» виден только в локальном режиме; публикуемая сборка использует настоящую Git-дату и полную историю.
- [ ] При изменении MDX/формул выполнен `npm run test:mdx`, схемы/маршрутов — `npm run test:articles`; при изменении критичного пути, доступности или адресов — полный `just test-e2e`, включая корень и префикс. Поиск проверен по настоящему индексу, когда затронута индексация.
- [ ] Локальное чтение в обеих темах на 390 и 1440 px и без JS проверено; широкие блоки также на 320 px. Страница не прокручивается горизонтально; ссылки и ресурсы учитывают `base`.
- [ ] Для изменённого UI проверены состояния, клавиатура, фокус, увеличение текста/масштаба и границы 599/600, 1023/1024, 1279/1280 px из дизайн-системы. Создание снимков сопровождается просмотром.

- [ ] Для заметок просмотрены обе темы на 320, 390, 1279, 1280 и 1440 px, печать, увеличенный текст/масштаб, клавиатурные переходы и работа без JS. Верх справа совпадает с абзацем; соседние заметки и широкие блоки не перекрываются, оглавление свободно; на узком экране и при печати заметка на поверхности под абзацем, порядок DOM сохраняется.

- [ ] Ошибка Web Audio объясняется и не ломает график; клавиши плеера не мешают полям и ползункам.
- [ ] `SamplingDemo`: смена частоты дискретизации останавливает звук и сбрасывает позицию, следующий запуск звучит с новой частотой результата; переключение видимой синусоиды звук не прерывает. «Сбросить» возвращает 8 000 Гц, видимую синусоиду, позицию 0, громкость 30 % и включённый звук. Перетаскивание касанием не прокручивает страницу. Автоматически — `tests/unit/lfo.test.ts` и `tests/e2e/lfo-demo.spec.ts` в `just test-e2e`.
