# Стиль кода C++

Правила для примеров на C++ в статьях «Теории аудио». Основа — [JUCE Coding Standards](https://juce.com/blog/coding-standards/): читатель сайта пишет плагины на JUCE и видит этот стиль в исходниках фреймворка. Дополнения учитывают недостатки учебного кода, разобранные в [рецензии WolfSound на книгу Уилла Пиркла](https://thewolfsound.com/designing-audio-effect-plugins-in-cpp-by-will-pirkle-book-review/): голые `new`, массивы C, отсутствие `const` и `constexpr`, лишние специальные функции-члены, геттеры с побочным эффектом, числа без единиц. Отступления от JUCE перечислены [в конце](#отступления-от-juce). Общие правила подготовки материалов — в [rules.md](rules.md), проверка — в [чеклисте](checklist.md).

## Область применения

- Правила действуют для собственных примеров сайта: листингов, фрагментов и однострочных иллюстраций в fenced-блоках `cpp`.
- Цитата из чужого кода сохраняет текст и оформление источника. Сейчас это фрагменты [tremolo-juce-course](https://github.com/juce-framework/tremolo-juce-course) (clang-format в стиле Chromium: 2 пробела, скобка на строке объявления) и исходников JUCE. Источник назван в тексте рядом с листингом или в комментарии первой строки (`// PluginProcessor.cpp`). Сокращение `// ...` и учебная ошибка, построенная на цитате, остаются в стиле источника.
- Код в обычном тексте (`std::span`, `processBlock()`) пишется так же, как в листинге того же происхождения.

## Стандарт языка

- Примеры написаны на C++23 и собираются с `-std=c++23` без расширений компилятора. Расширение допустимо, только когда статья объясняет его, например `[[clang::nonblocking]]` для RealtimeSanitizer.
- Использовать средства стандартной библиотеки вместо старых приёмов: `std::numbers::pi` вместо `M_PI`, `std::array`, `std::vector` и `std::span` вместо массивов C и пары «указатель и длина», `std::bit_cast` вместо `memcpy` и `union` для переинтерпретации, `std::clamp`, `std::complex`, алгоритмы `std::copy` и `std::fill` там, где они короче цикла. Пару «указатель и длина» оставлять, если её требует API JUCE или пример о ней.
- Возможности C++14–C++23 при первом упоминании в тексте статьи получают пометку стандарта в скобках: «`std::span` (C++20)», «назначенные инициализаторы (C++20, designated initializers)». Возможности C++11 помечаются, когда это нужно для чтения старого кода или сравнения. Сравнение со старым поведением записывается как «до C++17». Пометки нужны в тексте, а не в комментариях кода.

## Форматирование

- Отступ — 4 пробела, без табуляции. Фигурные скобки в стиле Allman: открывающая на отдельной строке. Короткое тело метода в одну строку допустимо: `void reset() noexcept { phase = 0.0; }`.
- Пробел перед открывающей круглой скобкой вызова, объявления и условия, если внутри что-то есть: `std::sin (phase)`, `if (gain > 0.0f)`. Пустые скобки без пробела: `reset()`. Индекс без пробела: `buffer[index]`.
- Перед `{` инициализации ставится пробел, внутри непустых фигурных скобок — пробелы: `WhiteNoise white { 2026 };`, `std::array<float, 16> rows {};`, `std::complex<float> z { 3.0f, 4.0f };`.
- Пробелы вокруг бинарных операторов, после запятой и после `!`: `if (! voice.isActive())`. У `++` и `--` пробела нет. В объявлении оператора пробел перед скобкой: `bool operator== (Gain other) const`.
- `*` и `&` прижимаются к типу: `const float* samples`, `juce::AudioBuffer<float>& buffer`. Одно объявление указателя или ссылки на строку. `const` стоит перед типом: `const Parameters& parameters`.
- Шаблоны: `template <typename SampleType>` с пробелом перед `<`, `std::vector<float>` без пробела.
- Простое тело `if`, `for`, `while` в одну строку пишется без скобок на следующей строке. Многострочное тело или длинное условие получают скобки. В цепочке `if … else` все ветви оформлены одинаково: либо все со скобками, либо все без них. `if` вместе с телом на одной строке не пишется.
- Перенос длинного выражения начинается с оператора или точки на новой строке: `+ g.sub * sub.nextSample()`, `.withSampleRate (sampleRate)`. Жёсткого предела длины строки нет; ориентир — 100 символов, чтобы листинг читался без горизонтальной прокрутки.
- Пустая строка отделяет смысловые шаги функции и следует за закрывающей скобкой блока, если дальше не другая `}`.
- Лямбда: короткая — в одну строку `[] (double phase) { return std::sin (phase); }`; многострочная открывает тело на новой строке, как обычный блок. Пустой список параметров не пишется: `[this] { … }`.
- Литералы: у числа с плавающей точкой есть цифра до и после точки (`0.0f`, `1.0`, не `0.f` и `.5`); шестнадцатеричные — в нижнем регистре (`0xffu`); суффикс `u` у беззнаковых констант в битовых операциях.

## Имена

- Классы, структуры, перечисления и псевдонимы типов — `CamelCase` с заглавной: `DelayLine`, `NoiseColour`. Функции, методы, переменные и поля — `camelCase` со строчной: `nextSample`, `writeIndex`. Значения `enum class` — `camelCase`: `WaveShape::sine`.
- Без венгерской нотации и префиксов: не `m_gain`, не `gain_`, не `fGain`. Имя называет назначение, а не тип.
- Параметр шаблона называется словом: `SampleType`, `Object`, а не `T`.
- Однобуквенное имя допустимо, если оно повторяет обозначение из формулы или текста статьи: `x`, `y`, `n`, `k`, `a`, `g`, `t`, `dt`. В остальных случаях имя — слово: `bytes`, а не `b`; `parameters`, а не `p`; `frequency`, а не `f`. Исключение — примеры механики языка без предметного смысла объекта, например `a` и `b` при демонстрации передачи владения.
- Величина с единицей несёт единицу в имени (`delaySeconds`, `cutoffHz`, `latencySamples`, `durationMs`) или в комментарии при объявлении (`double cutoff = 2000.0; // частота среза, Гц`). Для нового кода предпочтительно имя. Типы-обёртки для единиц в учебных фрагментах не вводятся: они добавляют строки, которые не относятся к теме статьи.
- Макросы — `ALL_CAPS` с префиксом проекта; свои макросы в примерах не определяются.
- В тексте различать класс и объект: `Lfo` — класс, `lfo` — его объект. Окно фон Ханна называется окном Ханна (Hann), не Hanning.

## Типы и константность

- Всё, что не меняется после инициализации, объявляется `const`; метод, который не меняет объект, — `const`. Константы времени компиляции — `constexpr` (`static constexpr` в классе), не `#define`.
- `auto` — почти всегда, когда тип виден из правой части или не важен для объяснения. Не использовать `auto` с литералом, тип которого неочевиден: `auto count = 0` хуже, чем `int count = 0`; `auto gain = 0.5f` допустимо.
- Целые фиксированного размера — `std::int16_t`, `std::uint32_t`, `std::int64_t` из `<cstdint>` или `juce::int64` и подобные в коде с JUCE. Без `long long` и одиночного `unsigned`. Индексы — тип API: `int` для `juce::AudioBuffer`, `std::size_t` для контейнеров стандартной библиотеки.
- Преобразования типов — только именованные: `static_cast` для чисел и иерархии классов, `std::bit_cast` или `reinterpret_cast` для переинтерпретации байтов. C-форма `(int) x` и функциональная `int (x)` не используются.
- Нулевой указатель — `nullptr`; проверка явная: `if (reader != nullptr)`. Указатель, который может быть пустым, объявляется в наименьшей области: `if (auto* next = toAudio.pop())`.
- Перечисления — `enum class`.
- Небольшие значения (числа, `juce::Point`, `juce::Range`, структуры из нескольких чисел) передаются по значению; крупные объекты — по `const&`, изменяемые — по ссылке.
- Математика — функции `std::`: `std::abs`, `std::sqrt`, `std::sin`, а не `fabs` и `sinf`.

## Владение и время жизни

- Сначала поле класса (композиция), затем `std::unique_ptr` через `std::make_unique`. Голые `new` и `delete` не пишутся. Исключения: API JUCE, которое забирает сырой указатель (`createPluginFilter`, `addParameter`), — с комментарием о владельце; примеры, тема которых — ручное владение, его ошибки или передача указателя через lock-free очередь.
- Буферы — `std::vector`, `std::array` или `juce::AudioBuffer`; не `new[]`, `malloc` и не `std::unique_ptr<float[]>`.
- Правило нуля: не объявлять конструкторы, деструктор и операторы присваивания, которые компилятор сгенерирует сам. Инициализация полей — значениями по умолчанию при объявлении. Запрет копирования — `= delete` или `JUCE_DECLARE_NON_COPYABLE` в конце класса.
- Изменяемые глобальные и `static` переменные не используются. Фрагмент, в котором поле класса показано без самого класса, отмечается комментарием (`// поле процессора`).
- Код аудиопотока не выделяет память, не блокирует и не обращается к диску: выделение — в `prepare` или `prepareToPlay`, подробности — в статье [«Код аудиопотока»](../../src/content/articles/cpp-audio-thread.mdx).

## Классы и функции

- Порядок: `public` (сначала конструкторы и деструктор), `protected`, `private`. Поля — после всех открытых и защищённых методов; закрытые методы — в конце класса, после полей.
- `struct` — для типов, у которых всё открыто; `class` — при закрытом состоянии.
- Наследование с явным модификатором доступа: `class MixBypassProcessor : public juce::AudioProcessor`.
- Переопределение помечается `override` без `virtual`. Конструктор с одним аргументом — `explicit`. Методы, которые не бросают исключений, особенно на пути обработки звука, — `noexcept`.
- Геттер не меняет состояние объекта и объявлен `const`. Метод, который продвигает состояние, называется глаголом: `nextSample()`, а не `getSample()`.
- Параметры, которые задаёт пользователь, отделены от состояния, которое меняется на каждом отсчёте: отдельная структура или отдельная группа полей с комментарием.
- Функция решает одну задачу; повторяющийся код выносится в функцию, если это сокращает пример (DRY).
- Предусловия проверяются `assert` (или `jassert` в коде с JUCE) на входе метода; ошибки входных данных в функциях разбора файлов — исключениями стандартной библиотеки.

## Комментарии

- Комментарии на русском, `//` с пробелом после. Документирующие комментарии Doxygen в примерах не нужны.
- Законченный листинг (класс, функция, программа) начинается с комментария-заголовка: что делает код и какое ограничение важно. Короткому фрагменту в 1–3 строки заголовок не нужен.
- Комментарий называет единицы, формулу, условие или причину, а не пересказывает строку: `// y[n] = y[n-1] + a·(x[n] - y[n-1])`, `// FileOutputStream дописывает в конец существующего файла`.
- Строка, которая показывает ошибку, помечена комментарием с её последствием: `// утечка: delete не выполнится`, `// ошибка компиляции: копировать нельзя`.
- Закомментированный код допустим только как вариант для сравнения и оформляется `//`.

## Проверка примера

- Пример без JUCE с `main` компилируется и запускается: `clang++ -std=c++23 -Wall -Wextra -pedantic`. Фрагмент без `main` проверяется в минимальной обёртке с нужными объявлениями.
- Пример с JUCE проверяется сборкой или `-fsyntax-only` против модулей той версии JUCE, которая названа в статье. Если проверка недоступна, это сообщается автору и не выдаётся за пройденную.
- Вывод программы в статье (числа, сообщения санитайзера с номерами строк) совпадает с текущим текстом листинга.

## Отступления от JUCE

| Правило JUCE | На сайте | Причина |
| --- | --- | --- |
| C-приведения допустимы для простых числовых типов | Только `static_cast` | Читатель учебника видит явное преобразование; один способ вместо двух |
| Пустая строка перед каждым `if`, `for`, `while` после другой инструкции | Пустая строка между смысловыми шагами | Короткие листинги и так разбиты на шаги; лишние строки удлиняют их без новой информации |
| Индексы контейнеров — `int` | Тип индекса из API: `int` для JUCE, `std::size_t` для `std` | Без лишних преобразований на границе API |
| Осмысленные имена переменных | Однобуквенные имена допустимы для обозначений из формул | Код читается рядом с формулами статьи |
| Строки и типы JUCE (`String`, `StringRef`, `HeapBlock`) | Типы стандартной библиотеки в примерах без JUCE | Пример без JUCE собирается одним компилятором |
