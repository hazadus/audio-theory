# Коммит изменений

Закоммитить текущие staged, unstaged и untracked изменения по [стайлгайду](../../../docs/styleguide.md) с учётом [правил проверки и публикации](../../../docs/spec.md#проверка-и-публикация).

## Шаги

1. **Осмотреть изменения**
   - Проверить `git status`, `git diff`, `git diff --staged` и содержимое новых файлов. Выяснить, какие изменения связаны между собой и какие проверки для них нужны.

2. **Проверить затронутое**
   - Сборка сайта уже доступна: `just build` вызывает `npm run build` и создаёт статические файлы в `dist/`. Выполнять её при изменениях приложения или конфигурации сборки.
   - `just build` также строит `dist/pagefind/` и проверяет локальные ссылки, HTML-якоря и ресурсы HTML/CSS без сетевой проверки внешних адресов; ошибка останавливает сборку. Фактические `base` и `outDir` учитываются при переопределении из CLI. Поиск по настоящему индексу проверяется полным `just test-e2e`; dev-сервер индекс не строит. Ручная проверка API на собранном сайте описана в [README](../../../README.md#поисковый-индекс-и-проверка-артефакта).
   - При изменении обработки MDX, формул или их ресурсов выполнить `npm run test:mdx`: проверка собирает служебные материалы из `tests/fixtures/mdx/`, подтверждает MathML и локальные ресурсы, ошибку неверной формулы и отсутствие тестовых страниц в публичной сборке. Просмотр тестовой страницы описан в [README](../../../README.md#проверка-mdx-и-формул).
   - При изменении схемы статей, групп или маршрутов выполнить `npm run test:articles`: проверка собирает служебные статьи из `tests/fixtures/articles/`, подтверждает маршрут из `slug`, отказ при повторном `slug`, неизвестной группе, пустых полях и неверном `readingMinutes`, отсутствие служебных статей в публичной сборке.
   - Для кода использовать существующие рецепты корневого `justfile`: `just fmt`, `just lint`, `just typecheck`, `just test`, `just build` по характеру изменений. После форматирования проверить `npm run fmt:check`; пропущенную проверку не выдавать за успешную.
   - При изменении критичного пользовательского пути, доступности элементов или обработки адресов выполнить полный `just test-e2e`; отдельный файл не заменяет полный прогон. При изменении поведения сначала обновить относящиеся к нему тесты. Для интерфейса выполнить требуемую задачей браузерную или визуальную проверку.
   - Документация и инструкции без изменения кода не требуют сборки и тестов приложения. Проверить ссылки, актуальность описанного поведения и согласованность со [спецификацией](../../../docs/spec.md). Статьи MDX и определения глоссария требуют проверки контента и сборки.
   - Для материалов изучить существующие статьи и [темы](../../../docs/topics.md), избегать дублирования и соблюдать контракты метаданных, ссылок и учебных компонентов из спецификации. Материалы — на русском с английским названием основного термина при первом упоминании. Проверить источники, термины, формулы и расчёты; выполнить редакционную проверку по tropes.md до передачи автору. Использовать общий набор правил `docs/authoring/`, когда они созданы; до этого руководствоваться спецификацией.
   - Новые статьи до коммита собирать в локальном режиме с состоянием «Черновик»; опубликованная сборка требует настоящей Git-даты. Проверить метаданные, внутренние ссылки и якоря; требования к Git-датам в CI не обходить.
   - При падении применимой проверки исправить причину и повторить её. Если обязательная проверка невозможна, сообщить о препятствии и не коммитить непроверенную работу.

3. **Подготовить коммиты**
   - Статьи, изменения их текста, определения глоссария и текст «О проекте» включать только после локальной проверки и явного одобрения автором. Вызов скилла не заменяет авторскую проверку; уже полученное одобрение текущих правок действует. Неодобренные материалы оставить вне коммита; независимые проверенные изменения можно закоммитить.
   - Разделить несвязанные правки на отдельные логические коммиты. Проверить, что новая переменная окружения описана в `.env.example`, а связанные документы и `README.md` обновлены, если этого требуют правила проекта.
   - Сообщение составить по разделу «Git: сообщения коммитов» [стайлгайда](../../../docs/styleguide.md): русский текст, разрешённый тип, необязательный `scope`, тема не длиннее 72 символов, без точки и трейлеров об инструментах. Номер пункта `docs/todos.md` в сообщение не добавлять.
   - Добавлять конкретные пути через `git add <путь>`. Не включать секреты, локальные `.env`, зависимости, тестовые данные и артефакты сборки.

4. **Закоммитить и проверить**
   - Создать новый коммит без `--no-verify` и без изменения предыдущего коммита. Проверить состав и сообщение через `git log -1 --stat`, затем состояние рабочего дерева.

Не пушить без явной просьбы пользователя или требования выбранной задачи. Этот скилл создаёт локальный коммит; порученную публикацию выполнять отдельным процессом по [инструкции по CI и деплою](../../../docs/deploy.md).

Использование: `$commit`

## Адреса при локальной проверке

Конфигурация `src/site.config.ts` задаёт стандартный базовый путь `/audio-theory/`. Фоновый Astro может сообщать только origin без префикса: открывать сайт по origin и фактическому `base`, добавляя его ровно один раз. Для проверки корневого размещения использовать параметр `--base /` при запуске и сборке (`npm run build -- --base /`). Служебный маршрут MDX — `<origin><base>__test/mdx/`. Построитель `withBase` и обычные MDX-ссылки используют фактический базовый путь, включая переопределение из CLI.

## Браузерные проверки и DOM

`just test-e2e` последовательно собирает сайт в `.e2e/root/` и `.e2e/prefixed/`, затем запускает Playwright в Chromium, Firefox и WebKit. Перед первым запуском установить браузеры: `npx playwright install chromium firefox webkit` (для Linux CI — `npx playwright install --with-deps chromium firefox webkit`). Playwright управляет своими preview-серверами на 4391 и 4392; `--ignore-lock` оставляет их в foreground без общего lock-файла Astro, а `reuseExistingServer: false` запрещает использовать чужой сервер. Занятый порт означает ошибку проверки.

Сценарии DOM находятся в `tests/e2e/`, unit-тесты — в `tests/unit/`. Для исследования DOM доступны `page.locator()`, `page.getByRole()` и `page.evaluate()`; для снимка — `page.screenshot()`. Снимки и trace смотреть локальными средствами агента; WebKit не заменяет ручную проверку Safari. `just test-production https://hazadus.github.io/audio-theory/` проверяет опубликованную начальную страницу и ресурсы; передавать фактический публичный URL с базовым путём. Параметры описаны в [инструкции по деплою](../../../docs/deploy.md#проверка-опубликованного-сайта). Команда не публикует сайт; при отдельно порученной публикации запускать после успешного деплоя нужного SHA. `just screenshots` ещё не реализован: следовать критерию соответствующей задачи и не считать его пройденным.
