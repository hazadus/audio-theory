# Выполнение пункта плана

Довести указанный пользователем пункт до проверенного результата. Выполнять именно этот пункт, а не весь этап.

## Шаги

1. **Прочитать задачу и правила**
   - Найти номер и его `Проверка:` в [задачах](../../../docs/todos.md); сверить зависимости и цель с [планом](../../../docs/plan.md).
   - Прочитать [правила репозитория](../../../AGENTS.md). Для изменения поведения свериться со [спецификацией](../../../docs/spec.md) и [дизайн-системой](../../../docs/design-system.md); открытые продуктовые решения — в [вопросах](../../../docs/questions.md).
   - Если номер отсутствует или решение невозможно вывести из документов, запросить нужное уточнение. Выбор способа реализации сделать самостоятельно.

2. **Реализовать пункт**
   - Размещать код по [структуре проекта](../../../docs/structure.md); соблюдать [стайлгайд](../../../docs/styleguide.md) и [дизайн-систему](../../../docs/design-system.md).
   - «Теория аудио» — статический сайт Astro с MDX, KaTeX, Shiki и Pagefind на GitHub Pages. Основной HTML создаётся при сборке, интерактивные элементы работают в браузере; ссылки и ресурсы учитывают базовый путь размещения. Демонстрационный рантайм макетов в приложение не переносится. Учитывать статусы инструментов в [техническом стеке](../../../docs/techstack.md).
   - Добавлять только нужные для пункта каталоги и зависимости. Новую переменную окружения описать в `.env.example` вместе с её первым использованием; секреты не записывать в Git.
   - После изменения кода сверить связанные документы с фактическим поведением и обновить устаревшие. Обновить `README.md`, если изменились статус, состав документов, требования к окружению или команды разработки.

3. **Проверить результат**
   - Для локальной проверки запускать из корня `just dev --host 127.0.0.1 --port 4321`. Фактический URL брать из вывода Astro: строка `Local` в обычном терминале или сообщение `Dev server running at` при фоновом запуске. Занятый порт может изменить адрес. В Codex запускать через `exec_command` с `tty: true`, сохранить `session_id`; читать вывод через `write_stdin`. Если процесс остался в сессии, остановить его через `Ctrl-C` (`\u0003`) в этой сессии и проверить завершение. Astro 7 автоматически запускает сервер агента в фоне и завершает команду: тогда сохранить PID и URL из вывода, проверить их через `npm run dev -- status`, читать логи через `npm run dev -- logs`. Перед остановкой снова сверить PID и URL через `status` с сохранёнными и только при совпадении выполнить из того же корня `npm run dev -- stop`, затем проверить `status`. Совместимый уже запущенный сайт можно использовать повторно; чужие процессы не останавливать и не заменять через `--force`. После своей проверки останавливать только собственный процесс; на время ожидаемой авторской проверки оставить его доступным. Не использовать массовые `pkill` или `killall`.
   - Статическую сборку проверять через `just build` (вызывает `npm run build`, результат — `dist/`). Сейчас доступны `just`, `just dev`, `just build`; остальные рецепты проверок добавляются в следующих пунктах и пока не считаются пройденными.
   - Выполнить именно проверку `Проверка:` из выбранного пункта, включая браузерную, редакционную, авторскую, CI или production-проверку, когда она там требуется.
   - Запустить подходящие проверки существующего приложения: `just fmt`, `just lint`, `just typecheck`, `just test`, `just build`. Для затронутого критичного пользовательского пути после появления сценариев выполнить полный `just test-e2e`; отдельный файл не заменяет полный прогон. Новую предметную логику подтвердить осмысленными unit-тестами.
   - В ранних задачах `justfile` и часть тестов ещё только создаются: отсутствующую команду не считать пройденной, а следовать проверке пункта и запускать доступную прямую команду. Если проверка зависит от ещё не созданного сценария, соблюдать указанную в задаче последовательность.
   - Для материалов изучить существующие статьи и [темы](../../../docs/topics.md), избегать дублирования и соблюдать контракты метаданных, ссылок и учебных компонентов из спецификации. Материалы — на русском с английским названием основного термина при первом упоминании. Проверить источники, термины, формулы и расчёты; выполнить редакционную проверку по tropes.md до передачи автору. Использовать общий набор правил `docs/authoring/` и скилл `$write-article`, когда они созданы; до этого руководствоваться спецификацией.
   - Новые статьи до коммита собирать в локальном режиме с состоянием «Черновик»; опубликованная сборка требует настоящей Git-даты. Проверить метаданные, внутренние ссылки и якоря; требования к Git-датам в CI не обходить.
   - Для визуализаций и аудио проверить численные и граничные случаи, согласованность графика и звука, запуск действием пользователя и остановку при уходе со страницы. Необходимую ручную проверку в настоящем Safari на Mac и iPhone не заменять WebKit-тестами.
   - При изменении интерфейса посмотреть результат в браузере в состояниях и размерах из задачи и дизайн-системы. Исправить обнаруженные ошибки и повторить соответствующую проверку.

4. **Завершить**
   - Новые статьи, изменения их текста, определения глоссария и текст «О проекте» перед коммитом дать автору проверить на локальном сайте и доработать до явного одобрения. Уже полученное одобрение текущих правок действует; отсутствие ответа одобрением не считать.
   - Если обязательная проверка не прошла или недоступна, не отмечать задачу выполненной и не коммитить; назвать препятствие и уже проверенный результат.
   - После успешной проверки отметить пункт в `docs/todos.md` и закоммитить по скиллу `$commit`. Номер задачи в сообщение коммита не добавлять.
   - Не пушить для обычной локальной задачи. Если выбранный пункт прямо требует пуша или публикации, выполнить их в его границах после необходимых проверок и авторского одобрения материалов. Публикация выполняется пушем в основную ветку без обязательного PR; проверить CI и деплой GitHub Pages, затем выполнить доступный `just test-production`. Технический каркас можно публиковать до готовности всех статей; неодобренные материалы в публикуемый коммит не включать.

## Итог

Использование: `$execute 4`
