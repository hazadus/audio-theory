# Теория аудио

Личный учебник по теории аудио и цифровой обработке звука: самостоятельные статьи, визуализации и интерактивные примеры. Материалы пишутся на русском с английскими названиями основных терминов. Статический сайт предназначен для публикации на GitHub Pages.

## Разработка

Нужны Node.js ≥ 22.12.0, npm ≥ 9.6.5 и [just](https://just.systems/). Зависимости зафиксированы в `package.json` и `package-lock.json`; установка из чистого checkout:

```sh
npm ci
```

Запуск из корня проекта:

```sh
just dev
```

Возьмите адрес из вывода Astro: строка `Local` в обычном терминале или сообщение `Dev server running at` при фоновом запуске. Фоновое сообщение может содержать только origin; добавьте фактический базовый путь `/audio-theory/` ровно один раз (обычно сайт открывается по `http://localhost:4321/audio-theory/`). При занятом порте Astro выбирает другой. Для проверки на определённом интерфейсе и порте:

```sh
just dev --host 127.0.0.1 --port 4321
```

В обычном терминале сервер работает до `Ctrl-C`. Astro 7 автоматически запускает сервер агента в фоне и завершает команду; для управления из корня проекта доступны:

```sh
npm run dev -- status
npm run dev -- logs
npm run dev -- stop
```

Агент сохраняет PID и URL своего сервера (либо ID активной сессии или фоновой задачи). Перед остановкой фонового сервера он сверяет PID и URL через `status` и останавливает только собственный процесс; на время авторской проверки сервер остаётся доступным. Чужой сервер не останавливается и не заменяется через `--force`.

Сборка:

```sh
just build
```

Результат находится в `dist/`: HTML и ресурсы для статического хостинга. Конфигурация Astro явно использует `output: 'static'`. TypeScript использует конфигурацию `astro/tsconfigs/strict`; отдельная проверка типов появится вместе с инструментами проверки в пункте 4. `just` показывает доступные команды; сейчас это `dev` и `build`.

Новые открытые вопросы записывайте в `docs/questions.md`, согласованные требования — в `docs/spec.md`. Статьи проверяются автором на локальном сайте и публикуются только после одобрения.

Импорты файлов из `src/` могут использовать алиас `@/`, заданный в `tsconfig.json`, например `@/styles/math.css`. Astro применяет его при разработке и сборке.

## Адреса сайта и базовый путь

`src/site.config.ts` задаёт адрес `https://hazadus.github.io`, базовый путь `/audio-theory/` и репозиторий `https://github.com/hazadus/audio-theory`. Astro берёт `site` и `base` из этой конфигурации. Переменные окружения для адресов не используются; `.env.example` пока не нужен. Настройки GitHub Pages и деплой добавляются позднее.

Страницы и ресурсы используют `withBase` из `src/lib/urls.ts`, например `withBase('/sampling/?mode=demo#nyquist-frequency')`. Функция берёт фактический `import.meta.env.BASE_URL`, сохраняет query и якорь, добавляет префикс один раз. Внешние URL (включая `//…`), схемы `mailto:` и `data:`, ссылки на якорь или query текущей страницы, относительные `./…` и `../…` сохраняются. Строки без начального `/` считаются логическими маршрутами от корня сайта. В MDX обычные ссылки и ресурсы преобразуются при сборке через `rehype-site-urls`; адреса в выражениях и свойствах встроенных компонентов формируются явным вызовом `withBase`.

Проверка размещения в корне без изменения конфигурации:

```sh
npm run build -- --base /
just dev --host 127.0.0.1 --port 4321 --base /
```

Для стандартного префикса используйте `just build` и `just dev`. `dist/` содержит корень публикуемого артефакта: каталог `audio-theory/` внутри него не создаётся. Статический сервер должен размещать содержимое `dist/` по выбранному базовому пути. CSS и импортированные ресурсы получают префикс средствами Astro.

## Проверка MDX и формул

MDX использует официальный `@astrojs/mdx` и обработчик `@astrojs/markdown-remark` с `remark-math` и `rehype-katex`. Строчные формулы записываются как `$T_s = 1/f_s$`, блочные — между отдельными строками `$$`. HTML и MathML создаются при сборке; неверная формула останавливает её. JavaScript для чтения формул не нужен.

На странице с формулами подключается `src/styles/math.css`: CSS и шрифты KaTeX входят в локальные ресурсы сборки; небольшие шрифты могут встраиваться в CSS. Кириллица внутри `\text{}` использует шрифт статьи. Лицензия KaTeX сохранена в `public/licenses/katex.txt`.

Проверка корректного MDX в корне и под `/audio-theory/`, ссылок, ошибочной формулы, компонента, MathML, локальных ресурсов и отсутствия проверочных материалов в публикуемой сборке:

```sh
npm run test:mdx
```

Проверочные исходники находятся в `tests/fixtures/mdx/`, отдельно от статей и обычных маршрутов. Сборки проверки создаются во временном каталоге и удаляются после выполнения. Для просмотра служебного материала:

```sh
just dev --host 127.0.0.1 --port 4321 --config tests/fixtures/mdx/astro.config.mjs
```

К адресу сервера с фактическим базовым путём добавьте `__test/mdx/`, например `http://127.0.0.1:4321/audio-theory/__test/mdx/`. Эта страница доступна только с тестовой конфигурацией; обычный `just build` её не публикует. Проверочный `SelfCheck` служит для проверки встраивания Astro-компонента, полноценные учебные компоненты добавляются позднее по плану.

## Скиллы агентов

| Задача | Codex | Claude Code |
| --- | --- | --- |
| Проверить изменения и создать логические коммиты | `$commit` | `/commit` |
| Выполнить указанный пункт `docs/todos.md`, проверить и закоммитить | `$execute 4` | `/execute 4` |
| Выполнить GitHub issue, дать результат на проверку и отчитаться в issue | `$issue 26` | `/issue 26` |

Скиллы учитывают наличие команд и тестов на текущем этапе разработки. Материалы включаются в коммит только после личной проверки и одобрения автором; обычные локальные задачи не запускают пуш. При порученной публикации проверяются CI, деплой и опубликованный сайт. Общий скилл подготовки статей `write-article` и правила `docs/authoring/` ещё предстоит создать по [плану](./docs/plan.md#4-подготовить-общий-скилл-и-первые-тексты).
