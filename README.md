# Теория аудио

Личный учебник по теории аудио и цифровой обработке звука: самостоятельные статьи, визуализации и интерактивные примеры. Материалы пишутся на русском с английскими названиями основных терминов. Статический сайт предназначен для публикации на GitHub Pages.

## Разработка

Нужны Node.js 22 (≥ 22.13.0), 24 или ≥ 26, npm ≥ 9.6.5 и [just](https://just.systems/). Зависимости зафиксированы в `package.json` и `package-lock.json`; установка из чистого checkout:

```sh
npm ci
```

Запуск из корня проекта:

```sh
just dev
```

Возьмите адрес из вывода Astro: строка `Local` в обычном терминале или сообщение `Dev server running at` при фоновом запуске. Фоновое сообщение может содержать только origin; добавьте фактический базовый путь `/audio-theory/` ровно один раз (обычно сайт открывается по `http://localhost:4321/audio-theory/`). При занятом порте Astro выбирает другой. Для проверки на определённом интерфейсе и порте:

```sh
just dev --host 127.0.0.1 --port 4321
```

В обычном терминале сервер работает до `Ctrl-C`. Astro 7 автоматически запускает сервер агента в фоне и завершает команду; для управления из корня проекта доступны:

```sh
npm run dev -- status
npm run dev -- logs
npm run dev -- stop
```

Агент сохраняет PID и URL своего сервера (либо ID активной сессии или фоновой задачи). Перед остановкой фонового сервера он сверяет PID и URL через `status` и останавливает только собственный процесс; на время авторской проверки сервер остаётся доступным. Чужой сервер не останавливается и не заменяется через `--force`.

Сборка:

```sh
just build
```

Результат находится в `dist/`: HTML, ресурсы и индекс Pagefind для статического хостинга. Сборка проверяет внутренние страницы, HTML-якоря и ресурсы HTML/CSS; неверная цель останавливает её. Конфигурация Astro явно использует `output: 'static'`. TypeScript использует конфигурацию `astro/tsconfigs/strict`; `just` показывает доступные команды с русскими пояснениями.

Новые открытые вопросы записывайте в `docs/questions.md`, согласованные требования — в `docs/spec.md`. Статьи проверяются автором на локальном сайте и публикуются только после одобрения.

Импорты файлов из `src/` в коде приложения и Astro/MDX-компонентах используют алиас `@/`, заданный в `tsconfig.json`, например `@/styles/math.css`. Astro применяет его при разработке и сборке. Правила импортов описаны в [стайлгайде](./docs/styleguide.md#конфигурация).

## Проверки кода и браузерные тесты

```sh
just fmt                 # Prettier: форматирование исходников и конфигурации
npm run fmt:check        # Проверка форматирования без записи
just lint                # ESLint: JavaScript, TypeScript и Astro
just typecheck           # Astro Check и tsc --noEmit
just test                # Vitest: unit-тесты
just build               # Статическая сборка
just test-e2e            # Полный прогон Playwright на двух сборках
```

Prettier форматирует `.astro`, CSS, JavaScript, TypeScript и JSON; документация, HTML-макеты, MDX и генерируемые файлы исключены. ESLint проверяет код, включая служебные Astro-компоненты, но не демонстрационный рантайм макетов. Unit-тесты находятся в `tests/unit/`, браузерные сценарии — в `tests/e2e/`; Vitest не запускает сценарии Playwright. TypeScript закреплён на версии 6.0.3, совместимой с Astro Check и typescript-eslint.

Перед первым браузерным прогоном установите браузеры:

```sh
npx playwright install chromium firefox webkit
```

В Linux CI используйте `npx playwright install --with-deps chromium firefox webkit`. `just test-e2e` последовательно создаёт сборки в `.e2e/root/` и `.e2e/prefixed/`, затем проверяет сайт в корне и под `/audio-theory/` в Chromium, Firefox и WebKit. Начальные сценарии проверяют текст, навигацию, стили, локальный ресурс и отсутствие служебного маршрута, чтение без JavaScript на ширине 390 px и поиск по настоящему индексу Pagefind через API.

Playwright запускает собственные preview-серверы на `127.0.0.1:4391` и `127.0.0.1:4392` и останавливает их после прогона. `--ignore-lock` оставляет процессы в foreground без общего lock-файла Astro; занятый порт вызывает ошибку, чужой сервер не используется. Локальный dev-сервер для авторской проверки работает независимо. Результаты и trace при ошибках сохраняются в `test-results/`; эти файлы и `.e2e/` не входят в Git.

DOM можно исследовать через `page.locator()`, `page.getByRole()` и `page.evaluate()`, снимок сделать через `page.screenshot()`. Trace открывается командой `npx playwright show-trace <путь-к-trace.zip>`. При изменении критичного пользовательского пути, доступности элементов или обработки адресов нужен полный `just test-e2e`; отдельный файл его не заменяет. WebKit не заменяет ручную проверку настоящего Safari на Mac и iPhone. Общие команды `just screenshots` и `just test-production` появятся вместе с соответствующими задачами.

## Поисковый индекс и проверка артефакта

После создания HTML интеграция `scripts/build-artifact.mjs` проверяет готовые файлы через `scripts/check-artifact.mjs`, затем строит индекс Pagefind в `<outDir>/pagefind/`. Это происходит при каждом `astro build`, в том числе через `just build` и с переопределёнными `--base` и `--outDir`. В HTML проверяются `href`, `src`, `poster`, ресурсы `object`, встроенные стили и `<style>`; в CSS — `url(...)`. Ссылки разрешаются относительно страницы или CSS-файла, query не меняет целевой файл, HTML-якорь должен существовать. Адреса того же origin считаются внутренними и должны учитывать `base`; внешние адреса и схемы вроде `mailto:` и `data:` не требуют сети. Проверка метаданных и нумерации учебных блоков будет добавлена вместе с коллекцией статей.

Начальная страница индексирует `<main data-pagefind-body>`; навигация исключена через `data-pagefind-ignore`. Служебные маршруты из `tests/fixtures/` обычная сборка не создаёт. Интерфейс поиска появится позднее; сейчас API проверяется браузерными тестами. Dev-сервер индекс не строит. Для ручной проверки соберите сайт и откройте preview:

```sh
just build
npm run preview -- --ignore-lock --host 127.0.0.1 --port 4322
```

Откройте адрес из вывода Astro с фактическим базовым путём, например `http://127.0.0.1:4322/audio-theory/`. В консоли браузера на этой странице:

```js
const pagefind = await import('/audio-theory/pagefind/pagefind.js');
const results = await pagefind.search('цифровой обработке');
const pages = await Promise.all(results.results.map((result) => result.data()));
console.table(pages.map(({ url, meta }) => ({ url, title: meta.title })));
```

Ожидается одна страница «Теория аудио» с адресом `/audio-theory/`; запрос `GitHub` не даёт результатов, поскольку навигация исключена. При сборке с `--base /` используйте импорт `/pagefind/pagefind.js` и запускайте preview с `--base /`. После проверки остановите свой foreground preview через `Ctrl-C`.

Unit-тесты проверяют отсутствующие страницы, якоря и ресурсы, query, относительные и внешние адреса и неверный базовый путь. Контрольная сборка со служебной ошибочной ссылкой должна завершиться с ненулевым кодом.

## Адреса сайта и базовый путь

`src/site.config.ts` задаёт адрес `https://hazadus.github.io`, базовый путь `/audio-theory/` и репозиторий `https://github.com/hazadus/audio-theory`. Astro берёт `site` и `base` из этой конфигурации. Переменные окружения для адресов не используются; `.env.example` пока не нужен. GitHub Pages настроен на публикацию через Actions; процесс описан в [инструкции по CI и деплою](./docs/deploy.md).

Страницы и ресурсы используют `withBase` из `src/lib/urls.ts`, например `withBase('/sampling/?mode=demo#nyquist-frequency')`. Функция берёт фактический `import.meta.env.BASE_URL`, сохраняет query и якорь, добавляет префикс один раз. Внешние URL (включая `//…`), схемы `mailto:` и `data:`, ссылки на якорь или query текущей страницы, относительные `./…` и `../…` сохраняются. Строки без начального `/` считаются логическими маршрутами от корня сайта. В MDX обычные ссылки и ресурсы преобразуются при сборке через `rehype-site-urls`; адреса в выражениях и свойствах встроенных компонентов формируются явным вызовом `withBase`.

Проверка размещения в корне без изменения конфигурации:

```sh
npm run build -- --base /
just dev --host 127.0.0.1 --port 4321 --base /
```

Для стандартного префикса используйте `just build` и `just dev`. `dist/` содержит корень публикуемого артефакта: каталог `audio-theory/` внутри него не создаётся. Статический сервер должен размещать содержимое `dist/` по выбранному базовому пути. CSS и импортированные ресурсы получают префикс средствами Astro.

## Проверка MDX и формул

MDX использует официальный `@astrojs/mdx` и обработчик `@astrojs/markdown-remark` с `remark-math` и `rehype-katex`. Строчные формулы записываются как `$T_s = 1/f_s$`, блочные — между отдельными строками `$$`. HTML и MathML создаются при сборке; неверная формула останавливает её. JavaScript для чтения формул не нужен. Временные сборки проверки создаются в `.e2e/mdx-*/` рядом с кешем Astro на одной файловой системе и удаляются после прогона.

На странице с формулами подключается `src/styles/math.css`: CSS и шрифты KaTeX входят в локальные ресурсы сборки; небольшие шрифты могут встраиваться в CSS. Кириллица внутри `\text{}` использует шрифт статьи. Лицензия KaTeX сохранена в `public/licenses/katex.txt`.

Проверка корректного MDX в корне и под `/audio-theory/`, ссылок, ошибочной формулы, компонента, MathML, локальных ресурсов и отсутствия проверочных материалов в публикуемой сборке:

```sh
npm run test:mdx
```

Проверочные исходники находятся в `tests/fixtures/mdx/`, отдельно от статей и обычных маршрутов. Сборки проверки создаются во временном каталоге и удаляются после выполнения. Для просмотра служебного материала:

```sh
just dev --host 127.0.0.1 --port 4321 --config tests/fixtures/mdx/astro.config.mjs
```

К адресу сервера с фактическим базовым путём добавьте `__test/mdx/`, например `http://127.0.0.1:4321/audio-theory/__test/mdx/`. Эта страница доступна только с тестовой конфигурацией; обычный `just build` её не публикует. Проверочный `SelfCheck` служит для проверки встраивания Astro-компонента, полноценные учебные компоненты добавляются позднее по плану.

## Скиллы агентов

| Задача | Codex | Claude Code |
| --- | --- | --- |
| Проверить изменения и создать логические коммиты | `$commit` | `/commit` |
| Выполнить указанный пункт `docs/todos.md`, проверить и закоммитить | `$execute 4` | `/execute 4` |
| Выполнить GitHub issue, дать результат на проверку и отчитаться в issue | `$issue 26` | `/issue 26` |

Скиллы учитывают наличие команд и тестов на текущем этапе разработки. Материалы включаются в коммит только после личной проверки и одобрения автором; обычные локальные задачи не запускают пуш. При порученной публикации проверяются CI, деплой и опубликованный сайт. Общий скилл подготовки статей `write-article` и правила `docs/authoring/` ещё предстоит создать по [плану](./docs/plan.md#4-подготовить-общий-скилл-и-первые-тексты).
